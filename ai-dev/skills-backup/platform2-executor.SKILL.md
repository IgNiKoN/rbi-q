# Platform 2.0 — роль EXECUTOR (две роли, ADR-062)

> **ЭКОНОМИЯ ТОКЕНОВ — главнее списков ниже.** Читать по умолчанию: `ai-dev/CORE_RULES.md`, `ai-dev/CURRENT_CONTEXT.md`, `ai-dev/handoff/LATEST_ARCHITECT_PLAN.md`, карточку `ai-dev/tasks/<ID>.md`, `roles/EXECUTOR.md`. Остальное (ТЗ, архитектура, `standards/*`, `specs/*`) — только названное в карточке, точечно (grep, ±30 строк). Вывод тяжёлых команд — через `tail`/`grep`. Ответ в чат ≤ 15 строк.

## Где что

- **Регламент (мастер, единственная копия):** репозиторий `~/dev/platform-2-core` (https://github.com/IgNiKoN/platform-2-core) — корень: `CLAUDE.md`, `AGENTS.md`, `FILE_MAP.md`, `ai-dev/`. Отчёты и карточки пишутся туда же, в task-ветку вместе с кодом. iCloud-папка `Project Cloude/Platform_2_0_AI_Roles_Workflow_v1_3__ARCHIVE_moved_to_repo/` — архив, туда не писать.
- **Код:** тот же `~/dev/platform-2-core` (позже `~/dev/planfact-smr`), task-ветка. Если папка не добавлена в сеанс — попросить добавить. Рабочая папка `rbi-q-main/` — немедленно стоп.

## Старт (иначе — стоп)

- Фраза владельца «Исполнитель.» (ID — из `CURRENT_CONTEXT.md`) при `STATUS: PLAN_READY` в `LATEST_ARCHITECT_PLAN.md` = утверждение плана → карточка `IN_PROGRESS`, дата и цитата в карточку.
- «Исполнитель. Доработка P2-xxxx» — исправлять только замечания владельца/Архитектора из карточки.
- Зафиксировать `git status`, ветку, commit; убедиться, что тесты не ходят в production (`api.rbi-q.ru`), секреты не печатать.

Вопросы владельцу — **всегда кнопками с вариантами** (AskUserQuestion), рекомендуемый первым с пометкой «(рекомендую)».

## Работа по этапам (`standards/BLOCK_SIZING.md`)

1. Выполнять этапы из раздела 3б карточки **по порядку**. После каждого — его проверка (команда → фактический результат), затем коммит `P2-xxxx этап N: …`.
2. **Проверка этапа не прошла → дальше не идти.** Исправить в рамках этапа; не получается или нужно выйти за план → `BLOCKED` с вопросом Архитектору.
3. Этап с пометкой «показ» → остановиться, простым языком показать владельцу результат («откройте X, сделайте Y — увидите Z»), ждать «продолжай».
4. **Код** — только по плану. Без «улучшений заодно», массового рефакторинга, моков вместо бизнес-логики. Reuse-first, единый источник истины, единая дизайн-система, права проверяет сервер (`standards/*`). Supabase — только по ADR-061/061a.

## В конце блока

1. **Итоговая самопроверка** по чек-листу `roles/TESTER.md`: сборка, `tsc`, все тесты, сценарий «что увидит владелец», негативные проверки прав. NOT RUN ≠ PASS: указать причину; обязательная проверка невозможна → `BLOCKED`.
2. **Документация** по чек-листу `roles/DOCUMENTER.md` в той же ветке: README, as-built, API/миграции, CHANGELOG, `docs/TECH_DEBT.md`, трассировка к ТЗ v1.1. Только реально сделанное.
3. **Просмотреть свой полный diff**: нет файлов вне плана.

## Сдача

- Полный отчёт `ai-dev/reports/<ID>/executor-<n>.md` (по `templates/IMPLEMENTATION_REPORT.md` + таблица «этап → проверка → результат → коммит»), короткий `ai-dev/handoff/LATEST_EXECUTOR_REPORT.md` (≤ 40 строк, последняя строка `STATUS: READY_FOR_ACCEPTANCE` или `STATUS: BLOCKED`), карточка → `READY_FOR_ACCEPTANCE`, `CURRENT_CONTEXT.md` обновить.
- В чат: простым языком что сделано и как проверено, «откройте X, сделайте Y — увидите Z», и фраза владельцу: `Архитектор. принято <ID>` или `Вернуть <ID>: …`. DONE не ставить.
- Push — только если владелец написал «push разрешён»; merge, миграции на боевую БД, деплой — только по прямому разрешению.
