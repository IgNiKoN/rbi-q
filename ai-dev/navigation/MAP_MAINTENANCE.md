# Обслуживание карты файлов и публичных контрактов

## Владелец и изменение

**Каноническая точка входа:** `FILE_MAP.md` (корень каждого репозитория новой Platform 2.0).  
**Технические справочники:** `ai-dev/navigation/CODEBASE_MAP.md`, `FILE_INVENTORY_SNAPSHOT.md` (этот файл *снимок*, не живой каталог), `AGENT_SEARCH_PLAYBOOK.md`.

При создании/перемещении публичного сервиса, модуля, контракта, миграций, общих компонентов или скриптов Архитектор указывает затрагиваемые строки карты. Документатор изменяет карту после PASS; Тестер проверяет соответствие коду и относительные ссылки. Роль не предполагает массовой реконструкции карты при каждом изменении частной функции.

## Формат записи

```md
| Функция | Подтверждённый путь/экспорт | Владелец | Потребители/граница | Статус и проверенный commit |
|---|---|---|---|---|
| Дерево проекта | `...` | Core/Master Data | API v... → Plan/Fact и Quality | CONFIRMED `abc123` |
```

Для условной будущей функции ставить **PLANNED** и не указывать придуманного физического пути как существующего.

## Правила актуальности

1. Карта актуальна **только для указанного репозитория и commit**; архивный снимок и другой Git — разные источники.
2. При большой смене ревизии составить одноразовый delta-audit путей; не переносить line numbers из старого `_ai/MODULE_CROSS_REFERENCE_MAP.md` без сверки.
3. Для новых модулей фиксировать публичный entrypoint, owner данных, server/API, UI-компоненты, тесты, миграции, версии и направление зависимостей.
4. Для смены Auth/роли/общей темы хранить один владельческий контракт, а не по копии документа на каждый модуль.
5. Скрипты и окружение документировать только после безопасного теста. Старые MacOS-пути/CDP-порты из `_ai/DEV_RUNTIME.md` не являются кросс-платформенным обязательством.
6. Ни одна карта не может ослаблять RLS, разрешать доступ к production или заменять действующие проверки прав.
7. Исправление устаревшего пути в документации **не требует искусственно запускать полный кодовый релиз**, если поведение и код не меняются; запись и review достаточны.

## Контроль качества карты

- Целевые файлы существуют в подтверждённой ревизии.
- Публичные entrypoints и owner названы верно.
- Все ссылки в текущей документации открываются.
- Отмечены исторические/предложенные места, которых физически нет.
- После изменения публичного контракта указаны затронутые модули, тесты и способ отката.
- README и `AGENTS.md` продолжают вести к `FILE_MAP.md`.
