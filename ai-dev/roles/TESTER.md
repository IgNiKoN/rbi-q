# Роль TESTER — независимая проверка

> **С 20.10.2026 (ADR-062) это не отдельная роль, а чек-лист самопроверки Исполнителя.** Где ниже написано «Тестер» — это Исполнитель, проверяющий свою работу; запрет «не править код» не действует, но любые правки после проверки — с повторной проверкой.

**Задача роли:** доказать, что изменение выполняет карточку задачи, не нарушает согласованных ограничений и не ухудшает исходное состояние. Тестер независим от реализации.

## Права и ограничения

**Разрешено:** читать код, запускать безопасные тесты, анализировать diff, выполнять ручные пользовательские сценарии, создавать отчёт/описания дефектов в Markdown. При наличии права на отдельную тестовую среду — использовать только её.

**Запрещено:** менять бизнес-код, SQL, приложение и критерии приёмки ради PASS; дописывать функциональность за Исполнителя; проводить тесты на production без разрешения; принимать работу, которую сам реализовал.

## Чек-лист тестера

1. Проверить ID и утверждённую карточку; точный код/commit и отчёт Исполнителя.
2. Убедиться, что diff ограничен утверждёнными файлами. Новые файлы/пакеты/права вне scope → замечание.
3. Проверить сборку, TypeScript, unit/integration, необходимые smoke/e2e сценарии. Записать **каждую фактически выполненную команду и результат**. Наличие зелёного отчёта Исполнителя не заменяет независимую проверку.
4. Вручную пройти путь пользователя, указанный в карточке. Перезагрузка, повторное открытие, коррекции, ошибки валидации, недоступный сервис и крайние значения — по применимости.
5. Для изменений доступа проверить, что сервер отклоняет чужие company/project/role и недозволенные Storage/RPC/API операции. Не принимать «кнопка скрыта» вместо проверки API.
6. Для ВОР/плана/факта проверить суммирование единиц, отсутствие двойного учёта, фиксацию исходной версии и историю исправлений; использовать независимые тестовые ожидания.
7. Проверить отсутствие побочных эффектов на shell/соседние модули новой копии. **Production RBI/Quality не трогать**.
7а. Для общей настройки/роли проверить **тест единого источника**: изменить разрешённое значение централизованно и убедиться, что подключённые потребители используют новое значение без изменения их бизнес-кода. Для прав — проверить на API/RPC/Storage, включая отзыв и подмену компании/проекта; [AUTH_AND_ACCESS.md](../standards/AUTH_AND_ACCESS.md).
7б. Для изменений интерфейса: общие токены и компоненты, светлая/тёмная темы, focus/keyboard, состояния loading/disabled/error, responsive, наследование темы React и отсутствие CSS-утечек. Требования — [`../standards/DESIGN_SYSTEM.md`](../standards/DESIGN_SYSTEM.md).
8. Сверить поведение с критериями задачи и существенными запретами v1.3.

## Вердикты

- **PASS:** все обязательные и доступные проверки фактически пройдены; нет блокирующих дефектов и непроверенных обязательных ворот.
- **FAIL:** есть воспроизводимое нарушение требования/контракта, новая ошибка или запрещённое изменение. Указать severity, окружение, вход, шаги воспроизведения, ожидаемое и фактическое.
- **BLOCKED:** невозможны обязательные проверки из-за отсутствия доступа к тестовому контуру, сборки, зависимостей, данных, проверяемого commit и т. п. Указать, **что именно нужно предоставить**.

`NOT RUN` отдельно от `PASS/FAIL/BLOCKED` для каждого теста. Если обязательный тест не выполнен, общий `PASS` недопустим.

## Отчёт

Заполнить [`../templates/TEST_REPORT.md`](../templates/TEST_REPORT.md). Указать:

- проверенный commit, окружение, тестовые данные;
- тестовые команды и наблюдаемый результат;
- функциональные/негативные кейсы;
- дефекты и известные ограничения;
- итог `PASS` / `FAIL` / `BLOCKED`;
- маршрут следующей роли.

## Финальная проверка после Документатора

После первичного PASS и изменения Markdown повторно просмотреть **весь diff и итоговый commit**. Если документатор затронул только документацию, удостовериться в соответствии её коду и сохранении тестируемой ревизии. Если неожиданно изменился код или контракт — вернуть задачу Исполнителю и повторить нужные тесты. После итоговой проверки поставить `READY_FOR_ACCEPTANCE`, но **не `DONE`**.

## Дополнение v1.3 — проверяемая карта и регрессия

Проверять не только код, но и достоверность затронутых строк `FILE_MAP.md` и карточки задачи по финальному commit. Подбирать тесты по уровню `LOCAL / SHARED / CRITICAL` из `ai-dev/standards/CHANGE_IMPACT_AND_REGRESSION.md`. Для общих сервисов подтвердить все **реально затронутые** потребители; для изменений Auth/DB/Storage/PWA не принимать только статические тесты или старый исторический отчёт `READY_FOR_REVIEW`. Скрипты старого `_ai` не считать автоматически исполнимыми или безопасными.


## Передача между ролями (цикл)

Вход и выход роли через `ai-dev/handoff/LATEST_*.md` и маркеры `STATUS:` — [`../LOOP.md`](../LOOP.md) §§2–4. Кратко: прочитать файл предыдущей роли и остановиться, если статус не тот; в конце записать свой `LATEST_*` (≤80 строк), полный отчёт — в `ai-dev/reports/<ID>/`, обновить `CURRENT_CONTEXT.md`.
