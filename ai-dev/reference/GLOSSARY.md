# Platform 2.0 — словарь терминов

**Версия:** 1.0 · 27.10.2026 · согласован с `MODULES.md` v1.4.

**Правило:** одно слово — одно значение во всех документах, интерфейсе и коде. Агент, встретив термин в другом значении (особенно в старых документах), берёт значение из этого словаря. Новый термин сначала добавляется сюда.

Колонка «В коде» — рекомендуемое имя. Фактические имена таблиц сверить с репозиторием `rbi-q`, при расхождении записать сюда.

## Платформа и коммерция

| Термин | Значение | В интерфейсе | В коде |
|---|---|---|---|
| **Платформа** | Platform 2.0 целиком: оболочка, ядро, сервисы, модули | — | `platform` |
| **Компания** | клиент платформы (арендатор), граница данных. Чужие данные недоступны никогда | Компания | `company`, `company_id` |
| **Подразделение** | дирекция или филиал внутри компании, группа проектов. Необязательно | Подразделение / Дирекция | `division` |
| **Модуль** | область работы: План/Факт, Качество, Стройконтроль, ИД, Сроки… | название модуля | `module_id` |
| **Сторона модуля** | функции модуля для одной стороны стройки: «подрядчик» (подготовка, производство) или «заказчик» (проверка, контроль) | — | `module_side` |
| **Решение (пакет)** | готовый набор модулей и сторон под тип компании: «Отделочник», «Девелопер», «Технадзор» | Тариф / Решение | `bundle` |
| **Лицензия** | право компании на модуль × сторону × срок × лимиты. Пробный период — тоже лицензия | Подписка | `license` |

## Ядро: где

| Термин | Значение | В интерфейсе | В коде |
|---|---|---|---|
| **Проект** | управленческий контейнер: ЖК, очередь. Сроки, бюджет, страна, часовой пояс, наша роль. **Раньше в интерфейсе назывался «Объект» — это устарело** | Проект | `project`, `project_id` |
| **Объект (здание)** | физический объект внутри проекта: корпус, паркинг, сети, благоустройство, детский сад, школа | Корпус / Объект | `location` с типом `object` и видом объекта |
| **Место** | любой узел дерева внутри проекта: секция, этаж, квартира, помещение, комната, МОП, кровля, захватка, трасса | Место / по типу | `location`, `location_id` |
| **Тип места** | секция, этаж, квартира… Задаёт правила вложенности | — | `location_type` |
| **Схема этажа** | план этажа (PDF или картинка), может использоваться для нескольких типовых этажей | План этажа | `floor_plan` |

## Ядро: что

| Термин | Значение | В интерфейсе | В коде |
|---|---|---|---|
| **Вид работ** | единица справочника работ компании: код, ЕИ, трудозатраты, параметры графика, чек-листы, кто принимает. У Setl это «СТК» | Вид работ | `work_type`, `work_type_id` |
| **Классификатор видов работ** | дерево групп (уровни) над видами работ | Классификатор | `work_type_group` |
| **Набор видов работ проекта** | выборка из справочника компании на проект со своими параметрами | Виды работ проекта | `project_work_type` |
| **Позиция работ** | главная ячейка учёта: место × вид работ × объём. К ней цепляются график, деньги, факт, приёмка, замечания | Работа / Позиция | `work_item`, `work_item_id` |
| **Строка ВОР заказчика** | строка исходного файла девелопера, не изменяется | Строка ВОР | `vor_source_line` |
| **Связка ВОР** | строка заказчика ↔ наша позиция работ с долей | — | `vor_mapping` |
| **Раскладка объёма** | деление объёма строки заказчика на места (этажи, квартиры) с долями; сумма долей = строке. Точнее всего — по объёмам листа площадей, затем по площадям мест, иначе поровну с подтверждением ПТО (P2-0050) | Раскладка | `vor_links.share` |
| **Лист площадей** | лист файла заказчика «секция · этаж · квартира/помещение · площадь», иногда с объёмами по видам работ; источник мест и долей раскладки | Лист площадей | `vor_area_sheet` |
| **Единица измерения (ЕИ)** | м², м.п., шт. Разные ЕИ не складываются | ЕИ | `unit` |
| **Шаблон чек-листа** | пункты, допуски, фото, норматив; привязан к виду работ. Используется в Качестве, приёмке СК и ОТ | Чек-лист | `checklist_template` |

## Ядро: кто

| Термин | Значение | В интерфейсе | В коде |
|---|---|---|---|
| **Пользователь** | человек с одним входом. Может состоять в нескольких компаниях | — | `user` |
| **Сотрудник** | пользователь внутри конкретной компании | Сотрудник | `company_member` |
| **Роль** | набор разрешённых действий. Название должности на права не влияет | Роль | `role` |
| **Участие в проекте** | сотрудник × роль × область (проект / объект / секция / договор / срок) | Команда проекта | `project_assignment` |
| **Ответственный за факт** | участник, который вносит факт по своим секциям | Ответственный / «отвечает за факт» | признак в `project_assignment` (сейчас `role_assignments.fact_owner`, P2-0048) |
| **Действие** | одно разрешение каталога (`<модуль>.<запись>.<что>`: «Закрыть замечание»); роль — набор действий; у действия есть модуль, группа и подпись (данные) и признак «действует при участии на часть проекта» | галочка в «Роли и права» | `core.permission_catalog` (`action`, `module`, `group_name`, `label`, `area_scoped`; P2-0070) |
| **Без объектов** | назначение роли, у которого нет ни одного объекта: человеку доступны только общие разделы (база знаний, ИИ-помощник, справочники), записей объектов он не видит и проверки не проводит | «Где: Без объектов» в мастере назначения | назначение на проект-контейнер Качества (`core.projects.quality_container`, P2-0071) |
| **Доступ к модулю** | переключатель модуля в роли: выключен — у роли нет действий модуля и модуля нет в меню | «Роли и права» | `setModuleAccess` (P2-0071); меню — `pf_my_platform` |
| **Своя запись** | запись, где человек — автор или исполнитель; без «Просмотр всех» человек видит только свои, правит своё по «Создание» / «Выполнение», чужое — только с «Редактирование чужих» | — | `quality.rec_ok` (own), P2-0071 |
| **Единый механизм прав** | одна проверка ядра «может ли человек действие на этом месте» (роль × действие × участие × модуль включён) для всех модулей; то же правило на телефоне | — | `core.can_at` / `core.has_grant`, правило строк `core.row_allowed`, отказ `core.require_action` (P2-0070, 052) |
| **Кто что может** | экран «люди × действия» на объекте или его месте по всем модулям на едином механизме, только просмотр | Кто что может | `pf_who_can`, `CompanyWho.ts` (P2-0070) |
| **Область назначения** | часть проекта, на которую назначен участник: узел дерева мест (объект / секция / этаж) и всё под ним; без места — весь проект | Где / Ваша область | `role_assignments.location_id` |
| **За кого** | отметка у факта, внесённого РП за ответственного за факт: автор — РП, «за кого» — ответственный | За кого | `fact_entries.on_behalf_of` |
| **Гость** | сотрудник другой компании, допущенный в наш проект в пределах договора и срока | Гость / представитель подрядчика | `guest_access` |
| **Наша роль в проекте** | кем компания выступает в проекте: заказчик, генподрядчик, подрядчик, технадзор, проектировщик. Определяет стороны модулей | Наша роль | `project.own_role` |
| **Контрагент** | другая организация в справочнике компании, по ИНН: подрядчик, поставщик, заказчик, проектировщик. Это **не** компания платформы | Контрагент / Подрядчик | `counterparty` |
| **Договор** | проект × контрагент: предмет, виды работ, фронт, цены, сроки, доп. соглашения | Договор | `contract` |
| **Фронт работ** | виды работ × места по договору. Хранится данными, а не текстом | Фронт | `contract_scope` |
| **Бригада** | производственный ресурс подрядчика или «свои силы», состав с историей | Бригада | `crew` |

## Работа на площадке

| Термин | Значение | Где |
|---|---|---|
| **Факт** | событие «выполнено X единиц по позиции работ» с автором и датой. Итог считается из событий, не перезаписывается | План/Факт |
| **Три факта** | **сдано** (прораб или подрядчик), **принято** (стройконтроль), **закрыто** (КС-2). Разрыв между ними подсвечивается | План/Факт + СК |
| **УрК** | уровень качества одной проверки: доля выполненных пунктов с весами (B1 = 1, B2 = 2, B3 = 3); «базовый» — без штрафов | Качество |
| **ИУрК (надёжность)** | интегральный уровень качества — УрК по серии проверок подрядчика с поправками на системный брак B2 и долю проверок с B3 (`getContractorMetrics`); в «Сводке» — «Надёжность» | Качество |
| **Открыто (замечание СК)** | замечание не закрыто, пока инженер не поставил «Проверено»; «Устранено» подрядчиком — открыто, «ждёт проверки» (P2-0049, одно правило для всей Аналитики) | Аналитика СК |
| **Просрочено сейчас / закрыто с опозданием** | две части просрочки замечаний СК: открыто и срок прошёл / закрыто позже срока | Аналитика СК |
| **Проверка** | выборочный контроль качества по чек-листу с оценкой (УрК, ИКО) | Качество |
| **Дефект** | несоответствие, найденное при проверке Качества, категории B1/B2/B3 | Качество |
| **Замечание** | несоответствие, выданное подрядчику на устранение (в СК, при приёмке, в ИД). Общее слово для «выдано → устранено → проверено» | СК, ИД |
| **Отклонение** | расхождение план ↔ факт по сроку или объёму. **Не путать с замечанием** | Сроки, аналитика |
| **Первопричина** | причина отклонения или замечания из справочника компании (для совещаний и PDCA) | Качество |
| **Предписание** | официальный документ подрядчику, собранный из замечаний | СК |
| **Вызов (заявка на приёмку)** | подрядчик записывается на окно инженера: место × этап | СК |
| **Ложный вызов** | вызов, на котором работа не готова или прошлые замечания не устранены | СК |
| **Приёмка этапа** | проверка инженером по чек-листу вида работ → принято / с замечаниями / не принято → акт | СК |
| **Эталон (эталонная работа)** | первая образцовая работа подрядчика, принятая до массовых работ | Качество, СК |
| **Шахматка** | таблица «места × виды работ», в ячейке — статус (готовность, замечания, передача); в «Объектах и местах» (P2-0055) — та же сетка мест без статусов: столбцы — секции, строки — этажи, клетки — помещения | СК, План/Факт, Компания |
| **Передача** | передача квартиры или помещения собственнику или в эксплуатацию | СК |

## Сроки и документы

| Термин | Значение | Где |
|---|---|---|
| **ГПР** | график производства работ | Сроки / План/Факт |
| **Директивный график** | утверждённый график, не меняется. От него считаются отклонения | Сроки |
| **Рабочий график** | копия директивного с правками, не длиннее директивного | Сроки |
| **ГДРС** | график движения рабочей силы | Сроки |
| **Веха** | ключевое событие проекта (коробка, ввод, ДДУ). Закрывается по дате, по работам или по событию | Сроки |
| **Адм. задача** | задача графика вне СМР: разрешение, акт | Сроки |
| **Буфер** | запас времени этапа с зелёной, жёлтой и красной зонами | Сроки |
| **ИД** | исполнительная документация: АОСР, АООК, акты по сетям и т. д. | модуль ИД |
| **Реестр ИД** | перечень документов ИД с комплектностью и статусами | модуль ИД |
| **КС-2 / КС-3 / КС-6а** | акт выполненных работ / справка о стоимости / журнал учёта | План/Факт |
| **ФОТ** | фонд оплаты труда бригад. Плановая и фактическая расценки разделены | План/Факт |
| **Редакция** | неизменяемая версия юридического документа. Исправление = новая редакция | все |

## Обмен, настройки, сервисы

| Термин | Значение | В коде |
|---|---|---|
| **Связь проектов** | связь нашего проекта с проектом другой компании через договор | `project_link` |
| **Пакет обмена** | копия документов или данных, отправленная другой компании, с версией формата и статусом ответа | `exchange_package` |
| **Сопоставление справочников** | «их вид работ / место ↔ наш» при обмене | `mapping` |
| **Шаблон платформы** | стандартный образец, который компания копирует себе | — |
| **Стандарт компании** | настройка компании, которую проекты наследуют (вехи, правила приёмки, первопричины…) | `company_setting` |
| **Замок** | признак «проект не может переопределить этот стандарт» | `locked` |
| **Сервис платформы** | общий механизм: файлы, печать, Excel, уведомления, ИИ… | `services/*` |
| **Адаптер** | реализация сервиса через конкретную библиотеку (html2pdf, SheetJS…). Заменяется без правки модулей | `adapters/*` |
| **Событие** | запись «что произошло» в журнале событий: «приёмка закрыта», «ИД принята» | `event` |
| **Журнал изменений** | кто, что, когда изменил, значения до и после | `audit_log` |
| **Автор записи** | учётная запись, создавшая запись. Определяется **по id**, ФИО — только подпись (P2-0061, `standards/SYNC_AND_ACCESS.md`) | `authorId` на устройстве ↔ `core_created_by` на сервере (ставит сервер) |
| **Не отправлено** | запись на устройстве, которая не ушла на сервер, с причиной и подсказкой «что делать». Отказ сервера — «Сервер отклонил: …» | `syncStatus: 'blocked'` + `syncBlockReason` |
| **Описание синхронизации** | строки в манифесте модуля: какие записи, поле автора, поле объекта, правило «моё», «своё первым», что держать заранее. Модуль подключается к синхронизации и правам только им | поле `sync` в `*.manifest.js` (P2-0061) |

## Устаревшие слова — не использовать

| Было | Стало |
|---|---|
| «Объект» в значении «весь ЖК» | **Проект** |
| «Локация» как отдельное дерево модуля | **Место** (одно дерево ядра) |
| «Подрядчик» как строка текста | **Контрагент** + **договор** |
| «СТК» (термин Setl) | **Вид работ** |

Полная опись таблиц и полей со светофором по стандарту — `reports/P2-0069/inventory.html` (машинная — `reference/schema-inventory.json`, стандарт состава полей — `standards/DATA_TABLES.md`, P2-0069).

|---|---|---|
