# Platform 2.0 — комплект правил для последовательной AI-разработки

**Версия комплекта:** 1.3  
**Дата подготовки:** 20.10.2026  
**Статус:** рабочий регламент на основе архитектуры Platform 2.0; включает зафиксированные 20.10.2026 дополнения по стеку, инженерным стандартам, дизайн-системе и централизованному управлению общими правилами, ролями, авторизацией и настройками. Архитектурные файлы v1.3/v1.2 сохранены без правок.  
**Цель:** довести независимый модуль **Plan/Fact СМР** до работающего MVP через небольшие задачи, проверяемые четырьмя разными ролями.

## С чего начать

**Сначала откройте [`FILE_MAP.md`](FILE_MAP.md)** — общая карта документов и конкретных файлов исходного проекта. Состояние активной задачи фиксируется в [`ai-dev/CURRENT_CONTEXT.md`](ai-dev/CURRENT_CONTEXT.md). Для точного поиска по коду используйте `ai-dev/navigation/CODEBASE_MAP.md`, для проверки старых решений — `ai-dev/reference/LEGACY_AI_TRANSFER_AUDIT.md`.

`_ai.zip` (локально распакован как `../rbi-q-main/_ai/`) — исходный **исторический** архив, он не подменяет правила `AGENTS.md`. В нём есть чувствительные runtime/credentials-материалы: **не копируйте его целиком в Git**. Актуальность `plan-fact` из отчётов октября проверяйте по Git, а не по одному Markdown.

## Как установить

1. Создать **отдельный** рабочий репозиторий `platform-2-core` из подтверждённого commit старой RBI Platform, не изменяя production. Пока Git commit не подтверждён, начать только с аудита P2-0001.
2. Скопировать `AGENTS.md`, `CLAUDE.md` и каталог `ai-dev/` в **корень нового репозитория**. `README_START_HERE.md` можно оставить в корне как инструкцию по регламенту. **Не заменять существующий продуктовый `README.md`.**
3. В отдельном будущем репозитории `planfact-smr` использовать тот же набор правил и документов, синхронно обновляя его согласованные версии. Никакой прямой зависимости нового репозитория от файлов на production RBI.
4. Проверить правила `.gitignore`: если `docs/`, `README.md`, `.cursor/` или `_ai/` исключены, исправить **только в новом репозитории** те исключения, которые мешают хранить необходимую документацию и проверки в Git. Проверить результат через `git check-ignore -v <путь>` и `git status`.
5. **«ТЗ для программы»** получено 20.10.2026: оригинал `../ТЗ для программы (1).docx`, Markdown-копия [`ai-dev/reference/TZ_PLAN_FACT.md`](ai-dev/reference/TZ_PLAN_FACT.md). Копировать её в новый репозиторий вместе с `ai-dev/`. Не придумывать детали, которых нет в ТЗ.
6. Запустить **только роль Архитектора** по [`P2-0001`](ai-dev/tasks/P2-0001.md). После утверждения карточки задачи — Исполнитель, Тестер, Документатор и приёмка владельцем продукта.
7. Для первой работы с Auth/ролями/правами и любым общим сервисом прочитать [`SINGLE_SOURCE_OF_TRUTH.md`](ai-dev/standards/SINGLE_SOURCE_OF_TRUTH.md) и [`AUTH_AND_ACCESS.md`](ai-dev/standards/AUTH_AND_ACCESS.md). В P2-0004 реализовывать **минимальную** серверную основу доступа, не конструктор корпоративных ролей.
8. Перед первым UI-изменением изучить [`DESIGN_SYSTEM.md`](ai-dev/standards/DESIGN_SYSTEM.md) и [`UI_COMPONENTS.md`](ai-dev/standards/UI_COMPONENTS.md). В существующей копии платформы повторно использовать проверенные общие токены/примитивы; **не создавать отдельную дизайн-систему Plan/Fact**.

> Комплект содержит инструкции и исходные Markdown-документы. Он **не содержит** код приложения, Git-историю, секреты, БД или настроенный тестовый сервер; одно его копирование не запускает Platform 2.0.

## Применение в Codex / Cursor / Claude Code

- **Codex:** открыть новый безопасный репозиторий и указать роль, ID задачи и пути к `AGENTS.md` и соответствующему файлу `ai-dev/roles/`.
- **Cursor:** открыть репозиторий и явно прикрепить инструкции `AGENTS.md`, нужную роль и карточку задачи к рабочему контексту. Не рассчитывать, что все внешние документы подтянутся автоматически.
- **Claude Code:** начать из корня нового репозитория с `CLAUDE.md`, `AGENTS.md`, конкретной ролью и задачей. При отсутствии этих файлов остановиться и запросить их либо задокументировать блокер.

Не запускать одновременно несколько инструментов на запись в одних и тех же файлах. Разные роли могут выполняться разными моделями, но **приёмку своей реализации Исполнитель не выполняет**.

## Две роли (ADR-062, с 20.10.2026)

```text
Архитектор ⇄ владелец: обсуждаем крупный блок → карточка
          |  «Исполнитель.»
          v
Исполнитель: код + тесты → самопроверка → документация → отчёт
          |
          v
Владелец: «принято» / «вернуть на доработку»
          |
          v
Следующий блок по ai-dev/ROADMAP.md
```

**Нельзя переходить к следующей задаче, если текущая не принята; нельзя ставить `DONE` вместо владельца продукта.**
