## 1. Цель

Представитель подрядчика входит, сразу видит «Мои замечания» — замечания своей фирмы, — берёт «В работу» и отмечает «Устранено» с фото; инженер принимает или отклоняет. Чужая фирма, удаление и самозакрытие — запрещены сервером.

## 2. Подтверждённое исходное состояние

- Роль: шаблон `contractor_rep` — `quality.view`, `construction.view`, `construction.edit` (`018_quality_up.sql:37`) + `quality.scope.contractor` (`020:36`); фирма — из назначения роли (`pf_assign_role(p_counterparty)`, `020:205-237`), мост ставит `assignedContractor` (`src/platform/auth/quality-bridge.ts:324-331`). **ТД №109 устарел** (привязка есть) — остаток ниже.
- Поток статусов Стройконтроля 2.0: `issued → in_progress → fixed (фото) → closed / rejected → fixed (повторно)` (`src/services/construction-defects/types.ts:5`; кнопки по роли — `src/modules/construction-v2/defect-form.ts:762-795`).
- Сервер: `construction_defects(_v2)`, `construction_acceptance(_v2)` — правка/вставка/**удаление** своей фирмы по `construction.edit` (`020_quality_scope_up.sql:151-174`); статус ничем не ограничен (подрядчик может поставить `closed`); таблицы `_v2` сопоставляют фирму по ключу/названию (`023_quality_scope_fix_up.sql:33-37, 111-114`), не по `core_counterparty_id`, как остальные с 039a (`039a_quality_contractors_by_id_up.sql:103-123, 177-200`).
- Клиент режет записи фирмы по точному тексту названия (`contractor-scope.ts:23-37`, `sync-engine.core.js:3809-3815`, `permission.service.js:557-565`) — расхождение написания или переименование прячет записи.
- Экран: вкладки для подрядчика не скрыты; «Новая проверка» открывается и не сохраняется (`audit.actions.js:603-605`), «План» — «недоступен» (`tasks.module.js:1038-1044`).
- Тесты: `rest.test.mjs:771-784` — только `construction_defects` (v1); `_v2`, удаление, переходы статусов не покрыты.

## 3. Объём

1. **Сервер (миграция `043_contractor_cabinet`):** `construction_defects_v2`, `construction_acceptance_v2` — фирма по `core_counterparty_id` (как 039a: колонка, триггер, разовое заполнение, правило `row_visible` по id); для роли с `quality.scope.contractor` в таблицах Стройконтроля (v1 и v2): **удаление — запрещено**; правка — только переходы `issued|rejected → in_progress → fixed` и поля ответа (фото устранения, комментарий подрядчика — по факту полей в таблице), остальные поля и `closed`/`rejected` — нет (триггер-сторож). Инженер/руководитель — как раньше.
2. **Клиент — фирма по номеру:** Стройконтроль 2.0 отбирает замечания подрядчика по `core_counterparty_id` (или доверяет отбору сервера) — без сравнения названий; `my_access` отдаёт id фирмы (если нет — добавить в ту же миграцию).
3. **Кабинет:** для роли `contractor` стартовый экран — «Мои замечания» (список Стройконтроля 2.0 своей фирмы, фильтр по статусу «к устранению / на проверке / принято»); вкладки без действий для подрядчика («Новая проверка», «План») скрыты; в форме — только «В работу», «Устранено (фото)», «Повторно предъявить»; без кнопки удаления.
4. **Проверки:** PGlite (подрядчик: своё видит, чужое — нет; удаление — отказ; `closed` — отказ; `fixed` с фото — да; инженер закрывает), REST (`rest.test.mjs`, раздел 0044), unit клиента, стенд/живой показ на тестовой компании.
