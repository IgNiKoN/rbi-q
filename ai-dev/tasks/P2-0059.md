## 1. Цель

На мигающей и слабой связи всё, что записано на телефоне, уходит на сервер **само, без нажатий**: ровно один раз, без потерь и дублей. Человек видит «не отправлено: N» и **по каждой записи — почему** («нет связи», «нет фото», «сервер отклонил»). На телефоне есть журнал синхронизации с кнопкой «Скопировать отчёт для разработчика».

## 2. Подтверждённое исходное состояние (по коду `main` `75ac61c`; на стенде ещё не измерено)

- `sync-engine.core.js:40-55` `triggerSync`: «есть ли сеть» проверяется по `navigator.onLine`. Wi-Fi без интернета или «одна палка» считаются сетью.
- `sync-engine.core.js:141-150`: одно общее ограничение на весь проход — 90 с. По его истечении `isSyncing = false`, а начатый проход **не останавливается**. **Гипотеза:** возможны две отправки одновременно.
- У отдельных запросов supabase-js своего ограничения времени нет. Клиент Качества создаётся в `quality-bridge.ts` `createQualityClient` — сюда можно подставить `global.fetch` с ограничением.
- `sync-retry.policy.js` `retryDelayMs`: пауза после неудач 2 / 5 / 10 / 30 мин. Цикл раз в минуту `sync-auth.js:162-190` паузу соблюдает. Событие `online` (`bootstrap.js:88`) запускает отправку, но на «лже-сети» оно не приходит.
- Отправка: `upsert … onConflict: 'id'` (`sync-engine.core.js:2624-2643`) — повтор не создаёт дублей (правило 1). Есть «нужно внимание» для отсутствующих фото (P2-0023). Есть защита своей неотправленной правки (`sync-merge.policy.js`).
- В начале прохода — `auth.getUser()` (сетевой запрос).
- Журнала синхронизации на устройстве нет. Причины неотправки по записям не показываются.
- После P2-0058: стенд `tests/offline/` (подставной сервер), признак «без связи» в состоянии платформы, счётчик «не отправлено: N».

## 3. Объём

1. **Стенд «плохая связь» и замеры (без исправлений).** Расширить `tests/offline/` «погодами»: нет сети; медленная (задержка 2 с, 50–400 кбит/с); «сеть есть, ничего не грузится» (сервер принимает и молчит); мигание (10 с есть / 20 с нет); обрыв посреди фото или пачки; ответы 500/503; две вкладки. На нынешнем коде записать по каждой: дошло ли всё **ровно один раз**, за сколько, сколько нажатий понадобилось, были ли две отправки сразу. Итог — таблица в `reports/P2-0059/measure-before.md`. Её же повторить в конце (`measure-after.md`).
2. **Проверка связи по делу (С1).** Короткий запрос к своему серверу (лёгкий RPC или `/auth/v1/health`) с ответом за 3–5 с. Не ответил — связи нет, отправку не начинать. Используется признак «без связи» из P2-0058, второго не заводить.
3. **Ограничение времени на запрос (С2).** `global.fetch` клиента Качества с `AbortSignal`: 20–30 с на запрос, для файлов — по размеру. Зависший запрос прерывается, запись остаётся «не отправлено».
4. **Один замок на отправку (С3).** Web Locks (`navigator.locks`) или существующий `syncChannel` + метка прохода. Две отправки одновременно невозможны, в том числе в двух вкладках. Общий 90-секундный «стоп» не снимает замок, пока проход не остановлен (прерывание через `AbortController` прохода).
5. **Порциями, с продолжением; сначала своё (С4, С5).** Отправка небольшими пачками, после каждой — отметка «отправлено». Обрыв → следующий проход продолжает с места обрыва. Своё уходит до скачивания чужого. Скачивание порциями.
6. **Умные паузы (С6).** Пауза после неудач остаётся, максимум 10 мин (было 30). Как только проверка связи (п. 2) ответила — отправка сразу, без ожидания конца паузы.
7. **Видно, что не ушло и почему (С8).** По нажатию на счётчик «не отправлено: N» (из P2-0058) — список: запись, когда сделана, причина («нет связи», «нет фото пункта …», «сервер отклонил: нет прав», «ждёт повтора в 14:32») и действие, если есть («Отправить без этого фото» — уже есть в P2-0023). Плюс «Последняя успешная отправка: 14:32».
8. **Журнал синхронизации на телефоне (С9).** Последние 500 событий: начало и конец прохода, сколько отправлено и получено, ошибка, длительность, состояние связи. Только на устройстве, **без содержимого записей и без персональных данных** (ID и тип записи, не текст и не ФИО). «Данные на устройстве» → «Журнал синхронизации» → «Скопировать отчёт для разработчика».
9. **Фоновая отправка на Android (С7) — только если замеры п. 1 покажут, что без неё не уходит.** Иначе — запись в ТД с замерами.
10. **Документы:** `docs/APP_GUIDE.md` (как работает отправка, что значит каждая причина), `CHANGELOG.md`, `FILE_MAP.md`, `MODULES.md` (сервис «Офлайн и синхронизация» — что теперь есть), отчёт; инструкция для владельца «полевой тест 15 минут» (подвал → 3 осмотра с фото → закрыть → связь → открыть → «0»).
