## 1. Цель

Старые данные приложения РБИ на сервере (места, замечания, приёмки, подрядчики, договоры, настройки компании) больше не отдаются без входа. Новое приложение (Платформа 2.0, схема `quality`) работает как раньше.

## 2. Подтверждённое исходное состояние

- `sql/002_create_platform_v2_tables.sql:306-334` — политики `"<t>_select_anon" FOR SELECT USING (true)` и `GRANT SELECT … TO anon` для 13 таблиц `public`; `sql/003:68-85` (`contracts`), `sql/012:32-44` (`rbi_company_settings`).
- Проверка REST публичным ключом (26.10.2026): отдаются `location_nodes` 392, `construction_floors_v2` 133, `construction_units_v2` 64, `construction_defects_v2` 33, `construction_acceptance_v2` 21, `contractors` 14, `contracts` 2, `rbi_company_settings` 1.
- Схема `quality` закрыта (`018_quality_up.sql:5`, политики `to authenticated`).
- Старое приложение РБИ (вход по PIN) выключено (P2-0032); новое приложение `public` не читает — **проверить** (grep клиента и функций `supabase/functions/*`, `Accept-Profile`/схема по умолчанию).

## 3. Объём

1. **Опись на сервере (только чтение):** все политики и права в `public`, дающие доступ `anon` (и `authenticated` без условий) — `pg_policies`, `information_schema.role_table_grants`; все таблицы/представления/функции `public`, доступные `anon`.
2. **Миграция `041_close_public_anon` (up/down):** у найденных объектов `public` — `revoke all … from anon`, удалить политики `*_anon`/`USING (true)` для `anon`; `authenticated` — тоже закрыть, если нет обоснованного потребителя (иначе — вопрос владельцу). Функции `public`, вызываемые новым приложением (`pf_*`, вход), **не трогать**. Down — вернуть как было (побайтно по описи).
3. **Проверка:** REST публичным ключом — те же таблицы отдают 401/403/пусто; `test:server` PASS; новое приложение (вход, Качество, План/Факт) — без ошибок.
