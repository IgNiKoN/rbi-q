## 1. Цель

Качество решает «кто что видит и может» тем же механизмом ядра, что Стройконтроль и План/Факт: тонкие действия в каталоге, область — участие в проекте, проверка — `core.row_allowed` / `core.require_action`, на телефоне — `core.my_grants`. Мост `quality_objects` больше не читается и не пишется. В РБИ никто не теряет и не получает лишнего, кроме решения владельца об участниках части объекта.

**Что увидит владелец:** «откройте "Компания → Роли и права" → группа "Качество" с галочками (проверки, задачи, совещания, методология, отчёты, ИИ, настройки); назначьте инженера на ЖК-1 в "Сотрудники" — в Качестве он сразу видит только ЖК-1 (отдельного списка "объекты Качества" нет); назначьте на секцию — видит проверки всего ЖК-1, правит только свои; снимите у роли "Закрыть задачу" — кнопки нет, обход экрана — отказ с текстом; "Кто что может на объекте" показывает и Качество; на телефоне — то же, что на ПК».

## 3. Объём реализации

   - Методология: `quality.method.edit` (эталоны, FMEA, ТИВИ, шаблоны чек-листов, этапы графика);
   - Отчёты и аналитика: `quality.reports.view`, `quality.reports.edit` (формировать, шаблоны);
   - Внешний СК: `quality.sk.view`, `quality.sk.import`;
   - прежние `quality.ai`, `quality.manage` (настройки), `quality.objects.manage` — остаются, получают группу и подпись.
2а. **Назначение инженера — «где» для всех модулей** (решения владельца 30.10, п. 10): объекты — **выбранные** (видит их целиком в Качестве, Стройконтроле, План/Факте) / **все** (назначение на компанию) / **без объектов** (только общие разделы: база знаний, ИИ-помощник, справочники; проверок не проводит, на телефоне «Новая проверка» неактивна). «Без объектов» = назначение на служебный проект-контейнер Качества (`core.projects.quality_container`, в списках объектов скрыт) — новых понятий в ядре нет. Мастер назначения: переключатель «Объекты: выбрать / все / без объектов» вместо прежнего списка «объекты Качества».
2. **Перенос без потери прав:** роли получают новые действия по прежним (`view` → все `*.view`; `edit` → создать / работать / методология / совещания / отчёты; `manage` → всё; `scope.contractor` → видеть и `tasks.work` своей фирмы); прежние ключи не удаляются (СК 1 и старые экраны). Назначения без проекта с `quality_objects` → участие на эти объекты **для всех модулей роли** (Стройконтроль тоже — только они; владелец: «в стройконтроле также — видишь только назначенные объекты»), прежнее назначение на компанию отзывается; назначения на компанию без объектов у ролей «только свои» (`edit` без `manage` / `scope.*`) → «без объектов» (владелец: «без объектов… таких вроде нет» — число в пробе); роли с `quality.scope.company` не меняются; журнал переноса — `p2_backup` для отката (в той же миграции; сами колонки не удалять — миграции только добавляющие, удаление — P2-0063 «Уборка»). Таблица «до = после» по каждому пользователю тестовой базы и копии РБИ.
3. **Участник части объекта — «весь объект, только просмотр»** (решение владельца): запись Качества без места видна участнику любой части проекта, правка — только своей. Делается **данными каталога** (признак у действия, например «участник части: все записи без места / только свои»), не кодом модуля; у действий СК и План/Факта признак не ставится → их поведение не меняется (тесты 052 / 047 / 043 — без изменения ожиданий). Место записи Качества по id в этом блоке **не вводится** (п. 2 стандарта не требуется: записи на уровне проекта).
4. **Правила строк** всех таблиц Качества с объектом — `core.row_allowed(компания, core_object_id, null, '{<действие view>}', автор, фирма)` + `core_company_id = quality.request_company()`; дочерние (`inspection_items`, `inspection_photos`) — через проверку своей проверки. Таблицы уровня компании (`shared_*` без объекта, профили, рейтинги, настройки) — по действию без области. `quality.record_visible / row_visible / assignment_sees_id` — обёртки на переходный срок или замена вызовов (решает Исполнитель, отчёт).
5. **Сторож действий** (BEFORE-триггер, последним; образец `quality.construction_action_guard`): проверки (создать / править чужую / удалить), задачи (создать / статус → `work` или `close` / исполнитель и срок / удалить) → `core.require_action` с текстом. Только запросы клиента.
6. **Мост:** `pf_set_participation` перестаёт писать `quality_objects`; ничто не читает `quality_objects / quality_object_keys` (поиск по репозиторию — 0 чтений вне down-миграций).
7. **Устройство:** описания `sync` Качества — `mode: 'area'`, `view / edit` — новые действия; «кто я» — `core.my_grants(…, 'quality')` вместо `quality.my_access` (оставить обёрткой, если её читает СК 1); записи без `core_object_id` на телефоне — переходное правило п. 7 стандарта (не по ФИО). Кнопки Качества, которые решают действие из каталога, — по `canAct` (как `construction-v2/rights.ts`); прочие `isAdmin` — опись в отчёте и ТД. Строки в зеркальном тесте.
8. **Экраны «Компания»:** группа «Качество» в «Роли и права» и строки в «Кто что может» появляются из каталога без кода (проверить). Отдельная настройка «объекты Качества» у сотрудника, если есть, — убрать с экрана (область задаёт участие).

9. **Доступ к модулю — переключатель в роли** (владелец 30.10, вариант «А»): в «Роли и права» у каждого модуля сверху «Доступ к модулю». Выключен — у роли нет действий модуля, модуля нет в меню у всех с этой ролью, галочки скрыты; включён — модуль в меню, галочки видны (включение ставит галочки просмотра модуля). Меню человека: модуль виден, если хоть одно действующее назначение даёт действие этого модуля (и модуль включён у компании). Индивидуальных галочек у человека нет — всё по роли; у человека только назначение (роль + где).

**Вне блока:** номера Качества на `uuid` (4в), Внешний СК по номерам (4г), место проверки по id (секция / этаж из текста), удаление колонок `quality_objects*` (P2-0063), назначение на подразделение (ТД 277 — после блока назначение без проекта = вся компания по ядру; подразделение — по запросу).
