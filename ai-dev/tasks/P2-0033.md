## 1. Цель

Войдите учёткой инженера (например, Иванова) → в Качестве видите **ровно те проверки, задачи, СК, что он видит в старом приложении** (все записи его объекта «Большевиков,22», кто бы их ни сделал, + свои без объекта); править и удалять можете только свои. Директором — видите всё, править нельзя. Заместителем и Админом — всё. Таблица сверки по всем 17: «видит в старом = видит в новом».

## 2. Подтверждённое исходное состояние (25.10.2026, код и сервер — только чтение)

- Старые права — `js/services/permission.service.js` `ROLE_MATRIX` (единственный источник поведения РБИ); у РБИ своих переопределений нет (`rbi_company_settings.role_matrix_overrides` = `{}`). Роли РБИ:

| Роль РБИ | Люди | Видит (`dataScope`) | Может |
|---|---|---|---|
| `manager` «Админ» | Кондратьев | всё | всё: создать, отправить, править/удалять любые, роли, объекты, СК, иерархия, База знаний |
| `deputy_manager` «Зам. руководителя» | Дзвонко, Степанов | всё | как Админ |
| `director` «Директор» | Петрушко, Капустин | всё | только смотреть (не создаёт, не отправляет, не правит, не удаляет); иерархия — да |
| `engineer` «Инженер СК» | 12 инженеров | `ownProjectOrOwnRecords`: все записи закреплённых объектов + свои без объекта | создать, отправить, править и удалять **свои**, СК, правка Базы знаний, недельный план |
| (`project_manager`, `contractor`, `guest`) | — в РБИ нет | своих объектов / своей фирмы / ничего | см. матрицу |

- Закрепления инженеров (`assigned_projects`, дубль в `settings.assignedProjects`): названия объектов (Иванов — «большевиков,22 (гений)», Сивцев — «парашютная 47…», Кудашкин — «школа 400 (крыленко)», Петровский, Гогитаури, Гоголадзе, Латышев, Данилов) **или** UUID (Дзюбенко, Токарев, Тарасов, Борисов) — UUID расшифровываются справочником объектов, как в клиенте (`ObjectDirectory.canonicalKeysForAssignedProjects`, `location_nodes` / `project_objects`). Объект записи — `project_canonical_key` (у задач — с заглавными буквами).
- Платформа сейчас: назначение роли — на всю компанию или на объект ядра (`core.role_assignments.project_id`); все 13 объектов РБИ — внутри одного объекта ядра «Объекты RBI». `qc_engineer` без `*.manage` видит **только свои** записи (`row_visible` 'author'), а не все записи объекта. Мост Качества передаёт экранам `assignedProjects: []` («объекты держит сервер»).

## 3. Объём реализации

1. **Закрепление за объектами РБИ (сервер), по id (ADR-070):** к назначению роли — список объектов Качества внутри объекта ядра — **постоянные `project_objects.id` компании** (не названия и не ключи); пусто = все. Записи Качества пока ссылаются на объект текстом (`project_canonical_key`) — сопоставление «id объекта → его ключ и синонимы» делает сервер по справочнику (переходно, ADR-070 п. 4); перевод самих записей на id объекта — P2-0035. Хранение — в ядре рядом с назначением (одно место), функции назначения/просмотра — расширение `pf_assign_role` / `pf_list_company_members` (P2-0004b, P2-0018), без второго справочника объектов.
2. **Правило видимости (`quality.row_visible` и правила пунктов/фото/СК/задач):** для назначения с объектами — запись видна, если её объект в списке (любой автор) или это своя запись без объекта; правка/удаление — по роли (инженер — только свои). Всё на сервере; производительность — не хуже P2-0027 (`perf/01_rls_cost.sql`: пачка 200 проверок ≤ 1 с).
3. **4 шаблона ролей «как в РБИ»** (Админ РБИ, Зам. руководителя, Директор, Инженер СК) — права = `ROLE_MATRIX` по каждому флагу (таблица соответствия «флаг РБИ → действие платформы» — в отчёте); роли компании RBI из старых профилей 17 человек + закрепления за объектами (вместо временных ролей P2-0028).
4. **Экраны:** «Сотрудники» — выбор объектов РБИ при назначении роли («все» / список); мост Качества передаёт экранам закреплённые объекты (`assignedProjects`) — старые фильтры и выбор объекта на экранах работают как раньше; роль экрана Качества = роль РБИ.
5. **Сверка «видит в старом = видит в новом»** (скрипт, только чтение): для каждого из 17 — множество записей по правилам `ROLE_MATRIX` из `public` и множество, которое отдаёт сервер под его учёткой из `quality`, — по проверкам, пунктам, фото, задачам, СК, планам/совещаниям; плюс «может править/удалять» на выборке.

## 3а. Reuse / единый источник истины

- Поведение — **только** из `ROLE_MATRIX` (`permission.service.js`), без новых трактовок. Объекты — справочник объектов компании (`project_objects`), расшифровка UUID — тем же способом, что клиент.
- Роли, назначения, журнал — ядро (P2-0004b); правило видимости — расширение `quality.row_visible` (P2-0018), не параллельная проверка в клиенте.

## 8. Риски

- Старое приложение фильтровало на клиенте; сервер РБИ мог отдавать больше — сверять с **правилами** `ROLE_MATRIX`, а не с тем, что отдавал старый сервер; найденные отличия — владельцу.
