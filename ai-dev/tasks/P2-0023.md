## 1. Цель

На телефоне и ПК проверка со 150+ фото показывает все превью: при прокрутке ничего не пропадает, ложной надписи «Файл очищен с устройства» нет. После переустановки возвращаются все свои проверки и их фото. Совещания и карты ТИВИ не исчезают и не размножаются. Синхронизация не крутится каждую минуту и не повторяет «Задачи не отправлены».

## 2. Подтверждённое исходное состояние (`main` `ad12f10`)

Файлы фото, совещаний, задач и ТИВИ совпадают со старым Качеством один в один. Синхронизация (`sync-engine.core.js`, `sync-auth.js`, `app-mode-utils.js`) немного доработана в P2-0016/0018. Ссылки на строки ниже — по Platform 2.0.

- **Фото, лимит 80:** `js/services/storage/storage-photo-manager.js:12` `MEMORY_URL_LIMIT: 80`, LRU :44–52. Механизм:
  - адреса самых старых фото отзываются, хотя `<img>` ещё на экране;
  - превью и полные фото считаются в одном лимите;
  - `rbiBuildPhotoImgAttrs` (`js/shared/photo-editor.utils.js:57–71`) ставит закэшированный адрес прямо в `src`.
- **Загружаются все фото, а не видимые:** `rbiHydrateLocalImages` (`photo-editor.utils.js:204–234`) идёт по всем `img[data-local-src]` подряд. При этом в `js/core/bootstrap.js:288–361` уже есть ленивая загрузка через IntersectionObserver.
- **Ложная надпись «очищено»:** заглушка `photo-editor.utils.js:11–21` появляется, когда `getAsyncUrl` вернул null **или выбросил ошибку** (`storage-photo-manager.js:232–350`). Для `local://` без записи в IndexedDB программа не пробует облачный `sourceUrl`. При каждом чтении превью запись переписывается в IndexedDB (:259–278), а превью пересобирается на canvas (`THUMB_VERSION=2`).
- **Новое устройство:** `rbiPullRowsByInspectionIds` (`js/services/sync/sync-core.state.js:356`) загружает пачками по 40 проверок без постраничной загрузки строк. Сервер обрезает ответ по лимиту строк (по умолчанию 1000), и пункты и фото молча теряются.
- **Видимость проверок:** при `ownProjectOrOwnRecords` (`sync-engine.core.js:975–984`) действует условие «ФИО совпадает буква в букву **И** объект назначен». Инкрементальная загрузка идёт по `updated_at` клиента: записи, отправленные позже, не видны. Сервер с P2-0018 сам ограничивает видимость (`quality.row_visible`).
- **Круг синхронизации:**
  - любая ошибка ставит `rbi_cloud_dirty` + `rbi_force_full_pull`, и таймер 60 с (`sync-auth.js`) запускает полную загрузку;
  - ошибки повторяются вечно: `rbiUploadAsset` падает на `local://`, если файла нет, и `gameForceUpdatePlan` после каждой синхронизации помечает данные «к отправке» (`tasks.module.js:578–581, 990–991`);
  - сообщение «Задачи не отправлены» (`sync-engine.core.js` ~2766) показывается в режиме `manual`; этот режим держится, пока нет `rbi_sync_last_pull_at` (`bootstrap.js:147–157`).
- **Память при съёмке:** фото черновика лежит base64 внутри сессии, и вся сессия перезаписывается при каждом сохранении (`audit.actions.js:322–336`). `dbPut` (`storage-db.core.js:287–310`) не слушает `onabort`, поэтому при нехватке места promise может зависнуть.
- **Совещания пропадают:**
  - у не-админа совещание отправляется, только если автор совпадает с `engineerName`;
  - `purgeDataOutsideAssignedProjects` (`app-mode-utils.js:942`, вызов `sync-engine.core.js:297`) удаляет совещания с объектом «Все объекты» (исключение предусмотрено только для «Все») и совещания по нескольким объектам;
  - загрузка перезаписывает запись при `cloudTime >= localTime` и не проверяет неотправленные правки (`sync-engine.core.js:1434`).
- **Карты ТИВИ:**
  - «уже создана другим инженером» (`knowledge.module.js:3234`) срабатывает и на собственную карту, скрытую фильтром;
  - автоочистка дублей после отправки удаляет более позднюю карту и теряет `extractedText`;
  - полная загрузка (из-за круга синхронизации) идёт **до** отправки и возвращает удалённые карты.
- **Не подтверждено:**
  - какая из причин съела ~10 проверок у пользователя старого РБИ: облака старого РБИ у нас нет, воспроизводим на демо;
  - фактический лимит строк на нашем сервере;
  - поведение iOS при нехватке памяти — проверяется только на телефоне владельца.

## 3. Объём реализации

1. **Фото на экране.**
   - Загружать только видимые фото (один механизм: доработать IntersectionObserver в `bootstrap.js` и `rbiHydrateLocalImages`, без второй копии).
   - Отзывать адрес фото только когда элемент удалён со страницы или ушёл далеко за экран, а не по счётчику 80.
   - Не больше N одновременных загрузок.
   - Не писать в IndexedDB при чтении. Превью пересобирать в фоне, не блокируя показ.
   - Различать «ошибка» (повторить; надпись «Не удалось загрузить — нажмите, чтобы повторить») и «файла нет на устройстве» (взять `sourceUrl` из облака; если сети нет — «Загрузится при подключении»).
2. **Фото при съёмке.**
   - Фото черновика сразу класть отдельной записью (`local://`), а в сессии хранить только ссылку.
   - `dbPut` и `dbPutBatch` отвечают на `onabort`, при переполнении памяти — понятное сообщение без зависания.
3. **Полная загрузка на новом устройстве.**
   - Постраничная загрузка в `rbiPullRowsByInspectionIds`.
   - Правило видимости проверок свериться с P2-0018: сервер уже фильтрует, а клиентское «ФИО И объект» не должно отбрасывать то, что сервер отдал.
   - Инкрементальную загрузку проверить на позднюю отправку.
4. **Синхронизация без круга.**
   - Ошибка одного объекта не ставит `force_full_pull` для всех. Объект с отсутствующим файлом помечается «нужно внимание» и не роняет синхронизацию снова.
   - `gameForceUpdatePlan` помечает к отправке только то, что действительно изменилось.
   - «Задачи не отправлены» — один раз за ошибку, с понятной причиной.
   - Поведение с `rbi_sync_last_pull_at` исправлено.
5. **Совещания не пропадают.**
   - Автоочистка не трогает «Все объекты», совещания по нескольким объектам и неотправленные записи.
   - Отправка совещаний идёт по назначенным объектам, а не по совпадению автора.
   - Загрузка не перезаписывает неотправленную локальную правку.
6. **Карты ТИВИ без пропаж и дублей.**
   - «Уже создана» проверяется по всем картам, а не только по видимым; если карта своя — открыть её, а не показывать отказ.
   - Убрать удаление дублей после отправки; уникальность на создании держится одним правилом.
   - Удаление карты доходит до облака раньше, чем следующая загрузка.
7. **Самопроверка и документы.** Показ на телефоне.
