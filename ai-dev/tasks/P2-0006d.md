## 1. Цель

Редакции ВОР безопасны для первых настоящих ВОР: перенос факта не обходит подтверждение РП и не теряет автора, одновременные принятия не оставляют факт на снятой позиции, КС-2 не выставляет объём повторно после смены договорного КП, базу сравнения видит только тот, кто может её использовать.

**Что увидит владелец:** «примите новую редакцию с переносом факта на почти выполненную позицию — перенос уйдёт РП на подтверждение; прораб исправит перенесённую запись сам; смените договорное КП на смету по новой редакции — в КС-2 не появится уже выставленный объём».

## 2. Объём (по ревью)

1. **Перенос — с блокировкой получателя** (`pf_vor_accept_revision`): позиция-получатель блокируется до проверки; получатель снимается в этот же момент — отказ.
2. **Перенос — с проверкой перебора:** итог факта получателя с переносом > плана × (1 + допуск) → перенесённые записи «на подтверждении РП», как при вводе.
3. **Автор перенесённой записи сохраняется** (`created_by`), перенесённая запись «на подтверждении» без исправления — не исправление (связь с прежней — в причине и журнале).
4. **КС-2 и смена договорного КП:** «уже выставлено» находится через позицию (связки), а не через id строки редакции; либо смена КП при выданных актах запрещена с понятным текстом. Исполнитель выбирает и обосновывает; ТД №269 — пересмотреть и обновить.
5. **`pf_vor_revision_base`** — только с правом `planfact.vor.manage`.
6. Мелкие: повторяющиеся решения по одной позиции — отказ; порядок блокировок в пачке факта — по id; счёт позиций в сводке по местам — одинаковый; `search_path` новых функций — с `pg_temp` в конце.

## 9. Замечания приёмки (ревью `046a`, 27.10.2026) — доработать в `046b`

1. **HIGH — перенесённый факт выставляется в КС-2 повторно.** Позиция P (строка A) — факт 10, выдан акт на 10 по A. Новая редакция снимает P с «Перенести» на Q (строка D): записи P — `superseded`, на Q — 10 принятых; выставленные 10 остаются на A, к выставлению по D предлагается +10 (и по прежнему КП, и по новому, и при переносе в другую ВОР). Исправить: записать переносы (позиция-источник → позиция-получатель, редакция) и учитывать их в `prev_map` `ks2_rows`; либо запретить «Перенести» для позиции, факт которой уже есть в выданных актах (только «Оставить»). Исполнитель выбирает и обосновывает; тест: акт выдан → перенос → КС-2 по старому и новому КП — к выставлению 0.
2. **MEDIUM — материалы сопоставляются по названию:** два одинаковых материала у работы — выставленное удваивается; переименованный материал или ЕИ «кг» / «кг.» — теряется и выставляется снова. Исправить: сопоставление 1:1 (по порядку внутри «работа + название + ЕИ», ЕИ — по ключу `unitKey`/справочнику) или связь материалов «старая строка → новая», записанная при принятии; тест на дубль и переименование.
3. **LOW — порядок блокировок при принятии:** цепочка и получатели блокируются двумя запросами — возможна взаимоблокировка (сервер прервёт одну операцию). Исправить: одним запросом, по id.
4. **LOW — блокировка получателя до проверки проекта:** добавить `project_id = проект загрузки` в блокировку.
5. Тесты: `pf_ks2_issue` черновика по другому КП; `pf_fact_add_batch` и `pf_summary_places` — проверки результата.
