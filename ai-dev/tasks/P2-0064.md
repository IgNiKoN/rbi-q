## 1. Цель

Прораб на площадке без связи вносит факт (в том числе пачкой по бригаде), видит его в журнале с пометкой «не отправлено». Когда связь появляется, факт уходит сам. Повторная отправка не создаёт дубль. Перерасход сверх плана, как и сейчас, уходит «на проверку».

## 2. Исходное состояние (сверено 29.10.2026, `main` `c31694e`; перед стартом — повторить сверку с `main` после P2-0061)

- Факт вносится вызовами `pf_fact_add`, `pf_fact_add_for`, `pf_fact_add_batch`, `pf_fact_add_batch_for` (`src/modules/planfact/fact/fact.service.ts:119–126`; на сервере — `030_fact_period_forecast_up.sql:140`, `046a_vor_revisions_fixes_up.sql:364`, `047_project_participation_up.sql:930`). Параметра «ID с устройства» нет — **номер записи выдаёт сервер** (проверено). При обрыве связи после записи на сервере повтор создаст дубль (нарушение правила 1 раздела 9).
- Исправление и решение по факту — `pf_fact_correct`, `pf_fact_decide` (с сетью; без сети в P2-0064 не делаются).
- После P2-0060 (проверено): сервис офлайна `src/platform/services/offline/` — копия для просмотра (`copy.ts`), `moduleOffline(id)` читает поле `offline` манифеста (`offline-read.ts:43`: `view`, `input[]`, `files`), `useInputBlocked(module, input)` — кнопка ввода неактивна без сети, если `input` не объявлен. План/Факт пользуется копией (`prefetch.ts`, `index.ts:72`); очереди ввода нет — пишет прямо на сервер.
- Механика отправки P2-0059 (замок, ограничение времени, порции, паузы, журнал) сегодня — у записей Качества: статус — поле записи `sync_status`, список «что не ушло» — `src/platform/auth/offline-rescue.ts` (`RECORD_STORES`), причины — `sync-status.ts`. P2-0061 делает её общей: модуль подключается описанием `sync` в манифесте.

## 3. Объём (черновик)

1. **Сервер (миграция):** ввод факта принимает **ID записи (и пачки), созданный на телефоне**. Повтор с тем же ID возвращает прежний результат, дубль не создаётся. Старые вызовы без ID работают как раньше. Права и проверки — прежние, на сервере.
2. **Ввод без сети — через общий механизм P2-0061:** запись факта хранится на устройстве со статусом в самой записи (`sync_status`, правило P2-0059 — без отдельной очереди-копии) и подключается описанием `sync` в манифесте План/Факта. Порядок, порции, повтор, «отклонено сервером», журнал — механика P2-0059/0061, без второго движка. Счётчик «не отправлено: N» и карточка «Отправка» учитывают факт.
3. **План/Факт:** `offline.input: ['fact', 'fact_batch']`. Форма ввода и пачка без сети кладут запись в очередь. В журнале и шахматке она видна с пометкой «не отправлено». После отправки — статус от сервера («принято» / «на проверке» / «отклонено» с причиной).
4. **Без сети не делается:** исправление факта, решение по факту, бригады (создать / в архив), КС-2 — кнопки неактивны с подсказкой (как в P2-0060).
5. **Конфликты:** два человека без сети внесли факт на одно место — сохраняются оба события (правило 3). Перерасход сверх плана → «на проверку» по существующему правилу. Бригада или позиция удалена, пока прораб был без сети → «отклонено сервером: позиция в архиве», запись остаётся на телефоне до решения.
6. **Документы:** `APP_GUIDE`, `CHANGELOG`, `FILE_MAP`, `MODULES.md` (План/Факт: ввод факта без сети), release-plan с миграцией (снимок базы, откат).

- **Стандарт синхронизации и прав (P2-0061, `standards/SYNC_AND_ACCESS.md`):** очередь факта подключается описанием `sync` в манифесте План/Факта (автор — id учётной записи, место — id места, причина «Не отправлено»), без своего отбора «моё»; `onBehalfPlan` (`area.ts:162`) — «я ответственный» по `user_id`, не по почте.
