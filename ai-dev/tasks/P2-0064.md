## 1. Цель

Прораб на площадке без связи вносит факт (в том числе пачкой по бригаде), видит его в журнале с пометкой «не отправлено». Когда связь появляется, факт уходит сам. Повторная отправка не создаёт дубль. Перерасход сверх плана, как и сейчас, уходит «на проверку».

## 2. Исходное состояние (`main` `2ec8959`; уточнить перед стартом)

- Факт вносится вызовами `pf_fact_add`, `pf_fact_add_for`, `pf_fact_add_batch`, `pf_fact_add_batch_for` (`src/modules/planfact/fact/fact.service.ts`). **Номер записи выдаёт сервер**. При обрыве связи после записи на сервере повтор создаст дубль (нарушение правила 1 раздела 9).
- Исправление и решение по факту — `pf_fact_correct`, `pf_fact_decide` (с сетью; без сети в P2-0064 не делаются).
- После P2-0060: сервис офлайна платформы (копия для просмотра, поле `offline` в манифесте, «Данные на устройстве → Офлайн по модулям»). После P2-0059/0061: проход отправки с замком, ограничением времени, порциями, умными паузами и журналом.

## 3. Объём (черновик)

1. **Сервер (миграция):** ввод факта принимает **ID записи (и пачки), созданный на телефоне**. Повтор с тем же ID возвращает прежний результат, дубль не создаётся. Старые вызовы без ID работают как раньше. Права и проверки — прежние, на сервере.
2. **Очередь ввода — сервис платформы** (`src/platform/services/offline/`): общая очередь «не отправлено» для модулей с `input` в манифесте. Порядок, порции, повтор, «отклонено сервером», журнал — на механике P2-0059, без второго движка. Счётчик «не отправлено: N» и карточка «Отправка» учитывают факт.
3. **План/Факт:** `offline.input: ['fact', 'fact_batch']`. Форма ввода и пачка без сети кладут запись в очередь. В журнале и шахматке она видна с пометкой «не отправлено». После отправки — статус от сервера («принято» / «на проверке» / «отклонено» с причиной).
4. **Без сети не делается:** исправление факта, решение по факту, бригады (создать / в архив), КС-2 — кнопки неактивны с подсказкой (как в P2-0060).
5. **Конфликты:** два человека без сети внесли факт на одно место — сохраняются оба события (правило 3). Перерасход сверх плана → «на проверку» по существующему правилу. Бригада или позиция удалена, пока прораб был без сети → «отклонено сервером: позиция в архиве», запись остаётся на телефоне до решения.
6. **Документы:** `APP_GUIDE`, `CHANGELOG`, `FILE_MAP`, `MODULES.md` (План/Факт: ввод факта без сети), release-plan с миграцией (снимок базы, откат).
