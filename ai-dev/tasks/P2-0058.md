## 1. Цель

Человек, который раньше входил с интернетом, открывает приложение **без сети «с нуля»** (телефон и ПК) и видит свои разделы и свои данные Качества и Стройконтроля. Осмотр, записанный без сети, уходит на сервер, когда сеть возвращается. При устаревшем входе показывается плашка «Нет связи», а не экран «Вход». Записи, которые уже застряли на телефонах, находятся и отправляются.

## 2. Подтверждённое исходное состояние (ветка `task/P2-0056-excel-places` = `main` `75ac61c`; стенд 28.10.2026)

- `src/platform/auth/platform.service.ts:121-133` (`loadEmail`): при каждом запуске `pf_my_platform` + `pf_my_profile`. При ошибке сети `companies = []`, `companyId = null`. На устройстве хранится только `platform2_company`.
- `src/platform/auth/quality-bridge.ts` `applyQualityBridge` → `switchDeviceCompany(store, null, '')`: откладывает `rbi_*` (в т.ч. `rbi_cloud_dirty`) в `platform2_quality_state_<компания>:<пользователь>`, снимает `platform2_quality_company`, **перезагружает страницу**. Затем `storage-db.core.js:7-12` открывает `PLATFORM2_DB` без компании. Сеть вернулась — переключение обратно, а записи из `PLATFORM2_DB` никто не разбирает. **Стенд:** `OFFLINE-MARK` остался в `PLATFORM2_DB`, до сервера не дошёл (`baseline/report-1440.txt`, `report-375.txt`).
- Без сети: в меню только «Настройки» (телефон и ПК). «Компания» молча уходит на `#/settings/home`. План/Факт пишет «Модуль не включён… обратитесь к администратору».
- Устаревший вход (`expires_at` в прошлом) + нет сети: `auth.service.ts` `getEmail()` → `getSession()` (supabase-js 2.118) около 25–50 с пытается обновить вход и возвращает «нет сессии». Через ~26 с перезагрузка на пустую базу, через ~55 с экран «Вход». Сохранённый вход в `localStorage` не стирается (`baseline/report-exp375.txt`).
- Кэш приложения: без сети `postCacheAllowlist` (`entry.ts`) шлёт `P2_SW_ALLOWLIST` с пустым списком, и `sw.js` `purgeDisallowedP2Cache` **удаляет код План/Факта (1,6 МБ) и «Компании» (1,3 МБ)**. Код Качества и СК не удаляется (`baseline/report-cache.txt`).
- Счётчика «не отправлено» в приложении нет. Признак «запись не отправлена» — `isUnsentLocal` (`js/services/sync/sync-merge.policy.js`, статусы `not_synced` / `pending` / `needs_attention`).
- `legacy-device.ts` (P2-0032) удаляет только старую базу РБИ. `PLATFORM2_DB*` не трогает.

## 3. Объём

1. **Не переключать базу Качества без ответа сервера (З2).** В `platform.service.ts` различать «сервер ответил» и «нет связи / сервер недоступен». В состоянии платформы — признак `offline` (или `source: 'server' | 'device'`). Мост Качества меняет компанию и базу только по ответу сервера: другая компания выбрана или компании больше нет у человека. Ошибка сети — не повод.
2. **Спасение «ничьих» записей (З5).** При входе с сетью проверить `PLATFORM2_DB` на неотправленные записи (`isUnsentLocal`) во всех хранилищах, включая фото. Если такие есть — лист «Найдено N записей, сделанных без связи: [список: дата, тип, объект]. Перенести в «<компания>» и отправить?». Кнопки «Перенести и отправить» / «Позже». После переноса записи в базе компании «не отправлено», дальше их отправляет обычная синхронизация. В `PLATFORM2_DB` перенесённые помечаются, но не удаляются (правило 2). Ключ `platform2_quality_state_` (пустой слот) с `rbi_cloud_dirty` учесть: запустить отправку и снять ключ.
3. **Помнить права на устройстве (З1).** Последний удачный ответ `pf_my_platform` + `pf_my_profile` хранится в `localStorage` под ключом пользователя (`deviceUserKey`, как имя базы) вместе с временем ответа. Без сети используется он, при появлении сети ответ обновляется. «Выйти» стирает. Другой вошедший на том же устройстве чужого не видит (MODULES §1 правило 1).
4. **«Вошёл без связи» до 14 дней (З3).** Вход сохранён, но устарел, а сети нет → человек остаётся вошедшим (режим «без связи»), экран «Вход» не показывается. Когда связь появилась, вход тихо обновляется (`refreshSession`). Экран «Вход» — только если (а) человек сам вышел, (б) сервер ответил «вход недействителен» (`invalid_grant` / 401 после обновления), (в) **последнее подтверждение сервером было больше 14 дней назад**. В случае (в) текст: «Нет связи больше 14 дней — войдите, когда будет интернет. Данные на телефоне сохранены». Данные не удаляются. Без сети на сервер ничего не уходит, права при отправке проверяет сервер.
5. **Кэш приложения по сохранённым правам (к З1).** Без сети `P2_SW_ALLOWLIST` строится по сохранённым правам. Если прав нет — сообщение не отправляется (кэш не чистится по «пустоте»). Код План/Факта и «Компании» без сети не удаляется.
6. **Честные сообщения и значок связи (З4, З6).** «Компания» и План/Факт без сети: «Нужен интернет — раздел работает только онлайн. Данные Качества и Стройконтроля доступны». Не «нет прав» и не переброс. В шапке значок «Нет связи» и счётчик «не отправлено: N» (по `isUnsentLocal`, текущая база Качества/СК). Нажатие ведёт в «Данные на устройстве». Плашка «Нет связи — данные сохраняются на телефоне» один раз при запуске.
7. **Стенд в репозиторий.** Стенд `baseline/` (подставной сервер, `run.mjs`, `expire.mjs`, `cache.mjs`) → автотест `tests/offline/` с командой в `package.json` (например `npm run test:offline`). Сценарии: холодный запуск без сети (375 и 1440), устаревший вход, запись без сети → сеть → дошло, спасение `PLATFORM2_DB`, кэш модулей без сети.
8. **Документы:** `docs/APP_GUIDE.md` (раздел о работе без сети), `CHANGELOG.md`, `FILE_MAP.md`, отчёт.

## 8. Риски и зависимости

- **Перенос «ничьих» записей отправит чужое** (демо, старый РБИ, другой человек на том же телефоне). Мера: только `isUnsentLocal`, только после подтверждения человеком со списком; стоп-условие этапа 1.
- **supabase-js сам стирает сессию** при неудаче обновления. По стенду 28.10 не стирает (`authKept: true`). Мера: тест этапа 2 на 120 с.
- **Сохранённые права устарели** (человека отключили, пока он без сети). Мера: без сети на сервер ничего не уходит; при связи — новый ответ сервера и прежнее поведение моста.
- Следом P2-0059 меняет движок синхронизации — стенд `tests/offline/` станет его основой.
