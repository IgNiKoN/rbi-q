## 1. Цель

После выкладки у каждого пользователя работает **одна версия целиком**: все файлы одной сборки, без смеси старых и новых.
- Новая версия **скачивается в фоне целиком**. Файлы, которые не менялись, переносятся из текущей версии без скачивания. Не скачалась целиком — не ставится, текущая работает как прежде.
- Включается **при запуске**, а если приложение не закрывают — **при возврате из фона**, когда ничего не вводится и всё отправлено. Внезапных перезагрузок посреди работы нет.
- **Плашки нет.** В настройках — строка версии: номер и дата, «Скачивается новая версия…», «Новая версия скачана — включится при следующем запуске», кнопка «Перезапустить сейчас».
- **Номер версии и список файлов составляет сборка**, не человек. Больше нет `SW_VERSION` руками и правила «обновите страницу дважды».
- Приложение не перепроверяет у сервера каждый файл при каждом открытии (ТД 227, ~300 запросов).

## 2. Подтверждённое исходное состояние (`main` `4eee56a`, SW 18.104.1)

- **Смесь версий.** Обработчик `fetch` в `sw.js` (≈ стр. 474–513) — «из кэша сразу + сеть в фоне», и ответ сети **кладётся в кэш текущей версии** (`CACHE_NAME`). После выкладки старая страница получает новые файлы по одному. Отсюда правило «обновите страницу дважды» (`CORE_RULES`, «Сразу правильно», п. 4).
- **Неполная установка.** `install` (стр. 323–376): ошибка скачивания файла только пишется в консоль (`.catch → console.log`), версия всё равно ставится, `activate` удаляет прежний кэш. Без сети после такого обновления часть экранов не откроется.
- **Список файлов вручную.** `urlsToCache` (стр. 115–317, ~180 путей) ведётся руками. Бандлы `js/dist/planfact/`, `company/`, `platform-admin/` и их части (`chunks/*-<хэш>.js`) в нём нет — они догружаются по ходу работы. Старая страница после выкладки может запросить часть, которой на сервере уже нет.
- **Номер версии вручную:** `SW_VERSION = '18.104.1'`. Забыли поднять — `sw.js` не изменился, обновление не придёт. Экран диагностики показывает другой, устаревший номер: `window.RBI_APP_VERSION = { app: '18.59.0', sw: '18.59.58' }` (`index.html:744`) → `storage-diagnostics.render.js:174`, журнал синхронизации (`sync-journal.policy.js:111`).
- **Переключение.** `pwa-update.utils.js`: плашка «Доступно обновление → Обновить» → `SKIP_WAITING` → перезагрузка; в «Настройках» кнопка «Проверить обновления» (`settings.render.js:1081`). Если открыты две вкладки, новая версия берёт управление и старой вкладкой тоже.
- **Допуск модулей** (P2-0013): `P2_SW_ALLOWLIST` / `RBI_SW_ALLOWLIST` хранится только в памяти `sw.js`. После перезапуска кэша приложения там `null`, то есть «разрешено всё».
- **Есть что переиспользовать:** `scripts/release-rbi-q.mjs` → `isReleaseFile()` / `RELEASE_DIRS`. Это готовое правило «что входит в приложение»: без `.map`, тестов и `.env`.
- Первая установка поверх старого приложения РБИ (P2-0032, `LEGACY_CACHE_PREFIX`), закрытые файлы компаний (P2-0016/0018, `fetchCompanyFile`, `P2_SLOT_CACHE`) и push — работают. Их **не ломать**.

## 3. Объём

1. **Опись версии при сборке** — `scripts/app-version.mjs`, команда `npm run build:version`:
   - Список всех файлов приложения по `isReleaseFile()` (EXTRACT в общий модуль, release-скрипт использует его же). У каждого файла — отпечаток содержимого (sha-256, коротко) и размер.
   - Файлы сгруппированы: **оболочка** (всем) и **модули** — по тем же префиксам, что `P2_PREFIX_TO_MODULE` / `BUSINESS_PREFIX_TO_MODULE`. Это единое правило: из `sw.js` префиксы переезжают в опись.
   - **Номер версии** = дата сборки + короткий отпечаток описи (пример `2026.10.29-a1b2c3`). Он один на всё: кэш, экран, диагностика, журнал синхронизации. `RBI_APP_VERSION` в `index.html` и `SW_VERSION` руками — убрать.
   - Опись **встраивается в `sw.js`** (сгенерированный участок между метками) или в отдельный файл, который `sw.js` подключает. Требование одно: любое изменение любого файла приложения меняет байты, которые браузер сравнивает при проверке обновления. Как именно — решает Исполнитель, проверяет стенд этапа 3.
   - **Сторож** (unit-тест в `test:unit`): опись совпадает с файлами на диске. Каждый `<script src>` / `<link href>` из `index.html` и каждая часть, на которую ссылаются бандлы `js/dist/**`, есть в описи. Забыли `npm run build:version` — тест красный.
2. **Установка целиком** (`install`):
   - Новая версия ставится в свой кэш `platform2-<версия>`. Каждый файл оболочки и **допущенных** модулей: если в текущей версии лежит файл с тем же отпечатком — копия без сети, иначе скачивание (`cache: 'reload'`) с **проверкой отпечатка**.
   - Любая ошибка (нет связи, не 200, отпечаток не совпал — сервер в середине выкладки) → установка не удалась, текущая версия не тронута. Повтор — при следующей проверке обновления.
   - Допуск модулей сохраняется в постоянной памяти кэша приложения (как `P2_SLOT_CACHE`), а не только в переменной. При первой установке, пока допуска нет, — как сейчас: оболочка + всё, что разрешено до ответа входа.
   - Модуль, допущенный позже, докачивается **той же версии** с проверкой отпечатка. Если на сервере уже другая версия, сначала идёт обновление, потом модуль. Чужих версий в кэше нет.
3. **Отдача только из своей версии** (`fetch`):
   - Файлы из описи отдаются только из кэша **той версии, на которой открыта вкладка**. Сеть в фоне в кэш не пишет (stale-while-revalidate убрать).
   - Нет в кэше (модуль не допущен) → сеть без записи в кэш. Не из описи (API, Storage, закрытые файлы компаний, push) — как сейчас.
   - **Вкладка = одна версия.** При открытии вкладки (навигация) запоминается её версия: `resultingClientId` → версия, в постоянной памяти. Прежняя версия хранится, пока открыта хоть одна её вкладка, затем удаляется. Две вкладки на компьютере не смешивают версии.
   - Проверка обновления: браузер сам (при открытии и раз в сутки) + приложение вызывает `registration.update()` при запуске и при возврате из фона (не чаще раза в 30 мин). Перепроверки каждого файла нет → ТД 227 закрыт.
4. **Переключение** (`js/shared/pwa-update.utils.js` + ранний участок `index.html`):
   - **При запуске:** до загрузки модулей, на заставке. Если новая версия готова — `SKIP_WAITING` и одна перезагрузка. Защита от петли — флаг на одну загрузку.
   - **При возврате из фона:** вкладка была скрыта ≥ 30 мин, новая версия готова, **всё отправлено** (счётчик неотправленного P2-0059 = 0, синхронизация не идёт) и **ничего не вводится** (нет открытой формы / модального окна с изменениями). Для этого общая функция платформы «идёт ввод» (`appBusy()`): модули сообщают в неё о своих открытых формах, своих списков не держат. Условия не выполнены → переключится при следующем возврате или запуске.
   - **Данные на устройстве не трогаются:** очередь отправки, IndexedDB, копия прав (P2-0058) переходят в новую версию как есть. Проверка «очередь старой версии → новая версия отправляет» — в стенде.
   - Первая установка поверх старого приложения РБИ — как сейчас (P2-0032: сразу, с перезагрузкой окон).
5. **Строка версии вместо плашки** — по макету (этап 4). Место — блок с кнопкой «Проверить обновления» в «Настройках». Ничего не убирать (память `redesign-keep-all-functions`): «Проверить обновления» остаётся; плашка убирается по решению владельца (раздел 11). Состояния: «Версия … от …» · «Скачивается новая версия: 12 из 40 файлов» · «Новая версия скачана — включится при следующем запуске» + «Перезапустить сейчас» · «Новая версия не скачалась (нет связи) — работает текущая, повторим позже». Тот же номер — в диагностике и «Скопировать отчёт для разработчика» (P2-0059).
6. **Регламент Исполнителя:** в `CORE_RULES` («Сразу правильно», п. 4) вместо «поднять `SW_VERSION`, обновите страницу дважды» — «`npm run build:version` (сторож в `test:unit`), владельцу: версия включится при следующем запуске или кнопкой "Перезапустить сейчас"».
