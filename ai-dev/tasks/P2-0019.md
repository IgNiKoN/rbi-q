## 1. Цель

РП, ПТО или прораб открывает «План/Факт → ВОР → Позиции» на телефоне или ПК и работает со списком как в современных системах. Фильтрует чипами (место, вид работ, статус) или в панели «Фильтрация». Нажимает «Только просроченные», отмечает несколько позиций и видит «Выбрано: N» с действиями: выгрузить, закрыть, закрыть через РП. Выбирает колонки и сохраняет вид — свой или ссылкой коллеге. Открывает позицию в боковой карточке со «пред./след.», историей факта «было → стало» и шагами «Не начато → В работе → Выполнено». Компоненты реестра лежат в оболочке и годятся для следующих списков (КС-2, факт, Приёмка 2.0).

## 2. Подтверждённое исходное состояние (`main` `7c6cac0`)

- `src/modules/planfact/vor/VorPositions.ts` — позиции импорта ВОР: место · вид работ · ЕИ · объём · пометка, фильтр по месту; только чтение, без статусов и дат.
- Данные по позиции уже есть:
  - `pf_summary_positions(p_project, p_work_type)` — план, факт, %, остаток, факт за 7 и 14 дней, ждёт подтверждения;
  - `pf_fact_positions` — место, тип места, ждёт подтверждения (кол-во), последняя причина отклонения;
  - `pf_fact_history(p_position)` — записи факта со статусами, автором, решением РП;
  - сроки объекта — `projects.planned_start/planned_finish` (`pf_summary_project`).
- Массовый факт: `pf_fact_add_batch(p_project, p_brigade, p_date, p_items, p_workers, p_note)` (≤ 500 строк, одна бригада и дата, правило перебора к каждой строке — `planfact.fact_insert`), его использует «Закрыть этаж» (`fact/FloorClose.ts`). Подтверждение — `pf_fact_decide`, список — «Ждёт подтверждения» (`FactPending.ts`).
- Сейчас факт ждёт РП (`pending_approval`) только при переборе сверх `fact_tolerance_pct`. Право «Закрыть» — `planfact.fact.create`, подтверждать — `planfact.fact.approve`.
- Оболочка UI: `src/platform/ui/` — `tokens.ts`, `primitives.ts` (`StatusBadge`, `KpiTile`, `ProgressBar`, `Legend`), `format.ts`, `chess.ts`; выгрузка Excel — `summary/xlsx.ts` и `vor/xlsx-writer.ts` (ExcelJS).
- **Не подтверждено:** есть ли у `pf_summary_positions` права по `fact.view` для прораба (сверить); как `planned_finish` пуст — тогда «просрочено» только по темпу недоступно (кнопка показывает подсказку «нет срока объекта»).

## 3. Объём реализации

1. **Сервер (CRITICAL — факт и права):** миграция `027_fact_force_approval`. `pf_fact_add_batch` + параметр `p_require_approval boolean default false`: при `true` все строки пачки — `pending_approval` (причина «закрытие через РП» в записи), независимо от допуска. Права, проверки, журнал — прежние; прежний вызов — то же поведение. Откат — `027_down`.
2. **Оболочка — `RegistryTable` (`src/platform/ui/registry/`):**
   - колонки: описание, выбор колонок (1.7);
   - сортировка;
   - фильтры-чипы с «×» над таблицей и панель «Фильтрация» (Сбросить / Применить; на телефоне — на весь экран) (1.2);
   - кнопка-переключатель «Только просроченные» (1.3);
   - выбор строк и плашка «Выбрано: N» с местом под действия (1.4);
   - группы-аккордеоны «Всего: N» с цветными мини-счётчиками статусов (1.1);
   - пустое состояние;
   - единая палитра статусов (1.12): красный — просрочено / отклонено, оранжевый — в работе, синий — ждёт подтверждения, зелёный — выполнено, серый — не начато. Через токены `tokens.ts` и `StatusBadge`, без своих цветов.
3. **Оболочка — виды, выгрузка, карточка:**
   - сохранённые виды (фильтры + колонки + сортировка + группировка): личные — на устройстве (по компании и пользователю), «Скопировать ссылку» — параметры в адресе оболочки `#/planfact/vor/positions?…` (1.6);
   - «Выгрузить в Excel» — выбранные строки или весь отфильтрованный список, видимые колонки (1.5), через существующий ExcelJS-путь;
   - боковая карточка поверх реестра со стрелками «пред. / след.» (1.8), лентой «История» (записи факта: дата, автор, кол-во, статус «было → стало» цветными бейджами, решение РП) (1.9) и шагами процесса в шапке: «Не начато → В работе → Выполнено», отдельно «Ждёт РП» (1.13).
4. **Позиции ВОР — первый реестр:**
   - данные — REUSE `pf_summary_positions` + `pf_fact_positions`; статус и «просрочено по темпу» считаются в одной функции `positionStatus` (`summary/model.ts`, рядом с прежними расчётами);
   - чипы: корпус / место, вид работ, статус; группировка по корпусу;
   - действия «Выбрано: N»: «Выгрузить», «Закрыть выбранные», «Закрыть через РП». Закрытие — форма бригады и даты (REUSE формы «Закрыть этаж» / `FactEntryForm`), остаток каждой позиции — одной пачкой `pf_fact_add_batch`, больше 500 — частями;
   - кнопки закрытия — только при `fact.create` (из прав сервера), отказ сервера показывается.
5. **Счётчики на подвкладках (1.11):** «ВОР → Позиции (N)», «Факт → Ждёт подтверждения (N)».
6. **Документы и версия:** APP_GUIDE («Реестр позиций»), DESIGN_SYSTEM (компонент реестра, палитра статусов), SERVERS (027), CHANGELOG, «История обновлений», SW.

**Вне блока:** реестр на других списках (КС-2, история факта, Приёмка 2.0) — следующие блоки на готовом компоненте; общие виды для компании; плановые даты позиций; «Требует моего участия» (1.10); ссылка для внешнего (1.16).
