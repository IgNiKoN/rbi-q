## 1. Цель

Откройте «Компания → Сотрудники» в RBI (рабочей почтой) → видите 17 человек с ФИО и ролями из старого приложения. «Добавить сотрудника» → почта, ФИО, роль, объект → приложение показывает временный пароль. Войдите этой почтой и паролем → приложение требует придумать свой → после — работает. Войдите под учёткой инженера → в «Истории» видны его старые проверки, подписанные его ФИО. «Сбросить пароль» → старый перестаёт работать. Старое приложение работает как раньше.

## 3. Объём реализации

1. **Сервер — учётки** (новая миграция `032_company_staff`): `pf_company_add_member(компания, почта, ФИО, роль, объект|null)` — учётка (если почты нет) + участник + назначение + флаг «сменить пароль» + временный пароль (генерирует сервер, возвращается **один раз**, хранится только хэш); `pf_company_reset_password(компания, пользователь)` — новый временный, флаг; `pf_company_disable_member(компания, пользователь)` — назначения отозваны, вход заблокирован (если человек не состоит в других компаниях), история остаётся; `pf_password_changed()` — снимает флаг (вызывает сам пользователь после смены пароля через Auth); `pf_set_full_name(пользователь, ФИО)` — сам себе или администратор компании. Право — `security.roles.assign` (то же, что «Назначить роль»; у администратора компании) или администратор платформы; почта и ФИО — проверки формата; всё в журнал компании (`log_admin_change`). Нельзя: отключить/сбросить себя, администратора платформы — из компании.
2. **ФИО:** одно место хранения ФИО учётки (ядро, не Качество); `pf_list_company_members` + ФИО; при смене ФИО сервер переписывает имя в записях Качества этой компании, где автор — эта учётка (`engineer_name`/`inspector_name`/`created_by_name`… — список полей из `TABLES`), — старые и новые записи показывают текущее ФИО без переделки экранов Качества. Новое приложение пишет в Качество ФИО (мост — имя инженера = ФИО, не почта).
3. **Клиент:** «Сотрудники» — ФИО в списке, «Добавить сотрудника» (почта, ФИО, роль, объект), окно «Временный пароль — скопировать, больше не покажем», «Сбросить пароль», «Отключить доступ», правка ФИО; после входа с флагом — экран «Придумайте пароль» (дальше не пускает); «Настройки → Мой профиль»: ФИО, «Сменить пароль». Телефон 375 и ПК, светлая/тёмная.
4. **Старые профили RBI:** скрипт по списку «ФИО — почта» (файл вне git): для 17 — `pf_company_add_member` (роль временно, до P2-0033: `manager` → Администратор компании; `deputy_manager`, `director` → Руководство; `engineer` → Инженер ОТК на объект «Объекты RBI»; старая роль и закреплённые объекты профиля сохраняются в данных для P2-0033), `quality.rbi_transfer_people` → учётки; перенос заново (`docs/RBI_TRANSFER.md`: очистка + полный) — авторы `core_created_by` и ФИО в записях; старый профиль (настройки, рейтинг) — к профилю учётки. Владелец: старый профиль → **рабочая почта**; gmail — только администратор платформы (назначение «Администратор компании» в RBI с gmail снять после проверки рабочей). **Временные пароли 16 сотрудникам не выдаются** — их выдаёт владелец в день переключения (P2-0032) кнопкой «Сбросить пароль».
