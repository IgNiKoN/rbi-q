## 1. Цель

ПТО открывает проект → «КС-2» → выбирает договорную редакцию КП и период → система сама раскладывает принятый факт прораба по строкам заказчика (через связки ВОР) и добавляет материалы по норме → ПТО правит шапку и строки → сохраняет редакцию → скачивает Excel (унифицированная форма КС-2 или свой бланк проекта) → «Выдать» фиксирует акт; следующий акт не выставит этот объём повторно.

## 2. Подтверждённое исходное состояние (main `3f6790d`)

- Факт: `planfact.fact_entries` (`position_id`, `work_date`, `qty`, `status` — в объём идут только `accepted`); единый расчёт накопленного факта — `planfact.fact_totals(p_project)` (009), **без периода**.
- Связки: `planfact.vor_links` (`source_row_id` ↔ `position_id`, `share`), сейчас только 1:1 (`share = 1`); строки заказчика — `planfact.vor_source_rows` (`row_no`, `number`, `name`, `unit_text`, `qty`, `norm`, `kind` work/material, `parent_row_id`) — 007.
- Цены: `planfact.kp_revisions.snapshot` (`KpSnapshot.rows[]`: `import_id`, `row_no`, `price_labor`, `price_material`) — 008, неизменяемы (триггер). Тип — `src/modules/planfact/estimate/kp.ts`.
- Excel: exceljs 4.4.0 уже в бандле `planfact` (`vor/xlsx-reader.ts`, запись — `estimate/kp.ts` `kpWrites`). Новых зависимостей не требуется.
- Права: действие `planfact.ks2.edit` есть в каталоге (002) у `project_manager`, `pto`, `economist`. Действия просмотра КС-2 нет.
- Таблиц КС-2 нет. Storage проектом не используется (КП тоже не хранит файл).

## 3. Объём реализации

1. **Excel КС-2 по унифицированной форме (ОКУД 0322005)** — чистая функция «снимок акта → .xlsx» (`src/modules/planfact/ks2/`): шапка (инвестор, заказчик, подрядчик, стройка, объект, договор №/дата, номер и дата акта, отчётный период), таблица (№ п/п, № позиции по смете = номер строки заказчика, наименование, ЕИ, количество, цена за единицу, стоимость), итого, подписи «Сдал/Принял». Строки и ЕИ — заказчика, как в ВОР.
2. **Миграция 010** (`010_up.sql`/`010_down.sql`, только `planfact.*` и `public.pf_*`):
   - `ks2_settings` (на проект): `contract_kp_revision_id` (договорная редакция КП), `requisites jsonb` (реквизиты шапки, запоминаются), `template bytea` + `template_name`, `template_sha256` (свой бланк, ≤ 2 МБ; **не Storage**).
   - `ks2_acts`: `project_id`, `company_id`, `act_no`, `act_date`, `period_from`, `period_to`, `status` (`draft` | `issued` | `annulled`), `annul_reason`, кто/когда выдал.
   - `ks2_revisions`: `act_id`, `revision_no`, `snapshot jsonb` (шапка + строки: `source_row_id`, `row_no`, номер, имя, ЕИ, `kind`, **предложение системы** (объём, цена) и **итог ПТО** (объём, цена, исключена), «с начала работ», «выставлено ранее»), `total`; **неизменяемы** (триггер, как `kp_revisions`).
   - Выдача: `draft → issued` фиксирует последнюю редакцию; выданный акт не правится, новые редакции к нему запрещены; «Аннулировать» с причиной (`issued → annulled`), его объёмы снова доступны.
   - Расчёт предложения — сервером: EXTEND `fact_totals` необязательными границами дат (`p_from`, `p_to`, по умолчанию `null` = как сейчас; прежние вызовы не меняются) — **один** расчёт факта на всё. Объём строки заказчика = Σ (факт позиции за период × `share`) − уже вошедшее в выданные (не аннулированные) акты; материал = объём родительской работы × `norm`; цена — из договорной редакции КП по `row_no` (работа — `price_labor`, материал — `price_material`).
   - Права: новое действие `planfact.ks2.view` (просмотр) — шаблонам по матрице ТЗ (строка «Проект КС-2»: «да» → `ks2.edit`, «просмотр» → `ks2.view`); дозаполнить роли из шаблонов, как в 007–009. RLS: чтение — `ks2.view` или `ks2.edit` по проекту; запись — только `pf_*` `security definer` с проверкой `ks2.edit`, `company_id` из проекта, архивный проект — отказ.
3. **Экран «План/Факт → КС-2»** (раздел модуля, вкладка как «Факт», ПК и телефон): список актов проекта (№, период, статус, сумма, редакций) → «Новый акт» (период, № и дата — следующий номер подставляется) → таблица строк: наименование и ЕИ заказчика, «по системе», «в акт» (правится), «выставлено ранее», «с начала работ», цена (правится), сумма; отметка у строк, где итог ПТО ≠ предложение; «Исключить/вернуть строку»; шапка-реквизиты (правятся, по умолчанию из `ks2_settings`). Нет договорной редакции КП — экран просит выбрать её (ПТО), цены пустые нельзя выдать.
4. **Редакции и выдача (LP-09):** «Сохранить» = новая редакция (неизменяемая); «История» — список редакций с датой и автором, скачать любую; «Выдать» с подтверждением; «Аннулировать» с причиной.
5. **Свой бланк:** «Бланк КС-2 проекта» → загрузить `.xlsx` с метками в ячейках: `{акт_номер}`, `{акт_дата}`, `{период_с}`, `{период_по}`, `{заказчик}`, `{подрядчик}`, `{объект}`, `{договор}`, `{итого}` и **строка-образец** таблицы с метками `{№}`, `{номер}`, `{наименование}`, `{ЕИ}`, `{количество}`, `{цена}`, `{стоимость}`. Проверка при загрузке: файл читается, строка-образец одна, неизвестные метки — список. Скачивание акта: бланк проекта или унифицированная форма (выбор). Строка-образец размножается с сохранением её оформления. Список меток — на экране загрузки.
6. Документы: `APP_GUIDE`, `AUTH_AND_ACCESS`, `FILE_MAP`, `TECH_DEBT`, `CHANGELOG`, `SERVERS` (010).

**Вне блока:** КС-3; сверка «факт ↔ подписано заказчиком» как отчёт (вход — данные этого блока, отчёт — со сводкой P2-0008); связки 1:N/N:1 в интерфейсе ВОР (формула `share` уже их учитывает); плановый ФОТ/маржа (LP-05); подписи ЭЦП, отправка заказчику; редакции ВОР (P2-0006b) — при новой редакции ВОР акты продолжают ссылаться на строки своей загрузки.
