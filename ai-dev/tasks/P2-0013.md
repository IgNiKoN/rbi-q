## 1. Цель

Человек открывает платформу → экран «Вход» с двумя способами: **«Почта и пароль»** (основной, один вход на все разделы Platform 2.0) и **«Имя, код проекта и PIN»** (старые сотрудники РБИ, переходный период — прежний вход Quality без изменений). В меню только то, что положено: вошедшему почтой — модули его компании ∩ роль («План/Факт»…), вошедшему по PIN — Quality и Стройконтроль, как сейчас; неположенный модуль на устройство **не скачивается**. Владелец как администратор платформы в «Настройки → Администрирование платформы» видит компании, создаёт компанию и включает/выключает ей модули. В конце блока 2.0 готова заменить старую версию на сервере владельца: люди получают обновление и работают в Quality как раньше, без потери данных на телефоне.

## 3. Объём реализации

1. **Сервер (миграция `014`, только добавление):** `planfact.platform_admins(user_id)` (без доступа клиенту), `planfact.module_catalog(code, name)` — пока один модуль `planfact`; признак администратора платформы в `planfact.has_permission` / `has_company_permission` / `is_project_member` (ADR-064 п. 6 — **одна** проверка, не разрозненно); функции: `pf_my_platform()` — кто я: администратор платформы ли, мои компании и **доступные мне модули по каждой** (модули компании ∩ права); `pf_platform_companies()`, `pf_platform_create_company(name)`, `pf_platform_set_module(company, module, enabled)`, `pf_platform_set_company_admin(company, email)` — только администратору платформы, каждое изменение — в журнал (`audit_log`). Назначение владельца администратором платформы — отдельный SQL, выполняет владелец (почта — §8).
2. **Вход при открытии:** окно «Работать локально / Войти в облако» становится экраном «Вход» с двумя вкладками: **«Почта и пароль»** (по умолчанию) и **«Имя, код проекта и PIN»** — прежняя форма и прежний код входа Quality (`sync-auth.js`, `sync-connection.actions.js`) **без изменения логики**, подпись «для сотрудников, работающих в Качестве по старому входу». Ниже — мелкая ссылка «Посмотреть без входа (демо)» (нынешний локальный режим). Вход запоминается на устройстве; «Выйти» — в «Настройки → Платформа» (и в полосе «почта · компания · роль»). Несколько компаний — переключатель «Компания: …» в шапке. «Вход в План/Факт» внутри модуля убирается (нет сессии — экран «Вход»). Пока облако Quality в сборке разработки выключено (п. 6), вкладка PIN показывает прежнее «облачный вход отключён».
3. **Меню по способу входа и модулям:** вошедший **почтой** — модули из `pf_my_platform` для выбранной компании (+ «Настройки»), пункты Quality / Стройконтроля скрыты; вошедший **по PIN** — Quality / Стройконтроль по прежним правилам оболочки, пунктов Platform 2.0 нет; адрес недоступного модуля → «Модуль не подключён». Подвкладки — по правам, как сейчас. (Один человек с обоими входами — до этапа «Quality в Platform 2.0» это две разные учётки.)
4. **Не скачивать неположенное:** бандлы `planfact` и `company` подгружаются динамически только после входа и только при доступе (`planfact` — модуль доступен; `company` — право `security.roles.assign` или администратор платформы); `sw.js` — те же правила кэша/удаления, что у Quality, для `js/dist/planfact/`, `js/dist/company/`. Человек без доступа (и вход по PIN / демо) этих файлов не получает; выключили модуль — файлы удаляются после обновления.
5. **«Настройки → Администрирование платформы»** (только администратор платформы; сервер проверяет каждый вызов): список компаний (название, тестовая ли, число людей, модули), «Создать компанию», выключатель модуля у компании, «Назначить администратора компании» (по почте **существующей** учётки; создание учёток — P2-0013b). Подвкладки в стиле Настроек, адрес `#/settings/platform-admin`.
   **Старые модули (решение владельца 22.10.2026):** Качество, Стройконтроль и другие модули оболочки **не отключаются** и работают по старому входу, как сейчас; в списке модулей компании они видны с пометкой «работает по старому входу (PIN), управление — после переноса Quality в Platform 2.0», без выключателя. Выключатель (сервер + меню) — только у модулей Platform 2.0 (сейчас «План/Факт»). Каталог модулей (`module_catalog`) хранит и старые модули с признаком «управляется по старому входу» — один источник для списка.

6. **Готовность к выпуску 2.0 вместо старой версии:** один переключатель сборки «разработка / выпуск» в `config.service.js` (единственное место): **разработка** (GitHub Pages, как сейчас) — облако Quality выключено, локальная база `PLATFORM2_DB`; **выпуск** (сервер владельца, вместо старой версии) — адрес и ключ облака Quality возвращены, локальная база `RBI_QUALITY_DB` (черновики и фото людей на месте), старые кэши `rbi-quality-*` удаляются. Инструкция выпуска в `docs/SERVERS.md` («как собрать и выложить, как откатить на старую версию»). Выкладывает владелец, когда решит.
**Вне блока:** создание учёток людей, временный пароль, сброс пароля, смена пароля при первом входе (P2-0013b); сброс пароля письмом (отдельное решение по Auth); подключение старого Quality к компаниям (этап «Quality в Platform 2.0»); одна общая копия React для бандлов (ТД); переключение «админ платформы видит всё» → модель SaaS (пункт ROADMAP перед продажей).
