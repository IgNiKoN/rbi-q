## 1. Цель

Владелец (или его гость) открывает платформу с компьютера или телефона, входит по очереди ПТО, прорабом, РП и руководителем «Демо-компании» и по инструкции `docs/DEMO.md` проходит весь путь: объект «ЖК Спутник (демо)» → ВОР заказчика → смета и КП в форме заказчика → факт прораба с телефона (с исправлением) → КС-2 в Excel → сводка руководителю обновилась; вход сотрудником другой компании объекта не видит.

- Меню модуля (`js/modules/planfact/planfact.manifest.js`): первым — «Работы» (`#/planfact`, демо-таблица P2-0002 `PlanfactTable`/`PlanfactWorks` и таблица `planfact.works`).

## 3. Объём реализации

1. **Сквозной прогон** на локальном стенде (PGlite + оболочка, папка сеанса) по реальному файлу «Спутник» всеми ролями — журнал шагов и список находок (мелкие / крупные).
2. **Исправление мелких находок** (тексты, сообщения, переходы между разделами, пустые состояния, вёрстка) — только по списку, показанному владельцу.
3. **Меню:** убрать пункт «Работы»; `#/planfact` открывает «Сводку»; в режиме «Работать локально» без входа — понятная подсказка «войдите» вместо демо-таблицы. Код `PlanfactTable`/`PlanfactWorks`/`planfact.works` — не удалять (только убрать из меню и маршрута по умолчанию); удаление — отдельным решением (ТД).
4. **Демо-компания на общем сервере** (по разрешению владельца на шаг): компания «Демо-компания» (`is_test = true`), 4 учётки `*@demo.invalid` — ПТО, прораб, РП, руководство (+ админ компании); пароли только в `.env.local` (`P2_DEMO_*_PASSWORD`), владельцу — где их взять, не в чат и не в git; объект «ЖК Спутник (демо)» с деревом мест; заполнение — **через интерфейс/RPC `pf_*` от имени ролей** (ВОР из файла, смета, КП, договорная КП, факт за ~4 недели, один выданный КС-2, плановые даты). Скрипт создания учёток и наполнения — в `scripts/` без паролей и без данных файла (файл читается с диска владельца).
5. **Инструкция** `docs/DEMO.md` (шаги показа по ролям, что увидит зритель, как сбросить демо) + актуальный `README.md` (запуск, вход, демо).
6. Документы: `APP_GUIDE`, `SERVERS` (демо-компания, как удалить), `FILE_MAP`, `TECH_DEBT`, `CHANGELOG`.

**Вне блока:** новые функции и изменения БД (только списком владельцу), P2-0006b редакции ВОР, ГПР, удаление старого кода «Работы», чистка «Альфа/Бета», production RBI/Quality.
