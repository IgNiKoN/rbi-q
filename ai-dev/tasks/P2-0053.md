## Решения владельца (27.10.2026)

1. «Ну давай доделаем эталонный демостэнд» — пробующим дать учётки, пусть ставят на телефоны, грузят ВОР, смотрят.
2. **Состав — все модули:** ядро + План/Факт + Качество + Стройконтроль (рекомендация).
3. **Учётки — «Демо + Песочница»** (рекомендация, владелец без предпочтения): «ЖК Демо» — витрина с выдуманными данными, пересоздаётся; отдельная пустая компания «Песочница» — личные учётки пробующих, свои ВОР; пересоздание демо её не трогает.
4. **Старая «Демо-компания»** (ЖК «Спутник», реальная ВОР заказчика) — **удалить после приёмки** P2-0053, отдельным шагом по разрешению владельца.
5. **Начинать после P2-0048** (рекомендация).
6. **Риски безопасности — «низкие, в техдолг, пока не делаем»:** общий ключ ИИ без лимита, старый `deepseek-proxy` с паролем по умолчанию, общий ключ подсказок на телефоне — ТД №281–283. Следствие для блока: **ИИ-помощник в демо и «Песочнице» не включать.**

## 1. Цель

Владелец даёт человеку учётку → тот на телефоне или ПК видит заполненный выдуманный проект во всех модулях глазами своей роли, а в «Песочнице» загружает свою ВОР и пробует сам. Ни одной реальной записи заказчика или РБИ в демо нет. Демо пересоздаётся одной командой с тем же результатом.

## 3. Объём реализации

1. `scripts/demo/` — один сценарий: данные в JSON (структура, виды работ, чек-листы, подрядчики, бригады, роли), генератор ВОР и факта с фиксированным «зерном», параметр `--today`.
2. Компании (`is_test = true`, почты `@demo.invalid`): «Девелопмент Демо» (наша роль — заказчик) и «СтройМонтаж Демо» (наша роль — подрядчик). Подразделение «Дирекция 1», проект «ЖК Демо» (стадия «строительство», `Europe/Moscow`, RU).
3. Места: 2 корпуса × 2 секции × 9 этажей × 4 квартиры (строительный номер и номер БТИ) + МОП, кровля, паркинг ≈ 200 мест — через функции ядра P2-0047.
4. План/Факт: ВОР «своей» формы (генерируется), смета и КП, факт за 4 недели с одним исправлением, КС-2 №1, 3 подрядчика (отделка, сети, фасад) по ИНН-заглушкам, 1–2 бригады.
5. Качество и Стройконтроль: 20 видов работ, к каждому шаблон чек-листа 5–10 пунктов, 10 проверок, 30 замечаний с фото-заглушками, подрядчик видит только свои замечания, 2–3 приёмки СК.
6. Учётки по ролям, у каждой — своя область через участие (P2-0048): руководитель, РП, ПТО, прораб (одна секция), инженер качества (один корпус), экономист, заказчик, представитель подрядчика. Модули: План/Факт, Качество, Стройконтроль, База знаний — вкл., ИИ — выкл.
7. Сброс: только `is_test = true` **и** почты `@demo.invalid`; «Песочница» и реальные компании не трогаются (защита в самом скрипте + тест).
8. Памятка `docs/DEMO.md` (переписать): «как дать доступ пробующему» — демо-учётка или личная в «Песочнице», установка на телефон, сценарий показа по ролям, ограничения.

## 8. Риски и зависимости

- **Сброс на общем сервере** удалит не то → два признака, тест на стенде с «чужими» данными, снимок РБИ до/после, первый прогон на общем — только создание (сброс пуст).
- Запись Качества без серверных функций → через сервисы/REST под ролью; если клиентский сервис нельзя вызвать из скрипта — стоп, вариант Архитектору.
- Админ платформы не может создать учётку админа «Песочницы» из интерфейса → владелец заводит сотрудников сам (проверить в этапе 5) или SQL по схеме `demo-users.mjs`.
- Фото-заглушки занимают место на сервере (диск 80 ГБ) — маленькие (≤ 50 КБ), ≤ 30 шт.
- Демо-учётки общие: кто знает пароль — видит демо (данные выдуманные — допустимо).
