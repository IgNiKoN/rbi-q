## 1. Цель

Клиент с учёткой своей компании нажимает «Демо» → выбирает «смотреть как: прораб / ПТО / инженер качества / …» → видит заполненный «ЖК Демо» во всех модулях глазами этой роли (её область, её меню); любая запись — понятный отказ «Демо — только просмотр»; «Выйти из демо» — его компания и его неотправленные данные на месте. Кнопка «Обучение» ведёт по шагам (подсветка элемента + пояснение, «Далее / Назад / Закончить») через главные сценарии на данных «ЖК Демо». Владелец по памятке за 5 минут даёт новому клиенту доступ в его собственную компанию.

## 3. Объём реализации

1. **Вход в демо (сервер, `057`)**: признак демо-компании (`core.companies` — флаг или настройка, выбрать минимальное); набор **демо-ролей «только просмотр»** в демо-компании — копии 8 ролей (руководитель, РП, ПТО, прораб, инженер качества, экономист, заказчик, представитель подрядчика) только с действиями просмотра; `pf_demo_enter(p_role)` — вошедшему из любой компании: участник демо-компании с этой демо-ролью и её областью (участие P2-0048), повторный вызов меняет роль; `pf_demo_leave()`; `pf_demo_roles()` — список для выбора. 2. **Посетители не видны**: в демо-компании посетители не попадают в «Сотрудники», «Кто что может», списки людей, выбор исполнителя; клиенты не видят почты друг друга.

Запись — только через функции экранов / REST под учёткой роли (права проверяет сервер).

5. **Кнопка в приложении**: пункт «Демо» (место и вид — как в Качестве: меню/шапка, плашка «Демо · смотрите как: [роль ▾]», «Выйти из демо»); выбор роли; при записи — тост «Демо — только просмотр»; кнопки записи в демо можно не прятать, но отказ должен быть понятным, не «ошибка сервера». ## 8. Риски и зависимости

- **Функция записи проверяет ключ роли, а не действие** → посетитель пишет. Этап 1: перебор всех `pf_*` записи под посетителем в SQL-тесте (список функций — из описи схемы).
- **Сброс на боевом удалит не то** → признак демо-компании + почты `@demo.invalid`, тест «до = после» с посетителем, снимок РБИ, первый прогон на боевом — только создание.
- Демо-компания на устройстве — отдельная база «компания + пользователь»; размер данных демо на слабом телефоне — проверить время первого входа (≤ 5 с на стенде с замедлением, как P2-0068).
