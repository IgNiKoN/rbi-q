## 1. Цель

У Стройконтроля — свои действия в общей матрице «Роли и права» и область по объектам. Сервер сам проверяет каждое действие, телефон — то же правило (без сети тоже).

**Что увидит владелец:** «откройте "Компания → Роли и права" → группа "Стройконтроль" — галочки по действиям (выдать, в работу, устранено, закрыть, вернуть, удалить; приёмка: записаться, подтвердить время, провести); "Компания → Сотрудники" — у инженера участие на объекте ЖК-1; войдите им → в Стройконтроле только замечания и приёмки ЖК-1; снимите у роли галочку "Закрыть" → кнопки "Закрыть" нет, а запрос в обход экрана сервер отклоняет; "Кто что может на объекте" → выбрали ЖК-1 → люди × действия».

## 2. Подтверждённое исходное состояние (Архитектор, 30.10.2026, `main` `55dcd2e`)

- Действия Стройконтроля — три грубых: `construction.view` / `.edit` / `.manage` (+ `construction.objects.manage`); каталог — `core.permission_catalog` (перенесён из `planfact` в 016), экран — `src/platform/company/CompanyRoles.ts`, группы подписей — `action-groups.ts` (группы Стройконтроля нет — всё в «Прочее»).
- Права строк `construction_defects_v2`, `construction_acceptance_v2` — `quality.row_visible_id(…, 'contractor', …)` (043): **без объектов** — с `construction.edit` видно и правится всё в проекте; подрядчик — своя фирма по `core_counterparty_id`. Подрядчик в замечаниях — сторож `quality.contractor_defect_guard` (043): переходы `issued|rejected → in_progress → fixed`, история только дописывается.
- Объект записи: `"locationId" text` → `quality.location_nodes` (дерево мест, 044 — синхронно с `core.locations`), `core_project_id` ставит триггер `v2_bind_object`. Колонки места ядра (`core_location_id`) нет — это шаг **С1** плана переезда P2-0069.
- Область сотрудника: ядро — `core.role_assignments.location_id` (P2-0048, 047: узел и всё под ним; «Участие в проекте»); Качество — мост `quality_objects` (снятие — ТД 276, блок «Качество по участию»).
- Устройство: описание `sync` Стройконтроля — `objects: false` (`js/modules/construction-v2/construction-v2.manifest.js`), правило — `js/services/sync/sync-access.policy.js`, зеркальный тест — `tests/server/sync-access.mirror.mjs`.
- Статусы: замечание `issued → in_progress → fixed → closed`, возврат `rejected`; приёмка `pending → accepted / rejected / cancelled` (сверить по `src/modules/construction-v2/*`).

## 3. Объём реализации

1. **Действия Стройконтроля в каталоге** (строки `core.permission_catalog`, подписи по-русски):
   - Замечания: `construction.defects.view`, `.create` (выдать), `.assign` (подрядчик и срок), `.start` (в работу), `.fix` (устранено), `.close` (закрыть — принять устранение), `.reject` (вернуть на доработку), `.delete` (отменить / удалить).
   - Приёмка: `construction.acceptance.view`, `.book` (записаться), `.schedule` (подтвердить / перенести время), `.conduct` (провести: принято / с замечаниями / не принято).
   - Настройки: прежний `construction.manage`. **Передача квартир** (transfer-board) в списке владельца нет — ничего не терять: действие `construction.transfer.edit` («Передача: вести»).
   - **Перенос без потери прав:** у каждой существующей роли (шаблоны и роли компаний) новые действия выставляются по прежним: `view` → оба `*.view`; `edit` → все действия замечаний и приёмки; роль-подрядчик (`quality.scope.contractor`) → `defects.view/start/fix`, `acceptance.view/book`; `manage` — как был. Прежние ключи остаются (старые таблицы Стройконтроля 1 и Качество их читают). Проверка: до = после по каждому пользователю тестовой базы.
2. **Сервер — объект и место записи по id ядра (поле рядом, С1):** `core_location_id uuid` у `construction_defects_v2` и `construction_acceptance_v2` — триггер из `"locationId"` через дерево 044 (неоднозначно / не найдено — пусто, не угадывать); заполнить старые строки; проба на боевой — запрос только на чтение (сколько привязалось однозначно) до выкладки.
3. **Сервер — видимость по участию:** запись видна, если у сотрудника есть действующее участие с действием `*.view` и место участия пусто (весь проект) или `core_location_id` записи — в его поддереве; подрядчик — дополнительно своя фирма (как сейчас). Записи без места — видны только тем, у кого участие на весь проект, и автору. Общая функция — **одна**, с параметром «действие» (не копия на таблицу) — её же возьмёт заготовка «новая таблица модуля».
4. **Сервер — каждое действие:** сторож переходов (обобщить `contractor_defect_guard`): «создать / смена статуса / смена подрядчика и срока / удаление» → требуемое действие из п. 1 в области записи; иначе 42501 с русским текстом («Нет права "Закрыть замечание" на объекте ЖК-1»). Подрядчик — прежние ограничения 043 сохраняются.
5. **Устройство:** описание `sync` — действия и область по месту вместо `objects: false`; кнопки экранов (реестр, карточка замечания, канбан приёмки, кабинет подрядчика, передача) показываются по действию; без сети — то же правило (P2-0061). Зеркальный тест: телефон = сервер по всем новым действиям и по области.
6. **Экраны «Компания»:** группа «Стройконтроль» в `action-groups.ts` (подгруппы «Замечания», «Приёмка», «Передача», «Настройки»); участие сотрудника на объекте / секции — существующий мастер (`AssignWizard.ts`), без нового; новый экран **«Кто что может на объекте»** (вкладка в «Роли и права» или в карточке объекта — по макету): объект → люди × действия, только чтение, собирается из ролей и участия. Телефон и ПК, обе темы. Макет «сейчас / предлагаю» на настоящих данных стенда — **показ** до вёрстки.

**Вне блока:** Качество на тонкие действия и на участие (ТД 276) — следующим шагом по тому же механизму; исключения прав на отдельном объекте (вариант «В») — по запросу; заготовка «новая таблица модуля» и правило 10 «валюта у родителя» в стороже — блок 4в «Номера Качества» (перенесено из 4б: блок и так на пределе 3 дней).

## 6. Критерии приёмки

Сценарий п. 1 проходит на стенде; ни одна существующая роль не потеряла права (таблица до = после в отчёте); обход экрана — отказ сервера с понятным текстом; телефон = сервер (зеркало); полный стенд зелёный; выкладка — миграция до приложения, откат описан.

## 8. Риски

- Записи без места или с неоднозначным местом пропадут у инженеров с участием на объект — проба на боевой до выкладки, такие записи видны участникам на весь проект и автору; число — в отчёте.
- Приложение шлёт строку целиком (upsert) — сторож определяет действие по разнице полей, как в 043.
- Объём на пределе 3 дней — при превышении резать по этапу 4 (экран «Кто что может» — отдельным коротким блоком), не по слоям.
