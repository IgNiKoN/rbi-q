## 1. Цель

Один механизм прав для всех модулей: **действия** — строки общего каталога (с группами для экрана — данными, не кодом); **область** — участие в проекте (проект / объект / секция / этаж); **одна проверка на сервере** «может ли человек действие на этом месте» и **то же правило на устройстве** (P2-0061). Модуль подключается, объявив свои действия и место записи. Первыми подключаются Стройконтроль (у него сейчас нет объектов вообще) и План/Факт (уже работает так, но проверка живёт внутри План/Факта — поднимается в ядро без смены поведения). Качество — следующим блоком по тому же образцу.

**Что увидит владелец:** «откройте "Компания → Роли и права" → группы "План/Факт" и "Стройконтроль" с галочками по действиям; "Компания → Сотрудники" — у инженера участие на ЖК-1; войдите им → в Стройконтроле только ЖК-1; снимите у роли "Закрыть замечание" → кнопки нет, обход экрана — отказ сервера с текстом; экран "Кто что может на объекте" → ЖК-1 → люди × действия по всем включённым модулям; План/Факт работает как раньше».

## 3. Объём реализации

1. **Ядро — одна проверка прав** (миграция 052): `core.my_area(project)`, `core.in_area(location, area)`, `core.can_at(company, project, location, action)` и `core.row_allowed(…, action, location, author, counterparty)` для правил строк — по образцу `planfact.my_area/in_area` (поднять, не переписать заново). Подрядчик — своя фирма по id контрагента (как 043). Платформенный администратор, срок действия, отзыв назначения, включённость модуля у компании (`core.company_modules`) — как сейчас.
2. **Каталог — данные для экрана:** у `core.permission_catalog` — модуль, группа, порядок, подпись (колонки); `action-groups.ts` читает группы из каталога (свой список в коде — убрать, оставить только запасное «Прочее»). Новое действие любого модуля появляется на экране без правки кода.
3. **План/Факт — на проверку ядра без смены поведения:** функции и правила `planfact` вызывают `core.*` (старые `planfact.my_area…` — тонкие обёртки на переходный срок или замена вызовов — решает Исполнитель, отчёт). Все существующие серверные тесты План/Факта и стенд — без изменений ожиданий.
4. **Стройконтроль — подключение:**
   - действия в каталоге: замечания — `construction.defects.view`, `.create` (выдать), `.assign` (подрядчик и срок), `.start` (в работу), `.fix` (устранено), `.close` (закрыть), `.reject` (вернуть), `.delete` (отменить / удалить); приёмка — `construction.acceptance.view`, `.book` (записаться), `.schedule` (подтвердить / перенести время), `.conduct` (провести); передача — `construction.transfer.edit` (в списке владельца нет — ничего не терять); настройки — прежний `construction.manage`; какие из них даёт участие на часть проекта — `area_scoped`;
   - **перенос без потери прав:** роли получают новые действия по прежним (`view` → `*.view`; `edit` → все действия замечаний и приёмки; роль с `quality.scope.contractor` → `defects.view/start/fix`, `acceptance.view/book`); прежние ключи остаются (Стройконтроль 1 и Качество их читают); таблица «до = после» по каждому пользователю тестовой базы;
   - `core_location_id uuid` у `construction_defects_v2`, `construction_acceptance_v2` — триггер из `"locationId"` через дерево 044 (неоднозначно — пусто, не угадывать) + заполнение; проба на боевой — запрос только на чтение до выкладки;
   - правила строк — `core.row_allowed`; сторож действий (обобщить `contractor_defect_guard`): создать / статус / подрядчик и срок / удаление → нужное действие на месте записи, иначе 42501 с текстом («Нет права "Закрыть замечание" на объекте ЖК-1»); ограничения подрядчика 043 сохраняются.
5. **Устройство:** в `sync-access.policy.js` — область по участию (место) и действия для **любого** модуля (описание `sync`: `area: 'location'`, ключ места записи, действие на переход); Стройконтроль — вместо `objects: false`; План/Факт — то же описание; кнопки экранов Стройконтроля по действию; без сети — то же правило. Зеркальный тест: телефон = сервер для обоих модулей.
6. **Экраны «Компания»:** группы из каталога; участие — существующий мастер (`AssignWizard.ts`); новый экран **«Кто что может на объекте»**: объект (или секция) → люди × действия по всем включённым у компании модулям, только чтение, один RPC. Телефон и ПК, обе темы; макет «сейчас / предлагаю» — **показ** до вёрстки.
7. **Стандарт:** раздел «Права на сервере» в `standards/SYNC_AND_ACCESS.md` (одно место для устройства и сервера): как модуль подключается — действия в каталоге, `area_scoped`, место записи по id, правило строк через `core.row_allowed`, сторож действий, описание `sync`, строка зеркального теста. Это и есть образец для Качества и новых модулей.

**Вне блока:** Качество на тонкие действия и участие вместо `quality_objects` (ТД 276) — **следующий блок** по стандарту п. 7; исключения прав на отдельном объекте (вариант «В») — по запросу; заготовка «новая таблица модуля» и правило валюты в стороже — блок «Номера Качества» (ссылается на стандарт п. 7).
