## 1. Цель

На устройстве появляется **одно правило** «кто я, что моё, можно ли отправить, что скачать», зеркальное серверному. Модули подключаются к нему **описанием** в манифесте, а не своим кодом. После блока:
- Осмотр, задача, совещание, замечание и любая другая запись знает **id автора**; «моё» определяется по id учётной записи, объект — по id объекта ядра, фирма — по id контрагента. ФИО — только подпись.
- **Сменили ФИО**, пока на телефоне лежали неотправленные осмотры, — они уходят, ровно 1 раз.
- **На телефоне чужая запись** (работали двое) — не уходит, но в Истории и в «Данные на устройстве → Отправка» видно: «Не отправлено: запись другого сотрудника (Иванов И.)» и что делать. Ничего не висит молча.
- **Отклонённое сервером** уходит снова, когда права дали, — само или по кнопке «Отправить снова» (ТД 313).
- «Своё первым» и порции — у всех видов записей, не только у осмотров (ТД 315).
- Новый вид записи или модуль = одна строка описания: движок, счётчик «не отправлено» и экран «Отправка» не правятся.

## 3. Объём

1. **Правило устройства — один модуль платформы** (pure, unit-тесты; место — по образцу `sync-*.policy.js` или `src/platform/services/`, решает Исполнитель, фиксирует в стандарте):
   - `me` — кто я: `userId` (id учётной записи), `names` (текущее + прежние ФИО), `actions` и область (объекты по id, фирма по id, вся компания) — из ответа сервера (`my_access`, участие), **не из названия роли**;
   - `isMine(rec, kind, me)`, `canSend(rec, kind, me) → { ok, reason, hint }`, `visible(rec, kind, me)` (для отбора после скачивания), `stampAuthor(rec, me)`;
   - режимы — как на сервере: `author`, `owner`, `contractor`, `shared` (свойства каждого — по `quality.row_visible*` в `020/023/033/043`).
2. **Описание видов записей в манифестах** (поле `sync`, формат — `standards/SYNC_AND_ACCESS.md`): Качество (осмотры, задачи, совещания, вмешательства, FMEA, эталоны, этапы графика, отчёты, документы), СК (записи ПК СК), База знаний (практики, карты TWI), Стройконтроль 2.0 (замечания, приёмки, помещения). `RECORD_STORES` и счётчик «не отправлено» строятся из описаний.
3. **Автор — id:** при создании записи общая функция ставит `authorId = me.userId`, ФИО — подписью; при скачивании `core_created_by` сохраняется как `authorId`. Мост при смене ФИО запоминает прежнее (`names`, по «компания + пользователь»).
4. **Переходное правило** (решение владельца): запись без `authorId` — моя, если ФИО = текущему или прежнему моему; при первой проверке дописать `authorId`. Иначе — «Не отправлено: запись другого сотрудника (ФИО)» с подсказкой «отправит руководитель или автор, войдя на этом телефоне».
5. **Движок отправки — по правилу:** 6 копий отбора «по ФИО» и проверка `:1063-1105` заменяются вызовом правила; отсеянное — `blocked` с причиной (не `not_synced`). Решения по `isAdmin()` / `=== 'engineer'` в синхронизации — по действиям и области.
6. **Повтор и порядок (бывшая «Починка отправки»):** ТД 313 — `blocked` и «Сервер отклонил» перепроверяются, если мой доступ изменился с прошлой попытки (отпечаток доступа на записи), и по кнопке «Отправить снова» в «Данные на устройстве → Отправка»; ТД 315 — «своё первым» и порции по 5 для всех видов с `ownFirst`; ТД 320 — перед «своим первым» — лёгкое обновление справочника объектов, если он старше прохода (или отправка по id объекта без канонического ключа).
7. **Скачивание по правилу:** отбор после скачивания (`sync-push-pull.core.js:470-535`) и запросы «свои» (задачи `:1846-1880`, ТД 149) — по id автора, объекта и фирмы.
8. **Права экранов «изменить / удалить»:** `canEdit` / `canDelete` принимают запись и спрашивают то же правило (по id, переходно — по ФИО); вызовы ТД 238 (`game.actions.js:1247`, `meetings.module.js:1436`, `etalon.actions.js:959`, `interventions.js:1432`, `history.actions.js:301`, `knowledge.*`, `tasks.module.js:1805/1898/1921`, `sync-merge.policy.js:107`) переводятся на запись. Старая подпись `canDelete(name, id)` — оставить совместимой.
9. **Причины на экране:** `sync-status.ts` `reasonFor` различает «Не отправлено: …» (решило устройство, с подсказкой) и «Сервер отклонил: …»; кнопка «Отправить снова»; История модуля показывает ту же причину (`history.render.js:1276`). Тексты — через `locales` (ru), слова — по словарю.
10. **Документы:** `standards/SYNC_AND_ACCESS.md` — «Как подключить модуль» и «Где в коде» по факту; `MODULES.md` раздел 3 — сервисы «Права» и «Офлайн и синхронизация» (описание `sync`, правило устройства = серверу); `AUTH_AND_ACCESS.md` (P2-0035b — «своё» по id везде); `GLOSSARY.md` (если меняются имена полей); `APP_GUIDE.md` («Не отправлено» и «Отправить снова»); `CHANGELOG.md`, `FILE_MAP.md`; ТД 149, 238, 313, 315, 320 — закрыть; новое — в ТД.

**Вне блока:** План/Факт (пишет прямо на сервер) — подключается этим описанием в **P2-0064** (очередь факта, `onBehalfPlan` `area.ts:162` — по `user_id` вместо почты). Экранные проверки, не связанные с автором записи (`contractor-directory-ui`, `location-directory-ui` — право «управлять справочником»), и замена `ROLE_MATRIX` в экранах Качества целиком — по мере блоков, с записью в ТД. Сервер и RLS — не меняются.
