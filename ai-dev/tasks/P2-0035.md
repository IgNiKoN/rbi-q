# P2-0035 — Качество по id: записи привязаны к объекту и подрядчику по id, один список объектов компании

**Статус:** DONE · 26.10.2026 (принято владельцем «Архитектор. принято P2-0035»; акт `reports/P2-0035/acceptance-record.md`)
**Владелец продукта:** Igor (IgNiKoN)
**Репозиторий:** `platform-2-core`. База — `main` после P2-0031 (`8063ba8` и новее).
**Ветка:** `task/P2-0035-quality-by-id` (создаёт Исполнитель от `main`).
**Предшествующая задача:** P2-0031 (DONE). **Следом:** P2-0032 (день переключения, упрощён), затем P2-0038; **P2-0035b** (люди по id + ТД №189) — после переключения, до второй независимой компании.
**Основание:** ADR-070 «сначала id, потом имя» п. 1–4; ADR-066 (мастер-данные — ядро); ADR-068 п. 6 (подрядчики Качества = контрагенты ядра); ТД №191, №193, №197; `specs/2026-10-25-admin-settings-inventory.md` §3 п. 4. **CRITICAL — одна зона: правила доступа (RLS) и миграции данных Качества.**

**Решения владельца (25.10.2026, кнопки):**
1. P2-0035 делится на два блока: **P2-0035** (до переключения) — объекты и подрядчики по id, один список объектов; **P2-0035b** (после переключения, до второй компании) — люди по id (профиль, рейтинг, «мои задачи», очки) + ТД №189. Люди пока — через переходную привязку по ФИО (P2-0028).
2. Объекты — **один главный список на компанию** (ядро). Качество хранит только своё дополнительное (синонимы, коды, планы этажей) со ссылкой на объект ядра. Создали объект в одном месте — виден везде. Дубли с одинаковым (очищенным) названием склеиваются один раз; спорные — списком владельцу, не угадывать.
3. Записи, у которых объект или подрядчик не узнан, — в список «не разобрано» для администратора (ничего не теряется и не скрывается молча).

**Решения владельца после BLOCKED этапа 1 (25.10.2026, кнопки; обсуждение с Архитектором):**
4. **Каждый ЖК — свой объект ядра** (вариант 1). Каждая строка `quality.project_objects` получает свой `core.projects` (у RBI — 13 новых объектов); связь — новая обязательная колонка `project_objects.core_object_id`. У записей Качества — **новая** колонка `core_object_id` (объект ЖК). Смысл `core_project_id` и `project_code` **не меняется** (контейнер; на него опираются `quality.can`, назначения «на объект ядра», `bind_company`, сторож `037b`). Варианты «переназначить `core_project_id`» и «главный — список Качества» отклонены.
5. **Порядок:** P2-0035 → P2-0032 (переход всех на новую платформу) → P2-0038 → P2-0035b. Отказ от старого приложения не отменяет дописывания id сервером: экраны Качества новой платформы (`js/`) пишут название и `project_code` контейнера так же, как старое приложение.
6. **«Папка» «Объекты RBI»** (контейнер ядра) — скрыть из списков объектов («Компания», План/Факт, выбор объекта в Качестве), оставить служебной (на неё ссылаются `project_code`/`core_project_id`). Не удалять, не архивировать в этом блоке.
7. **Новый объект:** создан в «Компании»/План/Факте → сервер добавляет дополнение в `quality.project_objects` (виден в Качестве); создан в Качестве → сервер создаёт `core.projects` и связывает. Должно работать и у **новой компании без контейнера** (проверка обязательна). **Потом** (после P2-0032, отдельным блоком, в дорожную карту): экраны Качества пишут `core_object_id` сами — тогда узнавание по названию и контейнер можно убрать.

**Доработка 1 (ревью 26.10.2026):** исправить M1 (закрепления инженеров переходят на объект, пришедший вместо созданного сервером), M3 (пересчёт «не разобрано» — только при реальном изменении и один раз на запрос), L6 (переименование узла — по ключу/названию, без синонимов; неоднозначно — объект ядра не трогать). Тесты на каждое; миграция `039d` (up/down) — на сервер по разрешению владельца. L4, L5, L7 — в TECH_DEBT.
**Решение владельца №8 (26.10.2026, кнопки):** администратор Качества создаёт и переименовывает объекты компании из Качества — «Оставить как сделано».

## 1. Цель

Переименовали объект или подрядчика — записи Качества (проверки, пункты, фото, СК, задачи) остаются при нём, инженер, закреплённый за объектом, их видит, фильтры и отчёты показывают их под новым названием. Объект, заведённый в «Компании»/План/Факте, сразу доступен в Качестве, и наоборот.

## 2. Подтверждённое исходное состояние (25.10.2026, код — только чтение)

- `quality.project_objects` (`018_quality_up.sql`): `id text`, `canonical_key`, `display_name`, `synonyms[]`, `project_code`, `core_company_id`, **`core_project_id uuid`** (заполнение не проверено). Отдельный справочник Качества; синонимы — `quality.object_aliases`, очередь — `quality.object_normalization_queue`, дерево — `quality.location_nodes`.
- Записи Качества хранят объект **текстом**: `project_canonical_key` (29 упоминаний в 018), название, `"projectId"` узла локаций; подрядчика — `contractor_canonical_key` / `contractor_name`. Видимость — `quality.row_visible(...)` сравнивает очищенные строки (`quality.object_clean`, 033) и признаки `core.role_assignments.quality_object_keys` (ТД №191 — производный кэш; №193 — переименование без синонима отрывает записи; №197 — `"projectId"` на чужой узел).
- Подрядчики: справочник Качества заполняется из `core.counterparties`; связь «ключ Качества ↔ контрагент» — `quality.contractor_core_links` (018e, 022, 024, 026). Правило «только своя фирма» — `quality.contractor_only`, `contractor_ref` — по ключу/названию.
- **Подтверждено Исполнителем (этап 1, 25.10.2026):** главный список — `core.projects` (`planfact.projects` перенесена в `core`, 016). У RBI в ядре один объект-контейнер «Объекты RBI»; 13 ЖК — только в `quality.project_objects`, их `core_project_id` = контейнер (ставит `bind_company` из `project_code`). Отсюда решения 4–7.
- Старое Качество (`js/`) на устройствах пишет текст (ключ, название) — сервер должен сам дописывать id (переходно, ADR-070 п. 4).

## 3. Объём реализации

1. У записей Качества — **id объекта** (`core_object_id` → `core.projects`, объект ЖК; решение 4) и **id контрагента**; заполняет сервер (триггер) из текста по справочнику и синонимам при записи старым и новым клиентом; разовое заполнение существующих.
2. `row_visible` и правила «закреплённые объекты» / «только своя фирма» — **по id**; текст — только запасной путь для «не разобрано» (ТД №191, №193, №197 закрыть).
3. Один список объектов: `quality.project_objects` — дополнение к объекту ядра (`core_object_id` обязателен); объект, созданный в Качестве, создаётся в ядре, и наоборот (в т. ч. у компании без контейнера); разовая склейка дублей; контейнер «Объекты RBI» скрыт из списков объектов (решение 6).
4. «Не разобрано»: администратору компании — список записей без узнанного объекта/подрядчика с кнопкой «привязать к …» (существующий экран справочника Качества/очереди нормализации — расширить, не новый раздел).
5. Перенос РБИ (`docs/RBI_TRANSFER.md`, функции `quality.rbi_transfer_*`) заполняет id при финальном переносе.

## 3а. Reuse / единый источник истины

- **Владелец объектов** — ядро (ADR-066); Качество — потребитель. **Владелец контрагентов** — `core.counterparties` (ADR-068). REUSE: `quality.contractor_core_links`, `quality.object_aliases`, `quality.object_clean`, очередь нормализации, экран «Объекты и планы» Качества (при почте — только `*.objects.manage`).
- EXTEND: `quality.row_visible`, `contractor_only`/`contractor_ref`, `rbi_transfer_*`. NEW: только колонки id и триггер дозаполнения, при необходимости — представление «не разобрано».
- Новых ключей по имени не заводить (ADR-070 п. 4, правило ревью).
- UI: подвкладки как в Quality, телефон и ПК сразу, токены дизайн-системы.

## 5. Запреты и границы

- Не делать: экраны Качества, пишущие `core_object_id` сами (отдельный блок после P2-0032, решение 7); удаление/архив контейнера; люди по id, рейтинг, задачи, очки, ТД №189 (это P2-0035b); перестройку «Настроек» (P2-0038); день переключения (P2-0032).
- Не удалять текстовые колонки объекта/подрядчика (старый клиент их пишет); не менять общие настройки Auth/JWT (ADR-061/061a).
- `rbi-q-main/` и production RBI — только чтение.
- Имена при узнавании не угадывать по похожести — только точное совпадение очищенной строки или синоним; остальное — «не разобрано».

## 6. Критерии приёмки

- [ ] Переименование объекта и подрядчика не меняет видимость записей (тест + сценарий на сервере).
- [ ] Один список объектов: создали в одном месте — есть везде, дублей нет.
- [ ] «Не разобрано» видно администратору, привязка работает; нераспознанное не теряется.
- [ ] Чужая компания и чужая фирма подрядчика по-прежнему не видны (негативные тесты).
- [ ] Старый клиент `js/` продолжает работать (пишет текст — сервер дописывает id).
- [ ] Пробный перенос РБИ заполняет id; сверка видимости по 17 — 0 расхождений.
- [ ] Контейнер «Объекты RBI» не виден в списках объектов; `core_project_id`/`project_code` записей не изменились.
- [ ] У новой компании без контейнера объект, созданный в Качестве, появляется в «Компании», и наоборот (тест).

## 8. Риски

- Текст записей не совпадает со справочником (опечатки, старые названия) → «не разобрано», число в отчёте до применения на сервер.
- Склейка дублей объектов меняет закрепления (`quality_objects`) → пересчитать закрепления в той же миграции, сверка по 17.
- Скорость правил при новых колонках → индексы по id, замер.
- Откат: `039_down` возвращает текстовые правила 033; колонки id не мешают старому клиенту.
