## 1. Цель

Качество → Аналитика → История → «Отчеты»: вместо ряда фильтр-кнопок типов отчёты разложены по **раскрывающимся группам типов** («Сводный отчёт», «Плакат качества», «Акт-эталон», «One-Pager», «Отчёт по объекту», …, «Прочее» — последней), как группы в подвкладке «Проверки». И на ПК, и на телефоне. Тип у старых и перенесённых отчётов определяется одинаково на обоих видах — «Прочее» остаётся только для действительно нераспознанных.

## 2. Подтверждённое исходное состояние

- ПК: `js/modules/quality/features/analytics/history.desktop.content.js` → `paintDeskReports()` (≈стр. 449): слева колонка объектов (`buildObjectRailHtml`), справа чипы типов (`_deskReportsDocKind`, `data-ana-desk-doc-kind`) + плоский список `reportFileCard`. Тип — `reportDocKind()` (стр. ≈102): `r.doc_kind`, иначе угадывание по названию — **5 типов** (Плакат / One-Pager / День качества / Сводный / Прочее).
- Телефон: `js/modules/quality/features/analytics/analytics.render.js` → список отчётов (≈стр. 3870–3965): аккордеоны по объекту (`metadata.project`) + чипы `_renderReportsDocKindChips`; тип — `_reportDocKind()` / `_classifyDocKindFallback()` (стр. ≈629) — **≈15 типов**, другие правила, чем на ПК (One-Pager на телефоне → «Сводный»/«Прочее»).
- Запись типа при сохранении: `reports/reports.actions.js` `classifyDocKind()` (стр. ≈1130) и `reports/reports.pptx-export.js` `_docKindFromTitle()` (стр. 240: «Отчёт по объекту 2.0», «One-Pager 4.0», …), `practice.pptx-export.js` («Лучшая практика»). Три копии правил — расходятся.
- Образец групп: «Проверки» — ПК `groupHtml()` / `_deskChecksOpen` (стр. ≈359), классы `ana-desk-hist-grp*`; телефон — аккордеоны `history.render.js`; группировка — `history/history.group.js`.
- Отчёты РБИ после P2-0036 пришли с `doc_kind` из старой системы или без него — **распределение по типам не подтверждено** (этап 1).

## 2а. Решения владельца (кнопки, 25.10.2026)

1. «Эталоны» = **акты-эталоны** (сохранённые PDF «Акт-Эталон …») — своя группа «Акт-эталон». Карточки эталонов Библиотеки в «Отчёты» не тянуть.
2. **Объекты остаются**: ПК — колонка объектов слева, справа группы типов; телефон — объект → внутри группы типов. Подрядчика/вида работ в отчётах нет («только по типам»).
3. Порядок групп — **по количеству** (больше — выше), «Прочее» всегда последней.
4. Фильтр-кнопки типов **убрать** — группы их заменяют.
5. Место в очереди — **сразу после P2-0036**.

## 3. Объём реализации

1. Один общий модуль правил типа отчёта (например `js/modules/quality/features/reports/report-kind.js`): `reportKindOf(r)` — сохранённый `doc_kind` в приоритете (кроме пустого/«Прочее» — тогда по названию), варианты сводятся к одному названию группы (`One-Pager 4.0` → «One-Pager», `Отчёт по объекту 2.0` → «Отчёт по объекту», `Акт-Эталон` → «Акт-эталон» и т. п.); `orderKindGroups(counts)` — по количеству, «Прочее» последней. Его используют ПК, телефон и запись при сохранении (`classifyDocKind`, `_docKindFromTitle`) — копии удалить.
2. ПК: в `paintDeskReports()` справа вместо чипов и плоского списка — группы типов (строка-группа как в «Проверках»: название, «N шт», раскрыть/свернуть, галочка «отметить группу»); внутри — те же `reportFileCard`, свежие сверху. «Все объекты» — тоже только группы типов (объект — строкой в карточке, как сейчас).
3. Телефон: аккордеон объекта → внутри подгруппы типов (второй уровень, как Объект → Подрядчик в «Проверках»); «Показать ещё» — внутри подгруппы. Чипы убрать.
4. Раскрытые группы запоминаются до перерисовки (как `_deskChecksOpen` / `_captureExpandedReports`); по умолчанию свёрнуты, кроме случая «группа одна» — раскрыта.
5. Сохранить: «Выбрать всё», «Удалить выбранные», меню «⋮», открытие отчёта, вид «карточки/список» на телефоне, верхние фильтры истории (объект, период, автор).
6. Тексты — через `_t(...)` с ключами `quality.history.report.kind_*` (недостающие добавить по образцу существующих).

## 3а. Reuse и единый источник истины

- **Найдено:** `groupHtml()`/`ana-desk-hist-grp*` (ПК), аккордеон объектов отчётов и `_captureExpandedReports` (телефон), `history.group.js`, `reportFileCard`, `_renderReportCard`.
- **Решение:** EXTRACT правил типа в один модуль (сейчас 4 копии) + REUSE разметки/стилей групп «Проверок». Новых стилей — минимум, только если вложенный уровень на телефоне требует отступа.
- **Совместимость:** поле `doc_kind` в базе не меняется и не мигрируется; новые отчёты продолжают его записывать (то же значение, что покажет группа).
- **UI:** светлая/тёмная тема, ширина телефона 375 px, ПК ≥ 1280 px; без горизонтальной прокрутки.

## 7. План тестирования

- **Команды:** `npm test`, `npm run check:ts`.
- **Сценарий:** RBI (339 видимых) → ПК: «Все объекты» → группы; выбрать объект → группы этого объекта; телефон — то же.
- **Отрицательные:** отчёт без `doc_kind` и с нераспознанным названием → «Прочее»; объект без отчётов → прежнее пустое состояние.
- **Регрессия:** «Проверки» (группы, сортировка), удаление отчётов, синхронизация списка.

## 8. Риски

- Названия старых отчётов РБИ разнообразнее правил → много «Прочего». Мера: этап 1 — замер и вопрос владельцу до вёрстки.
- Удаление копий правил затрагивает сохранение отчётов. Мера: тест на все варианты названий из старых копий; значение `doc_kind` для новых отчётов то же.
