## 1. Цель

Ответственный в компании сам заводит проект и строит его структуру без программиста: создаёт проект, добавляет корпуса/секции/этажи/квартиры вручную или генератором «N секций × M этажей × K квартир», видит справочник единиц измерения и может добавить свою. Чужая компания ничего из этого не видит. Это база для импорта ВОР (P2-0006): каждая позиция будет ссылаться на `location_id` и `unit_id`.

## 2. Подтверждённое исходное состояние (main `6a669da`)

- `planfact.projects` (001): только `id, company_id, name, created_at`; создать проект можно только SQL-скриптом, экрана нет. Чтение — `public.pf_my_projects()`.
- Права: `permission_catalog` (002/004), шаблоны ролей (9, коды `company_admin`, `project_manager`, `pto`, `foreman`, …), копии в `company_roles` при создании компании (триггер в 002). Проверка — только `planfact.has_permission` / `has_company_permission`.
- Раздел «Компания» — `src/platform/company/CompanyApp.ts`, вкладки «Роли» / «Сотрудники» / «Журнал» (P2-0004b). Аудит — `planfact.audit_log`, `pf_list_audit`.
- Существующий `src/services/locations/` (`LocationsService`, `types.ts`: `NodeType = object|building|section|floor|apartment`, строгий `CHILD_OF`) — офлайн-сервис Quality/Construction на старой таблице `location_nodes` общего сервера (production Quality, трогать нельзя по ADR-061).
- Справочника единиц измерения нет.

## 3. Объём реализации

1. **Миграция 006** (только `planfact.*` и `public.pf_*`, есть `006_down.sql`):
   - `projects`: + `code` (необязательно), `archived_at`; правка через функции.
   - `planfact.locations`: `id, company_id, project_id, parent_id (null = корень проекта), node_type (building|section|floor|apartment|other), name, sort_order, area (необязательно), canonical_key, created_at, deleted_at`; составной FK на `projects(id, company_id)`; родитель — того же проекта; глубина ≤ 6. Удаление — мягкое (`deleted_at`), запрет удалять узел с живыми потомками без явного «удалить ветку».
   - `planfact.units`: `id, company_id (null = общий), code, name, deleted_at`; уникальность `(coalesce(company_id), lower(code))`; базовые: м², м³, м.п., шт., компл., т, кг, л, чел.-ч.
   - Новые действия в каталоге: `planfact.projects.manage` (проекты и локации), `planfact.units.manage`. Шаблоны: `company_admin`, `project_manager`, `pto` получают оба. **Дозаполнить** этими действиями уже существующие `company_roles`, созданные из этих шаблонов (иначе у текущих компаний права не появятся).
   - RLS: чтение локаций — кто видит проект; ЕИ — общие всем вошедшим, свои — только своей компании. Запись — только через `public.pf_*` (security definer, проверка права внутри, `search_path` фиксирован).
   - Функции: `pf_create_project`, `pf_update_project`, `pf_list_locations(project)`, `pf_add_location`, `pf_rename_location`, `pf_move_location` (в пределах проекта, без циклов), `pf_delete_location`, `pf_generate_building(project, parent, name, sections, floors, apartments_per_floor, first_floor)` — одна транзакция, лимит ≤ 5 000 узлов за вызов, нумерация квартир сквозная по корпусу; `pf_list_units`, `pf_add_unit`, `pf_delete_unit` (только свои). Все изменения пишутся в `audit_log`.
2. **Клиент:** вкладки «Проекты» и «Единицы» в разделе «Компания».
   - «Проекты»: список, создать, переименовать, архивировать; открыть проект → дерево локаций (раскрытие, добавить дочерний узел с подсказкой следующего уровня, переименовать, удалить, кнопка «Сгенерировать корпус» с предпросмотром «будет создано N узлов»).
   - «Единицы»: общий список (только чтение) + свои (добавить/удалить).
   - Без права `*.manage` — те же экраны только на чтение, кнопок нет.
3. Тесты, документы (`docs/APP_GUIDE.md`, `standards/AUTH_AND_ACCESS.md` — новые действия, `FILE_MAP.md`, `docs/SERVERS.md` — миграция 006), отчёт.

## 3а. Обязательная проверка повторного использования (reuse review)

- **Найдено:** `src/services/locations/types.ts` (словарь уровней), `locations.service.ts` (офлайн, `location_nodes` Quality); UI-компоненты и стили раздела «Компания» (P2-0004b); `audit_log` + `pf_list_audit`; `has_permission`.
- **Решение:** словарь уровней — **REUSE** (`NodeType` и подписи берутся из `services/locations/types.ts`; добавить `other` и мягкую подсказку вместо строгого `CHILD_OF` — **EXTEND**, не ломая Quality-потребителей). Хранение — **NEW** `planfact.locations`: таблицу `location_nodes` Quality менять/использовать нельзя (ADR-061). Мост к `location_nodes` — не делать, записать в техдолг как будущую задачу объединения при переезде на свой сервер (ADR-061a).
- **UI:** вкладки, таблицы, кнопки, состояния «загрузка/пусто/ошибка/нет прав» — как в `CompanyRoles.ts` / `CompanyMembers.ts`; светлая и тёмная тема.
- **Совместимость:** `pf_my_projects`, `pf_list_works`, модуль План/Факт и экраны P2-0004b не ломаются; unit-тесты `services/locations` проходят без изменений ожиданий.

## 3а. Единый источник истины

- **Владелец данных:** платформа (схема `planfact` до ADR-061a). Проект, локация, ЕИ — один экземпляр, модули ссылаются по `id`.
- **Где меняется:** только функции `public.pf_*` из миграции 006; клиент таблицы напрямую не пишет.
