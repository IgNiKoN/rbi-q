# P2-0035b — Качество: люди по номеру учётки (профиль, рейтинг, очки, «мои задачи») + защита от «чужой почты» (ТД №189)

**Источник:** ADR-070 «сначала id, потом имя» (`standards/DECISIONS_2026-10-20.md:268`); `tasks/P2-0035.md` решение 1; ТД №189 (условие приёмки P2-0028 — до второй независимой компании)  
**Предшествующая принятая задача:** P2-0041

**Решения владельца (26.10.2026, кнопки):**
1. Один блок P2-0035b: «люди по номеру учётки»; защита от «чужой почты» — его этап, отдельного блока нет («дешёвая страховка»).
2. Старые записи (проверки, задачи, черновики, профили, рейтинги) **привязать к учёткам один раз** по ФИО; спорные (однофамильцы, уволенные, не найденные) — **списком владельцу, не угадывать**.
3. Чужая почта: компания Б добавляет почту, учётку на которую создала другая компания, → **старый пароль перестаёт действовать**, все входы закрываются, Б получает новый временный пароль; дальше ни одна компания не сбрасывает этой учётке пароль (учётка личная).
4. Вторая независимая компания — **в ближайшие недели**: блок — следующий.
6. **Текущие рейтинги, очки и привязки не должны слететь** (вопрос владельца 26.10.2026): перед записью на сервер — копия профилей, рейтингов, очков (таблица-снимок `quality.p2_0035b_backup_*` или выгрузка); сверка «до/после» по каждому сотруднику — стоп-условие этапов 1–4.
5. **Профиль, рейтинг, очки — один на человека в компании** (не по объекту); человек в двух компаниях — по профилю в каждой, очки не смешиваются (владелец 26.10.2026: «зачем профиль по каждому объекту?»).

**Исключение из BLOCK_SIZING:** две CRITICAL-зоны (миграции данных Качества + вход/учётки) — по решению владельца №1; этапы разведены, у каждого своя проверка.

## 1. Цель

Качество узнаёт человека по номеру учётки (`auth.users.id`), а не по строке «объект + ФИО». Переименование сотрудника, однофамильцы и уволенные больше не теряют и не путают профиль, рейтинг, журнал очков и «мои задачи». Учётку, созданную одной компанией, нельзя использовать, чтобы войти в другую.

## 3. Объём реализации

1. **Разовая привязка старых записей** к учёткам (миграция `040a`): по ФИО и синонимам (`core.staff_name_aliases`) в пределах компании → `auth_user_id`/`created_by_auth_user_id`/`assigned_to_auth_user_id`/`owner_auth_user_id`. Сначала **пробный прогон** (отчёт без записи): «таблица · найдено · спорно · не найдено» + список спорных строк — владельцу; запись — после его «да».
2. **Сервер по id** (`040b`): **один профиль и один рейтинг на человека в компании** — уникальность `(core_company_id, auth_user_id)` (у профиля индекс уже есть — `018:1224`; рейтингу — добавить), не по объекту (решение №5) (старые ключи по имени — не уникальные, остаются подписью/переходом); сервер сам ставит `auth_user_id` автора из токена при записи профиля, рейтинга, проверки, задачи, черновика (клиенту не доверять); «назначен» задачи — по `assigned_to_auth_user_id`. Права и «свои» в RLS/функциях — по id.
3. **Клиент Качества по id:** профиль, рейтинг, журнал очков, «мои задачи», черновики, «свои» проверки — поиск и запись по номеру учётки; upsert профиля/рейтинга — по новому ключу; `canDelete` и админ пользователей — по id; ФИО — только подпись (ведёт ядро). Поле «имя» в форме Качества при входе по почте — только показ (меняют в «Настройки → Моё»).
4. **ТД №189 п. 2–3:** `rbi_transfer_attach_profiles` склеивает дубли только по `auth_user_id`; `staff_rename_quality` меняет только подписи строк этой учётки (по id), однофамильцев не трогает.
5. **Чужая почта (ТД №189 п. 1):** `pf_company_add_member` — существующая учётка, у которой `managed_company_id` задан и ≠ этой компании → закрыть все сессии, новый временный пароль (обязательная смена при входе), `managed_company_id := null`; запись в журнал обеих компаний. Экран «Компания → Сотрудники»: временный пароль показывается с пояснением «учётку создала другая компания — прежний пароль больше не действует».

## 6. Критерии приёмки

- [ ] **Сверка «до/после» по каждому из 17 сотрудников RBI:** число записей очков, рейтинг, число профилей, задач и проверок за автором — совпадают (например, у владельца 847 записей очков, рейтинг 17 445); расхождение → откат `_down` и копия.

- [ ] Переименование сотрудника не меняет его профиль, рейтинг, очки, «Мои задачи» в Качестве.
- [ ] Два однофамильца на одном объекте — раздельные профили и рейтинги; склейка/переименование не трогает чужое.
- [ ] Старые записи RBI привязаны к учёткам; спорные — решены владельцем или оставлены «не разобрано» списком.
- [ ] Автора записи ставит сервер по токену; подмена `auth_user_id` в запросе не работает.
- [ ] Компания Б, добавляя почту, созданную компанией А, получает новый временный пароль; старый не входит; А не может сбросить пароль.
