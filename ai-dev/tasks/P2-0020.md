## 1. Цель

РП открывает «Факт → Ждёт подтверждения (N)», фильтрует по корпусу, работе, прорабу, бригаде и дате, отмечает 10 записей и одной кнопкой подтверждает (или отклоняет с одной причиной); в карточке записи — история позиции. ПТО / РП / прораб открывают «Факт → Журнал» — все записи факта объекта (кто, когда, сколько, статус) с фильтром по периоду и выгрузкой в Excel. «КС-2» — список актов объекта на реестре (статус, период, сумма, фильтры, выгрузка); открытие акта — как сейчас.

## 2. Подтверждённое исходное состояние (`main` `8c069b3`)

- Реестр оболочки — `src/platform/ui/registry/*` (P2-0019): таблица, чипы, «Фильтрация», «Выбрано: N», группы, колонки, виды + ссылка, Excel, `SideCard`/`Steps`/`HistoryFeed`; пример модуля — `vor/PositionsRegistry.ts`, `vor/PositionActions.ts`.
- Очередь РП: `pf_fact_pending(p_project)` (право `fact.approve`): позиция, место, работа, ЕИ, план, факт, объём, дата, бригада, пометка, исправление, автор; экран `fact/FactPending.ts` (по одной записи, `pf_fact_decide`); счётчик — внутренняя кнопка «Ждёт подтверждения» в `FactTab.ts`.
- Решение РП — `pf_fact_decide(p_entry, p_approve, p_note)` (009): права, «не ждёт подтверждения», причина отказа обязательна, замена исправляемой записи, журнал.
- Журнала факта по объекту на сервере **нет** (есть `pf_fact_history(p_position)` — по одной позиции).
- КС-2: `Ks2Api.acts(projectId)` → `Ks2ActItem` (номер, дата, период, статус, сумма, редакции, выдан / аннулирован); список — `ks2/Ks2Tab.ts` (`k2-list`).
- Подвкладки «Факта» — «Ввод», «Шахматка» (`FACT_SUBS` в `PlanfactApp.ts`).

## 3. Объём реализации

1. **Сервер (CRITICAL — факт и права):** миграция `028_fact_decide_batch_journal`:
   - `pf_fact_decide_batch(p_project, p_entries uuid[], p_approve boolean, p_note text)` — ≤ 500 записей, все — этого проекта и `pending_approval`, иначе отказ всей пачки; права, причина отказа, замена исправляемой, журнал — **как `pf_fact_decide` для каждой записи** (REUSE её тела через общую служебную функцию или вызов по записи внутри одной транзакции); возвращает `{approved, rejected}`.
   - `pf_fact_journal(p_project, p_from date, p_to date, p_limit int)` — только чтение, право `fact.view`: все записи факта объекта за период (по дате работ) — позиция, место, работа, ЕИ, объём, дата, бригада, люди, чел.-ч, пометка, статус, автор, решение РП, исправление; лимит (по умолчанию 2 000), сортировка — новые сверху.
   - Откат — `028_down`. Прежние функции — без изменений.
2. **«Ждёт подтверждения» на реестре** (`fact/`): подвкладка маршрута `#/planfact/fact/pending` вместо внутренней кнопки (видна при `fact.approve`), «Ждёт подтверждения (N)»; колонки (работа, место, объём / план / факт, дата, бригада, прораб, пометка, «через РП», исправление); фильтры — корпус, работа, прораб, бригада, дата; группы по корпусу; «Выбрано: N» → «Подтвердить» / «Отклонить» (одна причина, обязательна) → `pf_fact_decide_batch`, > 500 — частями; карточка — история позиции (`pf_fact_history`) и решение по одной записи (REUSE `FactPending`/`pf_fact_decide`).
3. **«Факт → Журнал»** (`#/planfact/fact/journal`, все с `fact.view`): реестр записей `pf_fact_journal`; период (по умолчанию 30 дней), фильтры — корпус, работа, бригада, автор, статус; статус — палитра реестра; выгрузка Excel; карточка — запись + история позиции.
4. **КС-2 — список актов на реестре** (`ks2/`): колонки (номер, дата, период, статус, сумма, редакции, выдал), фильтры — статус, год/месяц периода; выгрузка списка; нажатие — открывает акт как сейчас (`Ks2Act`). Суммы — без права `money.view` не показываются (как сейчас).
5. **Документы и версия:** APP_GUIDE, DESIGN_SYSTEM (если меняется компонент), SERVERS (028), CHANGELOG, «История обновлений», SW, FILE_MAP, TECH_DEBT.

**Вне блока:** реестр в Приёмке 2.0 / Качестве; «Требует моего участия» (1.10); общие виды компании; правило «Отклонено» (ТД №129) и перепроверка допуска при подтверждении (ТД №134) — вопросы владельцу при показе.
