## 1. Цель

Покупатель (любая компания), вошедший **почтой**, работает в **тех же экранах** Качества и Стройконтроля, что и отдел РБИ сейчас: объект выбирается из «Объектов» своей компании (ядро), записи и фото синхронизируются с сервером в **отдельное хранилище компании**, права — по ролям компании, другие компании ничего не видят. Старое приложение РБИ (вход по **PIN**, боевые таблицы) — **отдельно и без изменений**. В Платформе 2.0 — **один вход: почта** (+ демо без входа).

## 2. Подтверждённое исходное состояние (23.10.2026, только чтение, разбор кода)

- Старое Качество: данные на устройстве (IndexedDB) + синхронизация с **50 таблицами** `public` и **11 бакетами** Storage; разбиение — по `project_code` (текст) и PIN-профилю `rbi_engineer_profiles`. Понятия «компания» нет.
- Синхронизация: один глобальный клиент `window.supabaseClient` (`js/services/sync/sync-auth.js:129`, `APP_CONFIG.SUPABASE_URL`), конфигурация `window.syncConfig` (код проекта — только из формы PIN, `sync-connection.actions.js:609`); имена таблиц зашиты строками в 16 файлах (~45 вызовов в `sync-engine.core.js`, 4 382 строки), соответствия «тип → таблица» — `sync-push-pull.core.js:55, 421`; пути файлов — `${projectCode}/…` или `hashed_assets/…`.
- Режим входа известен во время работы: `RBI.platform2.getState().mode` ∈ `email | pin | demo | none` (`src/platform/auth/platform.service.ts:105`), обёртка `RBI.services.shell.platformEntryMode()`; при почте старое Качество сейчас скрыто (`app-shell.js:69`).
- Сборка «разработка» (GitHub Pages / localhost) **намеренно** не синхронизирует PIN-Качество с боевой базой; сборка «выпуск» — синхронизирует (P2-0013, проверено владельцем).
- Схемы `planfact`, `core` в API не открыты (ADR-061 п.2); RLS — deny-by-default; общие настройки Auth/JWT не трогаем.

## 3. Объём реализации (ADR-068)

1. **Хранилище `quality`** (миграция `018_quality`): все 50 таблиц — **та же структура** (колонки, типы, значения по умолчанию, ключи, индексы), что у `public.<таблица>` на сервере (снимок только чтением), **без** политик и триггеров РБИ; + `company_id uuid not null` (FK `core.companies`) и для проектных таблиц — `core_project_id uuid` (FK `core.projects`, та же компания); `project_code` при почтовом входе = `id` объекта ядра (текст). Компания записи: проектные — из объекта; прочие — из заголовка запроса «текущая компания» (`quality.request_company()` — только если пользователь в ней состоит), иначе отказ. RLS **на каждой** таблице: участник компании с правом модуля (`quality.*` / `construction.*`), запись — с правом записи; anon — ничего. Таблицы классифицируются: проектные / компании / общие справочники компании — список в миграции, неклассифицированная таблица — стоп.
2. **Раздел `quality` открыт для API** (настройка PostgREST сервера; по разрешению владельца на шаг): клиенту видны только таблицы `quality` под RLS. `planfact`, `core`, `public` — как были.
3. **Синхронизация Качества в Платформе 2.0 — только в `quality`**; экран входа Платформы 2.0 — «Почта и пароль» и «Посмотреть без входа (демо)», вариант «Имя, код проекта и PIN» убирается (как и переключатель сборки «выпуск» P2-0013 — по факту не используется). Детали: клиент синхронизации = клиент платформы со схемой `quality` и заголовком текущей компании; код проекта = выбранный объект ядра (список — `fetchMyProjects`); имя инженера — из учётки; формы PIN нет; локальная база на устройстве — отдельная на компанию (не смешивается с PIN-данными); меню — «Качество» и «Стройконтроль», если модуль включён компании (`module_catalog`: `quality`, `construction` становятся управляемыми). Старое приложение РБИ — отдельный код (`rbi-q-main`), в этом репозитории не меняется.
4. **Роли:** действия `quality.*`, `construction.*` в каталоге прав и шаблонах ролей (технадзор, прораб, руководитель, подрядчик, …); при почтовом входе роль экрана Качества (гость / инженер / руководитель …) берётся из прав компании (`pf_my_permissions`), не из `rbi_engineer_profiles`.
5. **Файлы:** 11 приватных бакетов хранилища компаний (имена — с префиксом, путь начинается с `company_id`), правила Storage: читать/писать — участник компании с правом модуля; при почтовом входе — соответствие «бакет РБИ → бакет компаний» в одном месте.
6. **Справочники из ядра:** объект — только из ядра (обязательно); подрядчики Качества при почтовом входе = контрагенты ядра вида «подрядчик» (представление / запись через ядро); дерево этажей и планы Качества — в `quality` со ссылкой на объект ядра (связь с `core.locations` — ТД, следующий блок).
7. Этап 0: ТД №104–106 (ревью P2-0015).
