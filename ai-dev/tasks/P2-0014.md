## 1. Цель

Покупатель План/Факта входит почтой на тот же сервер, что и отдел РБИ. После блока его учётка **не может** ни прочитать, ни изменить осмотры, СК, дефекты, приёмки, задачи, профили и фото Качества — даже в обход экранов. Сотрудники РБИ по PIN работают как раньше и ничего не замечают.

## 3. Объём реализации

1. **Аудит (только чтение):** по каждой таблице/бакету из списка — политики, роли, `anon`/`authenticated`; учётки Auth — **только счётчики** по типам (PIN-технические `@rbi-quality.local` / прочие), без имён и почт; есть ли не-PIN учётки, которые законно работают в старом Quality (например, админ по почте в старом приложении).

Существующие политики, функции, данные **не меняются** (ADR-067); откат — `015_down` удаляет только добавленное.
3. Проверочный скрипт `tests/server/015_rbi_guard.mjs`: почтовая учётка Демо-компании → select 0 строк / insert-update-delete отказ по каждой таблице и бакету; техническая PIN-учётка тестового проекта `TEST-P2` → чтение и запись как раньше.
