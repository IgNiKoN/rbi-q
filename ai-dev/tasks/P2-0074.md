## 1. Цель

Человек при первом входе видит короткое анимированное приветствие с именем и плитками разделов, которые ему доступны. В каждой плитке — одна строка «что тут делают», нажатие ведёт в раздел. При следующих входах приложение открывает последний раздел, где он был. Если последнего раздела нет (новый телефон, очистили данные), открывается раздел по его роли; если ролей несколько или роль руководителя — приветствие с плитками, но без анимации.

**Что увидит владелец:** «войдите новым сотрудником (или очистите данные сайта) → приветствие "Добро пожаловать, …" с плитками Качество / Стройконтроль / План/Факт (только доступные); нажмите "Качество" → откроется Осмотр. Закройте и откройте приложение → сразу Осмотр. Инженер СК без последнего раздела попадает в Стройконтроль, ПТО — в План/Факт».

## 2. Подтверждённое исходное состояние (Архитектор, 30.10.2026, `main` `eefedc7`)

  - `js/core/router.js:306–313` — пустой адрес → `rbi_last_module_hash` или `#/quality/audit`;
  - `src/platform/auth/entry.ts:124` → `homePathFor()` (`platform.service.ts:180`) — после входа почтой: последний модуль, если доступен, иначе `#/planfact`, без него — `#/settings`. Отсюда «по умолчанию План/Факт».
- Последний раздел пишет `router._rememberModuleHash` в `localStorage` (`rbi_last_module_hash`, без Настроек), на устройство, не на учётку.
- Доступные модули — `PlatformAccess` (`planfact`, `quality`, `construction`, `company`) и «Доступ к модулю» по роли (P2-0071); действия роли — `core.my_grants`.
- Обучение уже есть: «Настройки → Помощь и о программе → обучение» (`js/modules/settings/features/tutorial.js`).

## 3. Объём реализации

1. **Одно правило «куда вести»** — функция в `platform.service.ts` (расширить `homePathFor`), её вызывают и вход (`entry.ts`), и роутер (`router.js`, пустой адрес). Второго правила в коде не остаётся. Порядок:
   1) приветствия у этой учётки на этом устройстве ещё не было → приветствие (с анимацией);
   2) есть последний раздел, и он доступен → он;
   3) раздел по роли: из действий человека (`my_grants` / `PlatformAccess`) — есть действия Качества «проведение проверок» → `#/quality/audit`; иначе действия Стройконтроля → его первый экран; иначе План/Факт → `#/planfact`; несколько равных (руководитель, администратор) или ни одного → приветствие с плитками без анимации; без модулей → «Настройки».
   Признак «приветствие было» — в `localStorage` с id учётки (на новом телефоне приветствие покажется снова — это нормально; сервер не трогаем, миграции нет).
2. **Экран приветствия** (`#/welcome`, платформа, не модуль): «Добро пожаловать, <имя>», компания; плитки только доступных разделов (по `PlatformAccess` и «Доступ к модулю»): название, значок, одна строка «что тут делают» (тексты — из манифестов модулей, не в коде экрана); снизу ссылка «Как тут всё устроено — обучение» (существующее обучение) и «Настройки». Анимация — CSS (появление, лёгкий сдвиг плиток по очереди, ≤ 1,2 с), без библиотек; `prefers-reduced-motion` — без анимации; второй и последующие показы — без анимации. Телефон 375 и ПК 1440, светлая и тёмная тема, палитра приложения.
3. **Плитка → раздел**: нажатие ведёт на первый экран модуля и запоминает его как последний.
4. **Документы:** `APP_GUIDE` (первый экран), CHANGELOG, FILE_MAP, `reports/P2-0074/`.

**Вне блока:** «Что нового» на приветствии; выбор стартового раздела в настройках пользователя (если понадобится — отдельно); серверный признак «приветствие было» для всех устройств.
