## 1. Цель

ПТО получает от девелопера исправленную ВОР. В проекте → «ВОР» нажимает «Загрузить новую редакцию», выбирает файл. Видит, что изменилось: добавлено / удалено / изменился объём / без изменений; спорные 🟡, конфликты с фактом 🔴. Нажимает «Принять редакцию» — связки и факт по совпавшим строкам переходят сами, сводка, шахматка и КС-2 считают от новой редакции. Старая редакция не меняется и открывается из истории.

## 2. Подтверждённое исходное состояние

## 3. Объём

1. **Редакция в данных (`046`):** у загрузки — ссылка на предыдущую редакцию, номер редакции, признак «действующая» (одна на цепочку). Старая редакция при принятии новой становится «заменена», её строки и файл не меняются.
2. **Позиция переживает редакцию.** Рекомендуемая модель (Исполнитель может предложить лучше, но с теми же свойствами): совпавшая позиция остаётся той же записью (тот же `id`), поэтому факт на ней не переносится и не переписывается. Новые строки заказчика связываются с ней новыми связками; изменение объёма — событие «объём изменён в редакции №N: было → стало» (не перезапись без следа). Снятая позиция — мягко «снята в редакции №N», не удаляется; если на ней есть факт — 🔴.
3. **Сопоставление строк** (чистая функция, без сервера): ключ «нормализованное название + ЕИ + место» (место — из контекста секция/этаж/кв.); дубли и близкие названия — 🟡; номер строки — подсказка, не ключ. Результат — 4 группы + 🟡 + 🔴.
4. **Принятие** — одна функция на сервере, всё или ничего: проверка, что сравнение сделано с действующей редакцией (иначе отказ «редакция уже сменилась»), что 🟡 решены, перенос, смена «действующей», запись в журнал.
5. **Все потребители позиций** (сводка, шахматка, факт, КС-2, входящие, «Требует внимания») считают только позиции действующей редакции, снятые — не считают в план, но их факт виден с 🔴.
6. **Экраны:** «ВОР» → «Загрузить новую редакцию» → экран сравнения (фильтры по группам, счётчики, у 🔴 — действие «перенести факт на позицию…» / «оставить») → «Принять редакцию». История редакций с номером, датой, автором; старую — открыть только для просмотра. Три размера (ПК, планшет, iPhone 7), обе темы.
7. **Ошибки с номером строки** (PTO-01): после разбора любой загрузки (первой и новой редакции) — список «строка 57: нет ЕИ», «строка 112: объём 0 или пусто», «строка 140: место не найдено», «сумма позиций ≠ объёму строки»; переход к строке по клику; выгрузка списка не нужна.

## 3в. Связь с каталогом модулей (`reference/MODULES.md`)

- **Модуль:** «Сметы и КС-2» (5.1.1), сторона — подрядчик (ВОР получаем от заказчика). **Ядро читает:** проект, объекты и места (`core.locations`), виды работ, единицы. ## 6. Критерии приёмки

- [ ] Новая редакция загружается к существующей ВОР; экран сравнения показывает 4 группы, 🟡 и 🔴 со счётчиками.
- [ ] Сдвиг нумерации и вставка строки у заказчика не превращают совпавшие строки в «удалено + добавлено».
- [ ] «Принять» недоступно, пока есть нерешённые 🟡; принятие по устаревшему сравнению — отказ.
- [ ] После принятия факт на совпавших позициях тот же (те же записи); сводка, шахматка, КС-2 — по новой редакции, без двойного счёта.
- [ ] Снятая позиция с фактом — 🔴, факт не потерян; ПТО может перенести факт на другую позицию (новой записью, старая — `superseded`, как сейчас) или оставить.
- [ ] Старая редакция открывается только для просмотра; история — номер, дата, автор.
- [ ] После любой загрузки — список ошибок с номером строки и причиной, клик ведёт к строке.
- [ ] Чужая компания не видит и не принимает редакции (тест).
- [ ] Существующие ВОР на сервере после `046` — редакция №1, действующая; цифры сводки «до / после» совпадают.
