## 1. Цель

У каждой записи Качества, Стройконтроля в Качестве и внешнего СК появляется устойчивый `uuid`. Новые записи получают его на телефоне, старые — на сервере рядом со старым номером. Связи между записями дублируются по `uuid`. Старый текстовый номер пока остаётся ключом синхронизации. Его снимет «Уборка» (P2-0063). Ничего не переименовываем, данные не теряем, дублей при повторной отправке нет.

**Что увидит владелец:** «откройте светофор таблиц (`npm run test:schema` → `inventory.html`) → у 41 таблицы Качества "Ключ" жёлтый (мост), красных на 41 + 2 меньше; правило "валюта у сметы" проверяется; на телефоне проведите проверку с фото без сети, включите сеть → проверка на сервере одна, у неё и пунктов — новый номер; старые проверки и задачи открываются и правятся как раньше».

## 3. Объём реализации

1. **Сервис номеров платформы**: одна функция для нового номера (`uuid`) и одна для устойчивого (имя-основанный `uuid` v5 от «родитель + ключ»). Своих генераторов в модулях не остаётся. Сначала найти существующий (`crypto.randomUUID` уже есть в `contractor-directory.service.js`, План/Факт) и расширить его, без новой библиотеки. Для старых браузеров нужен запасной путь через `crypto.getRandomValues`.
2. **Телефон, проверка** (этап 1): новая проверка → `id` = `uuid` строкой. Пункт → `uuid` v5 от (проверка, пункт), фото → `uuid` v5 от (проверка, пункт, номер фото), черновик → `uuid` v5 от инспектора. Повторная отправка даёт тот же номер, значит дубля нет. Записи, созданные до обновления (в очереди без сети, на старой версии приложения), уходят со старыми номерами и принимаются.
3. **Миграция 054 (добавляющая) + `054_down`** для всех 41 таблиц:
   - рядом колонка `core_id uuid not null`, уникальная. Заполнение: если `id` уже имеет вид `uuid`, берётся он; у таблиц с `id uuid` — тот же `id`; у остальных — `gen_random_uuid()`;
   - триггер на вставку заполняет `core_id` по тому же правилу (серверные вставки, перенос 031, старые телефоны). На обновлении `core_id` не меняется: пустое значение → прежнее, другое → отказ с текстом. Если `id` имеет вид `uuid`, а `core_id` с ним не совпадает — отказ;
   - связи: рядом `core_<связь>_id uuid` (`core_inspection_id`, `core_report_id`, `core_parent_id` …), заполнение по совпадению текстовой ссылки в той же компании, триггер держит их в согласии. Внешний ключ — где ссылка всегда существует (решает Исполнитель по данным, без потери строк). Несовпавшие ссылки не стираются, а перечисляются в отчёте;
   - индексы, RLS и права не меняются; функции 053 не трогать.
4. **Телефон, остальное** (этап 3): все прочие генераторы Качества, СК 2.0 (`src/services/construction-*`), задач, совещаний, FMEA, эталонов, ТИВИ, отчётов, справочников, внешнего СК переходят на сервис из п. 1. Описания `sync` Качества получают `core_id`, телефон хранит его у загруженных записей. Отправка `core_id` не затирает: поле пустое → не отправлять.
5. **Сторож таблиц** (этап 4): 
   - мост «`id text` + `core_id uuid` рядом» → жёлтый с причиной, К1 / К6 → жёлтый; потолок `schema-debt.json` снижается (`--update-debt`);
   - **правило 10 «валюта у родителя»**: денежное поле в строке допустимо, если валюта есть у родителя (смета, КП, КС-2, прайс, договор, проект); без родителя с валютой → красный. Существующие нарушения попадают в потолок (шаг ПФ3 — P2-0065);
   - **заготовка «новая таблица модуля»**: SQL-шаблон с ключом `uuid`, компанией, проектом и местом, автором, временем, `deleted_at`, ссылками с внешними ключами и RLS в той же миграции, со ссылкой в `DATA_TABLES.md`. Проверка: шаблон, применённый в PGlite, проходит сторож зелёным.
6. **Документы:** `DATA_TABLES.md` (мост ключа, правило 10, заготовка), `MODULES.md` §5.2 (долг перед ядром: ключ `uuid` рядом, снятие — P2-0063), `migration-plan.md` (К1, К6 → «мост, 054»), `SYNC_AND_ACCESS.md` (сервис номеров), `TECH_DEBT.md` — мост с датой снятия (P2-0063: ключ синхронизации → `core_id`, `id text` — снимок), `docs/SERVERS.md` (054), CHANGELOG, FILE_MAP, `reports/P2-0072/release-plan.md`.

**Вне блока:** перевод ключа синхронизации и связей на телефоне на `core_id` и снятие `id text` (P2-0063 «Уборка»); `sk_*` по id ядра (4г); место проверки по id (К3).
