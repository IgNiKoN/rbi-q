## 1. Цель

Прораб с телефона открывает объект → корпус → этаж → видит работы этажа (позиции ВОР) с планом, накопленным фактом и %; вносит факт за дату с обязательной бригадой; может закрыть этаж/секцию целиком одной операцией с разложением остатков по позициям и правкой разбивки до отправки. Исправление факта — новой записью с причиной, старая видна в истории. Ввод сверх плана больше допуска (2 %) сохраняется, но в итог не входит, пока РП не подтвердит в списке «На подтверждение».

- Места: `planfact.locations` (`node_type` building/section/floor/apartment/other, `parent_id`, `depth`) — 006.

## 3. Объём реализации

1. **Миграция 009** (`009_up.sql` / `009_down.sql`, только `planfact.*` и `public.pf_*`):
   - `brigades` — справочник бригад компании: `name`, `leader_name`, `phone` (необязательно), `archived_at`; уникальность имени в компании.
   - `fact_entries` — запись факта: `company_id`, `project_id`, `position_id` (→ `vor_positions`), `brigade_id` (обязательно, PR-08), `work_date` (не в будущем), `qty > 0` в ЕИ позиции, `workers`, `man_hours` (необязательно), `note`, `status` (`accepted` | `pending_approval` | `rejected` | `superseded`), `corrects_id` (ссылка на исправляемую запись), `correction_reason`, `batch_id` (группа «закрыть этаж»), `created_by/at`, `decided_by/at`, `decision_note`.
   - Накопленный факт позиции = Σ `qty` записей `accepted` (единый источник; нигде не хранится отдельно; функция/представление `pf_fact_position_totals`).
   - Допуск перебора — колонка `projects.fact_tolerance_pct` (по умолчанию 2). Экран правки допуска — вне блока (техдолг).
   - Новые действия каталога: `planfact.fact.approve` (подтверждать/отклонять перебор, исправлять чужой факт) → шаблоны `company_admin`, `project_manager`; `planfact.brigades.manage` → `company_admin`, `project_manager`, `pto`. Дозаполнить роли из шаблонов (как в 007/008).
   - RLS: чтение факта — `planfact.fact.view` по проекту; бригады — члены компании; запись — только `pf_*` `security definer`, `company_id` из проекта, позиция/бригада/место проверяются на принадлежность; архивный проект — отказ. Записи факта не удаляются и не меняются, кроме перехода статуса через функции (триггер-сторож). Журнал `audit_log`.
2. **Ввод факта (PR-02, PR-03, PR-08):** экран «План/Факт → Факт», телефон в первую очередь: Объект → Корпус → (Секция) → Этаж → список работ (вид работ, ЕИ, план, факт, %, остаток) → форма «объём, дата (по умолчанию сегодня), бригада (последняя выбранная), люди, чел.-ч, примечание» → % пересчитан сразу. На ПК — тот же экран таблицей.
3. **Перебор плана:** если накопленный факт после записи > план × (1 + допуск) — запись `pending_approval`, прораб видит «Ждёт подтверждения РП». У РП: «Факт → На подтверждение» (счётчик), «Подтвердить» / «Отклонить» с комментарием.
4. **Исправление:** «Исправить» у своей записи (прораб) или любой (право `fact.approve`): новая запись с причиной, старая → `superseded`; «История» позиции показывает все записи, кто/когда/почему. Отмена = исправление на 0 → запись без объёма не создаётся, старая `superseded` с причиной.
5. **Закрыть этаж / секцию целиком (PR-01):** кнопка на уровне места → список всех позиций места и вложенных (квартиры) с остатками → по умолчанию объём = остаток каждой позиции (пропорционально «100 % этажа»; вариант «на X %» — та же пропорция от плана, с округлением до 3 знаков и досчётом в последней позиции) → прораб правит любую строку или снимает галочку → «Отправить» одной пачкой (`batch_id`), одна бригада и дата на пачку. Правило перебора применяется к каждой записи.
6. **Справочник бригад:** «Справочники → Бригады» (добавить, переименовать, в архив); прораб в форме выбирает из активных.
7. Документы и отчёт: `APP_GUIDE`, `AUTH_AND_ACCESS`, `FILE_MAP`, `TECH_DEBT`, `CHANGELOG`, `SERVERS` (009).
