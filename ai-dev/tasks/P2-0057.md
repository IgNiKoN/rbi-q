## 1. Цель (черновик)

PDF-план бросается на строку этажа или квартиры в «Компания → Объекты и места» (или в карточку места); несколько файлов, брошенных на объект, сопоставляются с этажами / квартирами по имени файла («Этаж 3.pdf», «3 этаж», «кв 45») с предпросмотром. План — запись ядра «документ места» (файл, версия, кто и когда загрузил); Качество и Стройконтроль (пины замечаний на плане) берут план из ядра.

## 2. Исходное состояние (проверено 28.10.2026)

- Планы этажей — `quality.construction_floors_v2` (`pdf_url`, `pdf_name`, офлайн-хранилище `CONST_FLOORS_V2`, синхронизация `sync-engine.core.js:1997, 3829`), квартир — `quality.construction_units_v2.pdf_url`; загрузка — `src/services/locations/locations.service.ts:uploadFloorPdf` и `construction-units.service.ts:uploadUnitPdf` в бакет `custom-assets` с **публичной ссылкой** (`getPublicUrl`); экран — старый справочник Качества `location-directory-ui.js:303-325`.
- Закрытые бакеты компаний есть только у Качества / СК (`018d`, `quality-*`, путь начинается с id компании).

## 3. Черновик этапов (уточнить с владельцем)

1. Сервер + Storage (самое рискованное): запись «документ места» в ядре, закрытый бакет ядра по компании, правила доступа (просмотр — участник проекта, загрузка — `places_manage`), перенос существующих планов РБИ (ссылки и файлы) без потери, тест PGlite + отпечаток Storage.
2. Макет (показ): перетаскивание на строку / объект, сопоставление по имени, карточка с планом (просмотр, заменить, снять, версии).
3. Экран «Объекты и места»: загрузка, замена, снятие, версии.
4. Качество и СК 2.0 читают план из ядра (пины на плане — на месте), старый путь загрузки в справочнике Качества убирается или ведёт в «Компанию».
