# P2-0034 — ИИ-помощник Качества по учётке: вход по почте + галочка в роли; вход «по имени» в старой функции закрыт

**Статус:** DONE · 25.10.2026 (принято владельцем, `reports/P2-0034/acceptance-record.md`; отчёт `reports/P2-0034/executor-1.md`; показ — владелец «всё работает»; старт — «Исполнитель.»; утверждена кнопками 25.10.2026; решения — ниже)
**Владелец продукта:** Igor (IgNiKoN)
**Репозиторий:** `platform-2-core`.
**Ветка:** `task/P2-0034-ai-by-account` от `main` **после влития P2-0033 и P2-0036** (порядок 0033 → 0036 → 0034 → 0031 → 0032 → 0035).
**Предшествующая задача:** P2-0036. **Основание:** ADR-070 п. 2, 5 («сначала id, потом имя»; внешние функции — по токену входа и правам компании); ТД №186, №187; диагноз — `ai-dev/reports/P2-0028/executor-1.md`, доработка 1, п. 1. ADR-061/061a.
**CRITICAL — одна зона: права (серверная проверка учётки и права роли).** Дополнительно — изменение объекта старого РБИ (функция `deepseek-proxy`) по прямому решению владельца (исключение из ADR-061 п. 1, см. §5).

**Решения владельца (25.10.2026, кнопки):**
1. Пользоваться помощником могут **только отмеченные роли** — новая галочка «ИИ-помощник» в конструкторе ролей.
2. Вход «по имени» в старой функции закрыть **сразу в этом блоке**, но **только его**: режимы «корпоративный пароль» и «свой ключ» в действующем РБИ продолжают работать. Перед изменением — копия старой функции для отката.
3. В настройках Платформы 2.0 остаются два способа: **«по учётке»** (по умолчанию) и **«свой ключ»** DeepSeek. «По роли» и «корпоративный пароль» убираются.
4. Учёт обращений и дневной предел — **не нужны**.
5. Как выкладывать функцию на сервер, владелец не знает — первым делом выяснить вместе с ним (этап 1).
6. Галочка по умолчанию — 4 ролям РБИ и ролям с `quality.edit` (владелец снимает лишние сам).
7. План — отдельным файлом `handoff/ARCHITECT_PLAN_P2-0034.md`; `LATEST_ARCHITECT_PLAN.md` остаётся у P2-0036 до её приёмки.

## 1. Цель

Сотрудник входит в Платформу 2.0 по почте, открывает Качество и нажимает любую кнопку ИИ (умный комментарий, отчёт, FMEA и т. п.) — получает ответ. Сервер решает по учётке из токена входа и галочке «ИИ-помощник» в её роли; без галочки — понятный отказ. Старая функция больше не отвечает тому, кто знает только имя инженера и код объекта.

## 3. Объём реализации

1. **Выкладка.** Вместе с владельцем выяснить доступ к функциям сервера (панель хостинга / SSH / Studio), записать в `docs/` пошаговую инструкцию выкладки и отката; снять копию старой `deepseek-proxy` в репозиторий (`supabase/functions/_legacy/deepseek-proxy/` — только как архив для отката).

4. **Приложение:** `callAI` — режим «по учётке» вызывает новую функцию через общий клиент сервера с токеном текущей сессии (не через `APP_CONFIG.SUPABASE_URL`); режим «свой ключ» — без изменений. Настройки: только «по учётке» / «свой ключ»; старые значения `role`/`corporate` у пользователей → «по учётке». Тексты отказов (`quality.ai.error.*`, `locales/`).
5. **Старая функция:** в `deepseek-proxy` убрать только режим «по имени» (ответ 403 «Режим отключён, войдите в Платформу 2.0»); режимы «корпоративный пароль» и «свой ключ» не трогать. Выкладка — по разрешению владельца в чате; откат — копия из п. 1.

## 3а. Reuse review

- **Найдено:** `callAI` (все вызовы ИИ идут через неё), `planfact.has_company_permission`, каталог прав и конструктор ролей (P2-0004b), общий клиент Supabase `src/platform/auth/*`.
- **Решение:** EXTEND `callAI` и каталог прав; NEW — серверная функция (сервер решает по токену — ADR-070 п. 5, браузер не может хранить ключ DeepSeek).
- **UI:** только блок «ИИ» в `settings.render.js` (существующие классы, тёмная тема, телефон 375 px); галочка в конструкторе ролей появляется сама из каталога прав — проверить, не верстать заново.
- **Совместимость:** все три потребителя `callAI` (ИИ, задачи, геймификация) — проверить по одному вызову; ответ функции — тот же формат `choices[0].message.content`.

## 3а. Единый источник истины

- **Кто может:** право `quality.ai` в роли компании — единственный источник; меняется в конструкторе ролей. Имя и код объекта нигде не участвуют.
- **Проверка централизованного изменения:** снять галочку у роли → у её сотрудника кнопки ИИ дают отказ без правки приложения.

## 5. Запреты и границы

- Боевой сервер: чтение и любые выкладки/миграции — **только по прямому разрешению владельца в чате, каждый раз**. Общие настройки Auth/GoTrue и JWT не менять (ADR-061a). Ключ DeepSeek и доступы к серверу — не в репозиторий, не в отчёт, не в чат.
- **Исключение из ADR-061 п. 1 (утверждено владельцем 25.10.2026):** разрешено изменить только функцию `deepseek-proxy` и только убрать режим «по имени». Таблицы РБИ (`public.*`), другие функции, бакеты — не трогать. Перезапуск службы функций — коротко, по разрешению, с проверкой старой функции сразу после.
- Учёт обращений, дневные пределы, новые возможности ИИ, смена модели — не делать (решение владельца).
- Профили/рейтинг/задачи по id — это P2-0035, не здесь.
- Ветки и карточки других блоков не трогать.

## 8. Риски и зависимости

- **Доступ к функциям сервера неизвестен** → этап 1 первый; без него блок `BLOCKED` (вопрос владельцу кнопками).
