## 2. Подтверждённое исходное состояние

## 3. Объём реализации

1. Черновик ставит «к отправке» только при реальном изменении (сравнение с последним сохранённым/отправленным); удаление — сохранить, затем пометить в памяти (откат при ошибке); «История» обновляет список при замене истории в памяти, тело объекта — из актуального списка.
2. Узнать лимит строк сервера: read-only запрос `range` > 1000 к таблице схемы `planfact` на помеченных тестовых данных (`test:server`, правила P2-0004+; настройка PostgREST общая для схем). По результату — размер страницы/пачки так, чтобы на 3000 проверок было ≤ 40 запросов, если лимит позволяет; иначе — зафиксировать число и оставить как есть (серверная выдача пачкой — отдельный блок по решению владельца).
3. №164 — после перевода снимков проверять, не закрыта ли база, переоткрыть; №165 — графики проверяют `isConnected` блока; №166 — одна выборка локальных записей только при полной загрузке (иначе — по нужным id); №167 — выдача пунктов по ключу (`id > последнего`) вместо смещения.
4. Стенд: инженер с назначенным объектом (или админ) — сохранить проверку → отправка → перехваченное тело запроса `rbi_inspections`/`rbi_inspection_items`: поля = до P2-0024 (снимка/ссылки нет), пункты с `details` целы. Самопроверка, документы, показ.
