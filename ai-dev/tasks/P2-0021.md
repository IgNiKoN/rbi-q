**Решения владельца (24.10.2026, кнопки):**
- что считать «требует моего участия» — все четыре вида: РП — факт ждёт подтверждения; прораб — мои отклонённые записи; ПТО — КС-2 (невыданные черновики и «сделано, не выставлено»); руководитель — позиции без факта больше 14 дней;
- где — красные точки с числом на пунктах меню + отдельная страница «Требует моего участия» по всем объектам;
- как считать — одним запросом сервера (миграция 029), в ней же исправление ТД №138.

**Уточнения владельца при выполнении (24.10.2026, кнопки):**
- «Стоят больше 14 дней» — тем, кто видит суммы (право `money.view`), а не всем с правом сводки;
- точки — сразу после входа, не только после открытия «План/Факта» (показ этапа 2): числа читает обёртка модуля `js/modules/planfact/index.js` через общее соединение входа (`RBI.platform2.rpc`), без загрузки бандла; файл добавлен к допустимым изменениям по этому решению;
- в красные точки меню — только «дела»: «Факт» = ждёт подтверждения + мои отклонённые; «КС-2» = черновики; «Требует моего участия» = сумма этих трёх. «Сделано, не выставлено» и «Стоят» — только числами на странице.

## 1. Цель

Человек входит — в меню у «Факта» и «КС-2» красные точки с числом. Открывает «План/Факт → Требует моего участия»: по каждому своему объекту — что ждёт именно его (по его правам): «Ждёт подтверждения: 8», «Мои отклонённые: 2», «Черновики КС-2: 1», «Сделано, не выставлено: 12 поз.», «Стоят больше 14 дней: 30 поз.». Нажатие — открывает нужный список с готовым фильтром. После решения (подтвердил, исправил, выдал акт) — число уменьшается.

## 2. Подтверждённое исходное состояние (`main` `bba35e7`)

- Очередь РП — `pf_fact_pending` (028: решение пачкой), журнал — `pf_fact_journal`; реестры «Ждёт подтверждения» / «Журнал» / КС-2 с видом в адресе (`#/planfact/fact/pending?…`, `#/planfact/fact/journal?…`, `#/planfact/ks2?…`).
- «Требует внимания» по объекту — `pf_summary_attention(p_project)` (013/013a): сделано не выставлено, позиции без факта > N дней, факт на подтверждении и др.; экран `summary/Attention.ts`.
- КС-2: `Ks2Api.acts` (статус `draft`).
- Меню оболочки: пункты модуля из манифеста (`nav`, `requiresAccess`), флаги доступа ставит модуль (`js/core/app-shell.js` ~стр. 64). **Чисел на пунктах меню нет.**
- ТД №138: `pf_fact_decide` (009) читает запись без `FOR UPDATE`, UPDATE без условия статуса.

## 3. Объём реализации

1. **Сервер (CRITICAL — права, факт):** миграция `029_inbox`:
   - `pf_my_inbox()` — только чтение, по всем объектам, где у вошедшего есть роль; по каждому объекту — только то, на что есть право: `pending` (`fact.approve`), `my_rejected` (свои записи `rejected`, пока на той же позиции нет моей более поздней записи; `fact.create`), `ks2_drafts` (`ks2.edit`), `ks2_gap` (позиций «сделано, не выставлено»; `ks2.edit`/`ks2.view`, ₽ — только при `money.view`), `stale` (позиций без факта > 14 дней; право сводки). Счёт — те же правила, что `pf_summary_attention` / `pf_fact_pending` (REUSE, без второй формулы). Архивные объекты — не показывать.
   - ТД №138: `pf_fact_decide` — `select … for update` записи и `update … where status = 'pending_approval'` (иначе «Запись не ждёт подтверждения»); `pf_fact_correct` — проверка «уже исправлена» после блокировки позиции. Поведение для одиночного вызова — прежнее.
   - Откат — `029_down` (функции 009 — как были).
2. **Точки в меню (оболочка):** общий механизм «число на пункте меню» (модуль сообщает `{ fact: N, ks2: M }`; оболочка рисует красную точку с числом на rail, нижнем таббаре и nav2; 0 — без точки; > 99 — «99+»). Модуль «План/Факт» берёт числа из `pf_my_inbox` при входе, при возврате на вкладку и после своих действий (решение РП, исправление, выдача акта). Подвкладка «Ждёт подтверждения (N)» — без изменений.
3. **Страница «Требует моего участия»** (`#/planfact/inbox`, пункт меню модуля с числом — сумма): группы по объектам, строки-плитки с числом и цветом палитры; нажатие — переход с готовым видом: «Ждёт подтверждения» объекта; «Журнал» объекта с фильтром «Отклонено» + «Внёс: я» и периодом, захватывающим запись; КС-2 с фильтром «Черновик»; «Сводка → Требует внимания» объекта. Пусто — «Всё сделано» (пустое состояние 1.14). Выбор объекта при переходе — тот же, что в списке.
4. **Документы и версия:** APP_GUIDE, DESIGN_SYSTEM (точка на пункте меню), SERVERS (029), CHANGELOG, «История обновлений», SW, FILE_MAP, TECH_DEBT (№138 закрыт).

**Вне блока:** уведомления (почта, push); «прочитано / скрыть»; счётчики Приёмки 2.0 и Качества; согласование прямо со страницы «Входящие» (только переход); почта или имя в журнале (ТД №139) — вопрос при показе.
