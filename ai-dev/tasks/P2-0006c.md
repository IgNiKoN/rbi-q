**Решения владельца (21.10.2026, кнопки и чат):**
1. **Один блок целиком** — справочник цен + смета + надбавки + КП + редакции КП (не резать на 0006c/0006d).
2. **Надбавки — гибко и настраиваемо**: точная методика станет ясна на пилоте, поэтому каждая строка надбавок редактируется (название, способ расчёта, база, ставка/количество, флажок «входит в итог»), шаблон компании правится, в смете — своя копия. Пример: строка «Аренда силомата+силосов» в `0_СЕБЕС…` не входит в итог хоз-быта — в системе это флажок, а не жёсткое правило.
3. **Единый справочник цен компании, редактируемый** (работы и материалы); цена, подставленная из справочника в смету, **всегда правится вручную** в смете (ручная правка помечается и не меняет справочник, пока ПТО не нажмёт «Записать в справочник»).

**Решения Архитектора (в рамках утверждения карточки):**
- Исходный файл заказчика **не хранится** (Storage не трогаем, вторая CRITICAL-зона не нужна): для КП ПТО выбирает тот же файл ещё раз, система сверяет SHA-256 с `vor_imports.file_sha256` (другой файл — понятный отказ), вписывает цены и отдаёт файл на скачивание. Редакция КП хранится как неизменяемый снимок цен и итогов — файл любой редакции можно получить повторно тем же способом. Хранение файлов — при переходе на свой сервер (этап Б+) или отдельной задачей.
- Начальное наполнение справочника — **вручную и кнопкой «Взять цены из загруженного ВОР»** (цены уже лежат в `vor_source_rows.prices`, например у нашего `0_СЕБЕС…`); после — только правка.

**Решение владельца по ходу этапа 1 (21.10.2026, кнопка «Точечная правка»):** exceljs при пересохранении файла заказчика теряет части файла (внешние ссылки формул `externalLinks`, `calcChain`, настройки печати, перенумерует листы) — стоп-условие этапа 1. Выбрано: файл не пересобирается — в zip-архиве меняется только XML листа (ячейки цен без формулы) и флаг `fullCalcOnLoad` в `workbook.xml`, прочие части копируются байт-в-байт; без новых библиотек (`CompressionStream`). Модуль `src/modules/planfact/vor/xlsx-writer.ts`; exceljs остаётся только для чтения. Дополнительно (владелец 21.10.2026, кнопка «Показать и открыть на нём»): лист с ценами делается видимым и открывается первым (`activeTab`, `tabSelected`), прочие скрытые листы заказчика остаются скрытыми. ## 1. Цель

ПТО по подтверждённому ВОР заказчика получает тендерную смету «как в `0_СЕБЕС…`»: работа = объём × расценка, материал = объём работы × норма × цена, затем настраиваемая цепочка надбавок (доставка, расходники, инструмент, ФОТ, ИТР, хоз-быт, прибыль, офис, НДС) → итог и ₽/м². Цены подставляются из единого справочника компании и правятся вручную. Результат — КП: файл заказчика с нашими ценами, структура файла не повреждена; редакции КП хранятся, видны отличия между ними.

## 3. Объём реализации

1. **Миграция 008** (только `planfact.*` и `public.pf_*`, есть `008_down.sql`, **применять файлом**, только по разрешению владельца):
   - `price_items` — единый справочник цен компании: `company_id`, `kind` (`work`|`material`), `work_type_id` (для работ), `canon_name` + `name` + `unit_id` (для материалов; `planfact.canon_name`), `price_labor` (расценка работы), `price_material` (цена материала или «материалы в составе работы»), `price_date`, `note`, `deleted_at`, `updated_by/at`. Уникальность: работа — по `work_type_id`; материал — по `canon_name + unit_id`.
   - `price_history` — каждое изменение цены (старая/новая, дата, кто, источник: `manual` / `import:<vor_import_id>` / `estimate:<id>`) — для подсказки «было раньше».
   - `overhead_templates` + `overhead_lines` — шаблон надбавок компании (по умолчанию один, «как в 0_СЕБЕС»): строка = `section` (материалы / ФОТ СМР / ФОТ ИТР / хоз-быт / прибыль / офис / НДС / прочее), `name`, `comment`, `method` (`percent_of` — % от выбранных баз; `qty_rate` — количество × ставка × множитель (чел. × мес. × ставка); `fixed` — сумма; `gross_up` — досчёт до 100 % по доле, «÷ 78 × 100»), `base` (jsonb: какие итоги/секции/строки — база), `params` (jsonb), `in_total` (bool), `sort`. Набор методов — **закрытый список**, произвольные формулы не вводим (риск ошибок и безопасности).
   - `estimates` — смета: `company_id`, `project_id`, `name`, `import_ids uuid[]` (один или несколько **подтверждённых** ВОР проекта, например два листа «себес»), `area_m2`, `status` (`draft`), `created_by/at`, `updated_at`.
   - `estimate_rows` — цена строки сметы: `estimate_id`, `source_row_id` (работа или материал), `price_labor`, `price_material`, `price_source` (`reference` | `manual` | `none`), `price_item_id`. Объёмы не копируются — берутся из `vor_source_rows` (SSOT).
   - `estimate_overheads` — копия строк шаблона в смете (те же поля, правятся в смете, не меняют шаблон).
   - `kp_revisions` — редакция КП, **неизменяемая** (LP-09): `estimate_id`, `revision_no`, `snapshot` (jsonb: цены по `row_no` каждого листа, надбавки, итоги, ₽/м²), `total`, `file_sha256` исходника, `created_by/at`, `note`. Повторное формирование = новая редакция.
   - Новое действие **`planfact.estimate.manage`** (справочник цен, шаблон надбавок, сметы, КП) → шаблоны `company_admin`, `project_manager`, `pto` + дозаполнение существующих ролей (как 007 §1). **Чтение цен, смет и КП — только у кого есть это право** (не все члены проекта: прораб цены не видит).
   - RLS на все таблицы: клиенту только SELECT по праву; запись — только `public.pf_*` (security definer, фиксированный `search_path`, право внутри, `company_id` из проекта); смета только по подтверждённым ВОР своего проекта; редакции КП — без UPDATE/DELETE (функции + триггер). Все изменения — в `audit_log`, журнал компании показывает цены, шаблон, сметы, КП.
2. **Справочник цен** (`Справочники → Цены`, ПК + 375 px): две вкладки «Работы» (по видам работ компании) и «Материалы»; поиск, правка цены в строке, дата цены, подсветка старых цен (старше константы, по умолчанию 90 дней), история изменений строки; «Добавить материал»; кнопка **«Взять цены из загруженного ВОР»** — выбор подтверждённой загрузки → предпросмотр «новых / изменится / без изменений» → применить (пишет историю с источником).
3. **Смета** (подвкладка «План/Факт → Смета», видна только с правом): «Новая смета» → выбрать подтверждённые ВОР проекта, ввести S, м² → таблица в структуре ВОР заказчика (группы / работы / материалы под работой): объём, норма, цена работы, цена материала, суммы «Работа / Материалы / Всего»; цена из справочника подставляется автоматически, ручная правка — в строке (пометка «вручную», подсказка «в справочнике X от даты, было Y»); фильтр «без цены»; «Записать ручные цены в справочник» (пачкой, с выбором строк). Материал = объём работы × норма × цена; если у строки материала уже посчитан объём в файле — берётся объём из `vor_source_rows.qty` (как в `0_СЕБЕС…`, где объём материала = F работы × норма).
4. **Надбавки** (в смете — блок «Расчёт», в настройках — «Шаблон надбавок компании»): строки по секциям, у каждой — способ, база, параметры, флажок «в итог», комментарий; добавить/удалить/переставить строку; промежуточные итоги секций, «Всего прямые затраты», итог, ₽/м². Шаблон по умолчанию (создаётся для компании при первом открытии) — **строки листа «Расчет» `0_СЕБЕС…`** с их способами; «Сбросить из шаблона» / «Сохранить как шаблон компании». Расчёт — чистая функция в клиенте с unit-тестами; округление — до копеек только при выводе и в снимке КП.
5. **КП в форме заказчика:** «Сформировать КП» → ПТО выбирает файл заказчика → проверка SHA-256 → цены вписываются в колонки цен профиля формы (`column_map`: цена работы / материалов / всего — какие есть в форме; если колонки цены не распознаны — ПТО указывает их выпадающим списком, профиль запоминает) по `row_no` нужного листа; формулы заказчика **не перезаписываются** (пишем только в ячейки без формулы; при пересчёте — флаг полного пересчёта книги при открытии); остальные листы, объединённые ячейки, форматы, ширины, скрытые строки — без изменений. Создаётся редакция КП, файл скачивается как `<имя>_КП_ред<N>.xlsx`. Список редакций сметы; «Сравнить с …» — строки, где изменились цены/суммы, и разница итогов; «Скачать ещё раз» (снова выбрать исходник).
6. Документы и отчёт: `docs/APP_GUIDE.md` (разделы «Цены», «Смета», «КП»), `standards/AUTH_AND_ACCESS.md` (новое действие, «прораб цены не видит»), `docs/SERVERS.md` (миграция 008), `FILE_MAP.md`, `docs/TECH_DEBT.md`, `CHANGELOG`.

**Вне блока:** бюджет объекта, плановый ФОТ и маржа (LP-05) — граница: смета = тендерная стоимость для заказчика, бюджет — позже; типовые материалы и нормы у вида работ (подстановка материалов, если в ВОР заказчика их нет) — техдолг, пока ПТО указывает «материалы в составе работы» ценой `price_material`; хранение файлов в Storage; импорт из сметных программ; ИИ; редакции ВОР (P2-0006b); КС-2.

## 8. Риски и зависимости

- Коммерческая тайна → чтение цен только по праву; прораб — отрицательный SQL-тест.
