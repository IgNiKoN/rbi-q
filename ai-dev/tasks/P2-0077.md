## 3. Объём

1. **Автоматический пересчёт без явной кнопки** — после синхронизации, при открытии базы и при смене компании — строит план **только на себя** (`engineersToProcess = [myName]`). План «на всех» остаётся только по явной кнопке админа «Синхронизировать / пересчитать план». Если такой кнопки нет — нигде.
2. **Пересчёт не двигает срок существующей задачи.** Срок ставится только при создании задачи. Сравнение — по дню, а не по миллисекундам. «Аудит» не меняет `target`/`done`/`status` у чужих задач.
3. **К отправке помечается только реально изменённая задача:** отпечаток до и после совпал — `_touchTaskForSync` не вызывается.
4. **Новые задачи и закрытие своих задач работают как раньше.** Задачи, которые инженер создаёт и закрывает сам, по-прежнему уходят на сервер.
4а. **Профиль инженера не уходит на каждом проходе (ТД 415, решение Архитектора 31.10.2026 — «да, делай в P2-0077»).** В `company.service.js` (`_mirrorRoleOverridesLocal` / `_mirrorOfficialTemplatesLocal`) не вызывать `settings.set`, если значение не изменилось; сравнение — не зависящее от порядка ключей. `sync-engine` не трогать. Unit-тест: два прохода подряд без изменений → второй «отправлено 0»; отдельный тест — реальная смена настроек компании по-прежнему уходит. Критерий приёмки: **«повторный проход без изменений — отправлено 0»**.
5. **Сервер, миграции, Внешний СК, План/Факт не трогать.** Серверная проверка «кто новее» — вариант В, позже.
