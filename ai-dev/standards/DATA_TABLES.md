# Стандарт таблиц сервера (P2-0069, 30.10.2026)

Единственное место правил «каким должно быть поле таблицы». Имена — из `reference/GLOSSARY.md` (колонка «В коде»); здесь — состав полей. Проверяет сторож: `npm run test:unit` (по описи) и `npm run test:schema` (по свежей схеме PGlite). Опись и светофор — `reports/P2-0069/inventory.html`; правила в виде кода — `tests/server/schema-lint.mjs`.

## Правила (каждая таблица разделов `core`, `planfact`, `quality`)

| № | Правило | Поле | Почему |
|---|---|---|---|
| 1 | Ключ | `id uuid primary key` | запись узнаётся одинаково на телефоне и на сервере; id создаётся на устройстве — повтор не делает дубль (MODULES §9 п. 1) |
| 2 | Компания | `company_id uuid not null` → `core.companies` | граница данных: чужая компания записи не видит |
| 3 | Проект и место | `project_id uuid`, `location_id uuid` (объект — тоже место), если запись к ним относится | поиск и права — только по id; название — подпись (спека п. 12, 15) |
| 4 | Автор | `created_by uuid` (учётка) — одно имя для всех новых таблиц; `core_created_by` — только мост Качества | ФИО меняется; подпись для печати — снимок `*_name` |
| 5 | Время | `created_at`, `updated_at timestamptz` | одно время в любом часовом поясе (§9 п. 6); `timestamp` без пояса — нельзя |
| 6 | Удаление | `deleted_at timestamptz` (+ `deleted_by uuid` или запись в `core.audit_log`) | ничего не стирается (§9 п. 2); `is_deleted`, `archived boolean` — нельзя; `archived_at` — это архив, не удаление |
| 7 | Ссылки | `uuid` с внешним ключом; фирма — `counterparty_id` | база не даёт сослаться на несуществующее; ссылка текстом или по названию — нельзя |
| 8 | Имена | `snake_case`, без кавычек | одно написание во всех таблицах |
| 9 | Защита строк | RLS включён в той же миграции | без неё таблица открыта всем учёткам |
| 10 | Деньги | `numeric`; `currency` — у родителя (проект, смета, прайс, договор), строки — в валюте родителя; чужая валюта пересчитывается при вводе | точная сумма с валютой (§9 п. 5); владелец 30.10.2026: «вся смета в одной валюте» |

Проверяется **вручную** (сторож не видит): ставка НДС у суммы; суммы внутри `jsonb`; что лежит в поле с неясным именем (`owner` — ФИО или id); `deleted_by` при наличии журнала.

## Светофор

- **Зелёный** — правило соблюдено. **Жёлтый** — исключение с причиной или мост: правильное поле уже есть, старое ещё рядом (снимется уборкой). **Красный** — нарушение. **—** — правило к таблице не относится.

## Классы исключений (жёлтый вместо красного, у каждой таблицы — своя причина в `schema-lint.mjs`)

| Класс | Снимает правила | Когда |
|---|---|---|
| Каталог платформы | 1, 2, 4, 5, 6 | общий для всех компаний справочник, ключ — код, правит только платформа |
| Связка | 1, 4, 5, 6 | пара значений и есть запись (составной ключ), изменения — в журнале |
| Журнал / событие | 1, 6 (и `updated_at`) | только добавление: не правится и не удаляется; исправление — новой записью |
| Дочерняя строка | 2, 4, 5, 6 | живёт и удаляется с родителем; компания, автор, время — у родителя |
| Одна запись на владельца | 1, 4, 6 | профиль или настройки: ключ — пользователь, проект, компания |
| Сама компания | 2 | `core.companies` |
| Мост / служебная | 1, 3, 4, 5, 6, 7 | перенос и сопоставление; снимается уборкой с датой (спека п. 14, `TECH_DEBT.md`) |
| Качество из RBI | 8 | решение владельца 30.10.2026: таблицы Качества не переименовываем |

Новый класс или новое исключение — только с причиной и решением Архитектора на приёмке. Правило 10 «валюта у родителя» утверждено при приёмке P2-0069 (владелец: «вся смета в одной валюте»); сторож проверяет его с P2-0072: сумма в строке без своей `currency` — зелёная, если у родителя по внешнему ключу есть `currency`, иначе красная (старые нарушения — в потолке, шаг ПФ3 — P2-0065). Ключ Качества `id text` — не исключение: переводится на `uuid` постепенно, мост — P2-0072 (ниже).

## Как менять старые таблицы

- **Качество (`quality.*`) — «поле рядом»** (решение владельца 30.10.2026): добавить правильное поле с префиксом `core_` (`core_company_id`, `core_project_id`, `core_location_id`, `core_created_by`, `core_counterparty_id`) или `deleted_at`, заполнить по сопоставлению, писать в оба, старое снять уборкой (мост с датой снятия). Переименований нет.
- **`core`, `planfact`** — переименование можно, если код читает таблицу только через RPC платформы (проверить по коду); иначе тоже «рядом».
- Чинить там, где блок всё равно трогает таблицу (§9). Очередь — `reports/P2-0069/migration-plan.md`.
- **Мост ключа Качества (P2-0072, миграция 054):** у 41 таблицы рядом со старым `id text` (ключ синхронизации) — `core_id uuid not null`, уникальный: новые записи с телефона — `uuid` (он же), старым — сервер. Связи по тексту — рядом `core_<связь>_id uuid` с внешним ключом на `core_id` родителя (16 связей: проверка, отчёт, родитель места, здание / этаж / объект старого Стройконтроля, место Стройконтроля 2.0, подрядчик договора). `core_id` не меняется (сторож `quality.core_ids_stamp`), телефон его не отправляет. В светофоре — жёлтый «мост» с причиной; старое снимет «Уборка» P2-0063 (ключ синхронизации → `core_id`).

## Сторож

- Новая таблица с красным — проверка падает (исключение — только классом с причиной).
- У старых таблиц красных **не больше** потолка `reference/schema-debt.json` (по таблице и правилу); стало меньше — проверка просит снизить потолок: счётчик только убывает.
- После новой миграции: `P2_PGLITE=<папка> node scripts/schema-inventory.mjs` — обновить опись (иначе `test:unit` скажет «опись устарела»); `--update-debt` — снизить потолок.
- **Заготовка новой таблицы модуля** — `supabase/templates/new_module_table.sql` (ключ `uuid`, компания, проект и место по id, автор, время, `deleted_at`, внешние ключи, RLS через `core.row_allowed` в той же миграции; деньги — по правилу 10). `npm run test:schema` применяет её в PGlite и проверяет: все правила зелёные.
