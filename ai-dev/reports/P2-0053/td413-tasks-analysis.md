# ТД 413 и «свалка задач» Качества — разбор (Исполнитель P2-0053, 31.10.2026)

Запрос владельца 31.10: «разобраться с отправкой задач, исправить»; «в целом разобраться, как правильно сделать задачи, чтобы работали нормально и адекватно — сейчас там свалка задач постоянно».
Только разбор по коду; код не менялся. Прямой запрос к боевой базе (только чтение) защита сеанса не пропустила, поэтому выводы — по коду, числа по боевому не сверены (запрос для сверки — в конце).

## 1. Почему ушли 84 задачи (ТД 413) — не демо и не 057

Задачи Качества «по плану» (тип `auto`) создаёт **само устройство** — функция `_gameGenerateWeeklyPlan` (`js/modules/quality/features/tasks/tasks.module.js:586`). Цепочка:

1. Отметка «план этой недели уже составлен» (`weekly_plan_data.weekId`) хранится в базе устройства **отдельно для каждой компании** (`game.actions.js:341`). При первом открытии Качества в базе РБИ на этой неделе отметка — с прошлой недели → `force = true` (`tasks.module.js:608`).
2. С `force` у **админа** (роль Качества `manager` = `isAdmin`, у владельца — «Руководство» → `quality.manage`) план пересчитывается **всем инженерам**, которые есть в проверках на устройстве (`tasks.module.js:626–630`; комментарий там же говорит, что это задумано только по явной кнопке).
3. С `force` у каждой открытой задачи срок ставится заново от «сейчас» (`tasks.module.js:711–720`: «Приёмка эталона» — сегодня, «Инспекция» — сегодня + 7/14 дней) → отпечаток задачи меняется → задача помечается «к отправке» (`_touchTaskForSync`, `:262`, `:722–725`).
4. Синхронизация отправляет все задачи «не synced» (`js/services/sync/sync-engine.core.js:3094–3114`) — 84 задачи 13 инженеров одного объекта.

Выход из демо только открыл базу РБИ на устройстве владельца — то же случится у любого админа при первом открытии Качества на новой неделе (и при смене компании туда-обратно). **Последствие для данных:** у задач инженеров на сервере сдвинулся срок (на «сейчас»/+7–14 дней) — просроченные задачи перестают быть просроченными; содержимое кроме срока и цели не меняется.

Ещё два входа в тот же пересчёт с `force` без кнопки: смена роли из профиля при старом входе по PIN (`sync-engine.core.js:624`), возврат из отсутствия, первая проверка по чек-листу, создание совещания (`game.actions.js:585, 621, 974, 1269`, `audit.actions.js:1014`, `meetings.module.js:1454`).

## 2. Откуда «свалка задач»

Генератор работает на каждом устройстве, при каждом открытии вкладки инженера (`tasks.module.js:2470`), и создаёт на **каждого** инженера:

| Задача | Когда создаётся | Почему копится |
|---|---|---|
| «Приёмка эталона» | на **каждую** пару «подрядчик × вид работ», которую инженер **когда-либо** проверял, без акта-эталона (`:756`, `:804`) | пары берутся за всё время — старые подрядчики и давно законченные работы дают задачи вечно |
| «Инспекция: подрядчик» | на каждую пару с нехваткой проверок; новый подрядчик — 7 проверок за 14 дней (`:811–849`) | тоже по всем парам за всё время |
| «Воркшоп», «Карта TWI», «FMEA» | по повторам дефектов | — |
| Плакат, совещание, One-Pager, выгрузка ПК СК, «День качества» | каждую неделю/месяц всем, «Системная» (`:954–989`) | новые id каждую неделю; незакрытые переносятся со сменой id (старая — «удалена», новая — создана) → лишние отправки |

Плюс: (а) у админа — то же на всех инженеров со своего устройства (п. 1), задачи «двоих авторов» (устройство инженера и устройство админа) переписывают сроки друг друга; (б) срок открытой задачи сдвигается при каждом принудительном пересчёте — задача никогда не просрочена, «висит» вечно; (в) правила считаются по проверкам, которые есть **на этом устройстве** (у прораба/инженера одна выборка, у админа другая) — разные устройства видят разный план.

**Суть:** задачи — не поручения людей, а вычисляемые подсказки, которые каждое устройство «материализует» в записи и отправляет на сервер. Отсюда и число, и шум, и повторные отправки.

## 3. Варианты (решает Архитектор с владельцем)

| Вариант | Что | Плюсы | Минусы |
|---|---|---|---|
| **А. Заплатка (маленькая)** | Пересчёт без кнопки — только свой план; пересчёт никогда не двигает срок существующей задачи и не шлёт неизменённую | Сразу прекращает повторные отправки и сдвиг сроков | Свалку не уменьшает |
| **Б. Подрезать генератор** | А + пары «подрядчик × вид работ» только за последние 4 недели и только активные объекты; не более одной «Приёмки эталона» и одной «Инспекции» на подрядчика; системные недельные — одна запись на период без смены id; устаревшие авто-задачи закрываются сами («неактуально») | Задач в разы меньше; без смены сервера | Логика остаётся на устройствах — разные устройства по-прежнему считают по-разному |
| **В. Правильно: задачи считает сервер** | Правила плана — одна функция на сервере, раз в неделю/по событию, по всем проверкам объекта; устройство только показывает и закрывает; поручения людей (`manual`) — отдельно; единые «Входящие» платформы | Один источник истины, одинаково на всех устройствах, нет гонок и повторных отправок; ложится в стандарт синхронизации (P2-0061) и «Входящие» | Крупный блок: миграция, перенос правил, тесты |

**Рекомендация исполнителя:** А сейчас (отдельной маленькой задачей, с тестом стенда «админ открыл Качество на новой неделе → 0 отправок чужих задач»), затем В блоком Архитектора; Б — только если В откладывается надолго.
