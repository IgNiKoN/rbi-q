# P2-0053 — план выкладки на боевой (после «проверено, выкладывай» Архитектора)

Порядок карточки («Автономия Исполнителя», п. 0–1): стенд → сдача Архитектору → доработка по кругу → **«проверено, выкладывай»** → Исполнитель сразу выкладывает (без отдельного «да» владельца) → короткий отчёт Архитектору → проверка боевого → «принято» владельца.

## 0. Перед выкладкой

- Ветка `task/P2-0053-demo-mode` свежая к `main` (если `main` ушёл вперёд — влить `main`, пересобрать `npm run build:platform && npm run build:planfact`, `test:unit`, PGlite 057).
- Прежний коммит сайта (откат): `git -C /var/www/rbi-quality rev-parse HEAD` → записать в `release/checks.md`.
- `scripts/demo/snapshot.sql`: поставить T0 = момент начала выкладки (первая строка) → SQL Editor → «Copy as JSON» → `release/snapshot-before.json`.

## 1. База: 057

1. SQL Editor: `supabase/migrations/057_demo_mode_up.sql` целиком (буфер в UTF-8, md5 файла — в `checks.md`) → «Success». Проверка: `select to_regclass('core.demo_visits'), (select count(*) from pg_trigger where tgname = 'zzzzz_demo_guard')` — таблица есть, сторожей ≈ 96.
2. SQL Editor: `tests/server/057_demo_mode.sql` (всё в транзакции, откатывается сам) → «FAIL всего: 0».
3. Стоп-условие: ошибка 1–2 → `057_demo_mode_down.sql`, отчёт.

## 2. «ЖК Демо»

1. `node scripts/demo/accounts.mjs` → `.env.zhk-demo-accounts.sql` → SQL Editor → удалить файл.
2. `node scripts/demo/seed.mjs` (адрес и ключ — `.env.local`) → сводка в `checks.md`: мест 244, видов работ 20, планов 3, демо-ролей 8, строк ВОР 325, записей факта 241, КС-2 3 (выдано 2), проверок 10, замечаний СК 30, приёмок 3.
3. `snapshot.sql` с тем же T0 → `release/snapshot-after.json` → сравнить с «до»: отпечатки не демо-компаний **равны** (иначе — откат, раздел 5).

## 3. Сайт

1. В основной папке: `git merge --ff-only task/P2-0053-demo-mode` (или merge-коммит, если `main` ушёл), `git push origin main`.
2. Сервер (терминал Beget, `docs/SERVERS.md`; символы с Shift — вставкой): `cd /var/www/rbi-quality && git pull --ff-only` → `node scripts/check-release.mjs` (или как в прошлых выкладках) — версия = `sw.js` ветки.
3. `test:server` (серверные тесты на помеченных тестовых данных) → FAIL 0.

Своей учёткой (админ платформы): `https://app.rbi-q.ru/#/demo` → 8 ролей (375 и 1440): плашка, раздел роли, прораб — только своя секция; попытка записи (смета ПТО) — «Демо — только просмотр»; «Обучение»: три тура до конца; PDF-план этажа 5 Корпуса 2 в СК 2.0 открывается (на стенде не проверялось — ТД 408); «Выйти» — своя компания, «Администрирование платформы» снова есть.

## 5. Откат (немедленно при утечке прав, изменении данных РБИ, ошибке на боевом)

- Сайт: `cd /var/www/rbi-quality && git reset --hard <прежний коммит>`.
- База: SQL Editor `scripts/demo/reset.sql` (демо-компания и `zd-dd-…` учётки) → `supabase/migrations/057_demo_mode_down.sql`.
- Песочница — тестовая компания; при откате остаётся (скрыта у админа платформы), учётки — `pf_company_disable_member` по «да» владельца.

## 6. Проверка владельцем (10 минут)

Войти своей учёткой РБИ → «Демо» (на приветствии) → «Руководитель проекта» (сводка: К1 0 %, К2 ≈ 56 %, К3 100 %) → плашка «Демо · … ▾» → «Прораб» (только Корпус 2, секция 1) → «Инженер качества» (СК 2.0 → «📄 эт. 5» → точки на плане) → «Демо» → «Обучение: План/Факт» до конца → «Выйти из демо» — вы в РБИ. Файл доступов «Песочница — Клиент 1» — в iCloud «Доступы клиентов»; до передачи клиенту закрыть порты (`docs/DEMO.md` §5).
