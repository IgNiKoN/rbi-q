# P2-0060 этап 4 — правило по роли + «Фото и PDF заранее» по охвату

Правило (`src/platform/services/offline/files-rule.ts`, чистые функции): роль — роль экрана Качества по правам сервера (`roleFor`), не название должности.
- инженер, подрядчик (полевые: инженер СК, прораб, мастер, подрядчик) — модули держать без сети, фото — **мои объекты за 30 дней + фото открытых замечаний моих объектов независимо от даты**;
- руководство (manager, director), гость — модули держать без сети, фото — **не скачивать заранее** (открытое остаётся в кэше).
Выбор человека важнее правила (хранится у «компания + пользователь»: `platform2_offline_files:<слот>`; «держать без сети» Качества выключено — фото заранее не качаются).

**Толкование «открытого замечания» Качества (отдельной отметки «закрыто» у осмотра нет):** пункт «не принят» (fail / bad), который более поздний осмотр
того же объекта по тому же шаблону не принял. Качается фото этого пункта из последнего осмотра, где он не принят. — **на приёмке подтвердить**.

автокэш после синхронизации (первый полный и по запросу) и «лёгкая очередь» после каждой синхронизации — в охвате человека (none — ничего). Уже скачанное само
