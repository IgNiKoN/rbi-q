## CRITICAL-ревью diff 018–018e, sync, Storage (независимое, read-only)

Блокирующих нет. Межкомпанийного доступа к строкам и файлам нет при применении в документированном порядке. Проверено: подмена `x-company-id` (принимается только при членстве в компании), привязка строк к компании/объекту (смена компании запрещена, составной FK), RLS на всех 55 таблицах, anon — ничего, `search_path` и revoke у всех SECURITY DEFINER, нет рекурсии триггеров, ограничивающие правила Storage не меняют бакеты РБИ, объекты `public` РБИ не затронуты ни up, ни down; клиент шлёт только заголовок и токен — проверки на сервере.

- HIGH (только при откате не по порядку): `018_quality_down.sql` — `drop schema quality cascade` до `018d_down` снимет и ограничивающие правила, а бакеты с файлами останутся → правило РБИ откроет их руководителю РБИ. Сторожа порядка нет — **ТД №117, исправить первым этапом следующего блока, Качества**.
- MEDIUM: `018b` задаёт `pgrst.db_schemas` целиком — если на сервере в API был ещё раздел, он пропал бы (снимок RBI этого не ловит; `public` на месте, `test:server` и проверки API — норма) — ТД №118 (сверить с настройкой сервера).
- MEDIUM: 018e — пользователь с правом записи в Качестве создаёт черновики контрагентов без права `core.counterparties.manage`, в журнале нет автора; правка контрагента в ядре воскрешает удалённую в Качестве строку справочника, архив контрагента её не убирает — ТД №119.
- MEDIUM (риск низкий): ключи 43 таблиц `quality` (`id text`, `project_code` у настроек) глобальные, не по компании — столкновение id с чужой компанией даёт ошибку (утечка факта существования / блокировка); id клиентские и трудноугадываемые — ТД №120 (добавить компанию в ключи, как у `sk_records`).
- LOW: файлы и строки уровня компании видны всем назначенным в компании (без разреза по объекту) — по замыслу, подтвердить с владельцем; `sw.js` при 401/403 отдаёт закэшированный файл (возможно, другой учётки на том же устройстве); `018d_down` удаляет `storage.objects` SQL-ом (на новых версиях Storage запрещено, файлы остаются в хранилище); `018e_down` упадёт, если черновик где-то указан (транзакция откатится целиком) — ТД №121.
