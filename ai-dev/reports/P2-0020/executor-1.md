## Что сделано (коротко)

- Сервер (028): `pf_fact_decide_batch(p_project, p_entries uuid[], p_approve, p_note)` — проверки пачки (право `fact.approve` в проекте, 1…500, без повторов и null, причина отказа, все записи этого проекта и `pending_approval`), затем для каждой — `public.pf_fact_decide` из 009 (REUSE: права, замена исправляемой, журнал APPROVE/REJECT); порядок — глубина цепочки исправлений в пачке, затем `created_at`; одна транзакция — всё или ничего. `pf_fact_journal(p_project, p_from, p_to, p_limit)` — только чтение, `fact.view`. Прежние функции не менялись.
- «Факт»: подвкладки маршрута «Ждёт подтверждения (N)» (только при `fact.approve`; на телефоне «Ждёт РП (N)») и «Журнал»; внутренняя кнопка «Ввод / Ждёт подтверждения» убрана. `PendingRegistry`, `FactJournal`, `PendingDecision` (решение по одной — из бывшего списка `FactPending`), `factStatus.ts` (статусы записи и строка истории — вынесены из `vor/PositionsRegistry.ts`, там реэкспорт `historyItem`). `fact.service`: `decideBatch`, `journal`.
- «КС-2»: `Ks2Registry` вместо самодельного списка; сумма — по `planfact.money.view` из `pf_my_permissions`.
- Оболочка: `syncRegistryAddress(base, вид)` в `registry/views.ts` (+ тест), «ВОР → Позиции» переведены на него (было своё такое же). Маршрут: часть адреса после «?» не ломает выбор страницы.
