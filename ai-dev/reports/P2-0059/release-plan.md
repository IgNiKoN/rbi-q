## 2. Совместимость

- Новое приложение работает с нынешним сервером без изменений: те же таблицы и `upsert … onConflict id`.
- На устройстве появляются ключи `rbi_sync_journal:<база компании и пользователя>` (журнал, ≤ 500 событий), `rbi_sync_retry_kind` (вид последнего сбоя), `rbi_sync_lease` (замок — только в браузерах без Web Locks). Старый код их не читает — откат безопасен.
- Неотправленные записи и их статусы — те же поля записи (`sync_status`): после обновления уходят новым кодом, после отката — старым.

## 4. Проверка владельцем — «полевой тест 15 минут» (телефон)

1. Войти с интернетом, открыть Качество. «Настройки → Данные на устройстве» — «Всё отправлено», внизу «Журнал синхронизации».
2. Подвал или авиарежим: записать 3 осмотра с фото → значок «3». Нажать на значок — у каждого осмотра «Нет связи · отправим сами, как появится».
3. Закрыть приложение. Выйти на связь (выключить авиарежим). Открыть приложение.
4. В течение 1–2 минут значок исчезает, «Данные на устройстве» — «Всё отправлено · Последняя успешная отправка: сегодня …»; в журнале — «конец · отправлено 3». На компьютере — 3 осмотра, каждый один раз.
5. Если что-то не ушло: «Журнал синхронизации → Скопировать отчёт для разработчика» и прислать текст.

**Не проверялось на настоящих iPhone / Android** (стенд — Chromium в режиме телефона, подставной сервер): сценарий выше — для владельца. Фоновая отправка при закрытом приложении не делалась (ТД №314).
