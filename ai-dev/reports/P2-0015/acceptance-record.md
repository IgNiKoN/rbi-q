## CRITICAL-ревью diff 016 / 017 (независимое, read-only)

Отбор функций для переписывания не задевает объекты RBI в `public` (единственная функция 015 на таблице RBI выбирается, но не меняется); коды прав в кавычках не трогаются; `create or replace` сохраняет владельца, ACL и SET; политики/FK/триггеры переезжают по OID; повтор up безопасен; компания проверяется в каждой новой функции и составными FK.

- MEDIUM → LOW после проверки сервера: `core.counterparty_card` — SECURITY DEFINER без проверки прав, отозвана только у public/anon. **На сервере 23.10.2026 (только чтение):** у всех функций `core.*` ACL `supabase_admin=X` — `authenticated` и `anon` вызвать не могут. Добавить явный `revoke … from authenticated` и тест ACL — ТД №104.
- MEDIUM: 016 (и откаты) без явного `begin/commit` — атомарность держится на запуске одним запросом (SQL Editor так и применял). Для будущих миграций ядра — явная транзакция; порядок откатов 017_project_links → 017_counterparties → 016 — в `docs/SERVERS.md` — ТД №105.
