Сторож: новая таблица с нарушением не проходит

Проверка работает в обычной самопроверке (npm run test:unit, по описи) и по свежей схеме (npm run test:schema). Пример — временная миграция (удалена после проверки, 30.10.2026): новая таблица без компании и с автором текстом, а у старой таблицы добавлено удаление флагом.

✕ новая таблица planfact.tmp_things: правило «Компания company_id» — нет company_id
✕ новая таблица planfact.tmp_things: правило «Автор created_by uuid» — автор только текстом (created_by)
✕ planfact.vor_profiles: правило «Удаление — пометка deleted_at» — нарушений стало 2, потолок 1: удаление флагом (is_deleted)
сторож таблиц: 106 таблиц, новые с нарушением 2, рост 1, снизить потолок 0

Если миграцию добавили, а опись не обновили, test:unit говорит: «опись устарела — миграции изменились». Если нарушений стало меньше — проверка просит снизить потолок ai-dev/reference/schema-debt.json: счётчик только убывает (сейчас 153 нарушения в 75 таблицах).
