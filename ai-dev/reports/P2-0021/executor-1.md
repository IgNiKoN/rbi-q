## Что сделано (коротко)

- Сервер (029): `pf_my_inbox()` — по всем неархивным объектам, где у вошедшего есть право; виды без права — `null`. «Не выставлено» и «стоят» — вызовом `pf_summary_attention` (REUSE, одна формула), только при праве. ТД №138: в `pf_fact_decide` и `pf_fact_correct` запись перечитывается `FOR UPDATE` после блокировки позиции (порядок блокировок прежний), решение — `update … where status = 'pending_approval'`, иначе «Запись не ждёт подтверждения». Откат `029_inbox_down.sql` — тела функций побайтно как до 029.
- Оболочка: общий механизм числа на пункте меню `setNavBadges(scope, map)` / `paintNavBadges()` — боковое меню, мобильное меню модулей, нижний таббар, nav2; без чисел меню прежнее.
- Модуль: обёртка `js/modules/planfact/index.js` ставит точки сразу после входа через `RBI.platform2.rpc('pf_my_inbox')`; бандл после своих действий шлёт `planfact:inbox-changed` (обёртка сервисов `withInboxRefresh` — факт и КС-2). Пункт «Входящие» и страница `#/planfact/inbox`. Разделы принимают объект из перехода (`p=`), «Журнал» — период (`from=`), «Сводка» — прокрутку к «Требует внимания» (`focus=attention`).

## Отклонения от карточки

- «Стоят > 14 дней» — по праву `money.view`, а не «праву сводки» (`fact.view` есть у прораба и заказчика) — решение владельца кнопкой 24.10.2026.
- В точки — только «дела» (без «не выставлено» и «стоят») — решение владельца кнопкой.
- Точки сразу после входа — числа читает обёртка `js/modules/planfact/index.js` (файл вне §4) — решение владельца на показе этапа 2.
- В `pf_my_inbox` добавлено поле `my_rejected_from` — чтобы «Журнал» открывался с периодом, захватывающим запись (карточка требует этого, но поля не называла).
- «Мои отклонённые» — пока на позиции нет моей записи, внесённой **после решения об отказе** (сравнение по `decided_at`, не по `created_at`: записи одной транзакции имеют одно время — тест ловил).
- «Сводка» из перехода — адрес `#/planfact/summary?…` (адрес `#/planfact?…` роутер оболочки не узнаёт).
