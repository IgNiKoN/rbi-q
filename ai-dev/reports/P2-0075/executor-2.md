# Отчёт исполнителя — P2-0075, доработка №1 (сухой прогон уборки на боевой — ошибка 42804)

**Дата:** 31.10.2026 · **Ветка:** `task/P2-0075-fix1` (рабочая копия `~/dev/platform-2-core-0075fix1`, от `main` `db71b49`) · не запушено, не влито · миграций нет. На боевом ничего не запускалось.
**Запуск:** сообщение Архитектора: сухой прогон `scripts/cleanup-test-projects.sql` на боевой → `ERROR 42804: type of parameter 28 (text) does not match that when preparing the plan (uuid)`, `PL/pgSQL … line 129 at EXECUTE`; откат, данных не тронуто.

## Причина

Шаг 3 скрипта (записи «REST…» по таблицам) — один цикл `for r in execute …` по 13 таблицам; ключ `r.id` у одних таблиц `uuid`, у объектов и мест Качества (`quality.project_objects`, `quality.location_nodes`) — `text`. PL/pgSQL запоминает тип выражения `r.id` при первом выполнении (`uuid`), на таблице с текстовым ключом — 42804. Засев PGlite этап 1 не имел «REST…» в таблицах Качества с текстовым ключом, поэтому не ловил.

## Что сделано

1. **Воспроизведено:** засев `tests/server/cleanup_seed.pglite.sql` дополнен «REST…» (и обычными) строками `quality.project_objects`, `quality.location_nodes` (идут после таблиц с ключом `uuid`); прежний скрипт → `type of parameter 28 (text) does not match that when preparing the plan (uuid)` — та же ошибка, тот же номер параметра.
2. **Исправлено в шаге 3:** своя переменная цикла `rn`; в выборке ключ всегда `::text`, компания — `::uuid`; удаление — `where <ключ> = $1::<настоящий тип ключа>` (тип из `pg_attribute` — удаление по индексу, без перебора таблицы на каждую строку).
3. **Найдено попутно и исправлено:** объект Качества «REST…» отражён в ядре проектом-объектом (`core.projects`, имя то же); `quality.project_objects.core_object_id` ссылается на него **без каскада**, поэтому проект не удалялся с первого запуска (оставался «есть ссылки»), удалялся только повтором. Теперь перед удалением проектов «REST…» убираются строки таблиц Качества с `core_object_id` этих проектов (только в тестовых компаниях; в журнал удалённого). На боевой это ожидаемо: «REST…» объектов Качества 39, проектов ядра 40.
4. **Остальные циклы проверены:** у каждого поля записи в скрипте один тип во всех циклах (`r.id`/`r.company_id` — только цикл проектов, `uuid`; `r.table_name`, `r.tbl`, `r.tgname`, `r.step`, `r.what` — неизменны). Других `using r.*` с меняющимся типом нет.
5. Проверка `cleanup_check.pglite.sql`: «REST…» объектов / мест Качества в списке оставшегося; обычные объект и место (ключ текстом) — на месте.
