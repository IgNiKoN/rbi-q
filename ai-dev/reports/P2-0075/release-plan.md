# P2-0075 — план выкладки

**Что выкладываем:** сайт (скрытие тестовых компаний, новый `test:server`) и разовая уборка «REST…» в тестовых компаниях. **Миграций нет.**
Каждый шаг на боевом — только по прямому разрешению владельца. Исполнитель на боевом сервере ничего не запускал.

## 1. Сайт (по «влей и выложи»)

1. Влить `task/P2-0075-test-data` в `main`, `git push` (разрешение владельца).
2. На сервере: `git log -1 --format=%h` (запомнить — это откат), затем `git pull --ff-only` в `/var/www/rbi-quality` (Beget, терминал панели — `beget-vnc-git-pull`).
3. Проверка (2 минуты): войти администратором платформы → «Настройки → Платформа» → в списке нет «Альфы» и «Беты», есть галочка «Показать тестовые (N)»; отметить — они появились с пометкой «тестовая»; «Настройки → Мой профиль» — переключатель компании с той же галочкой.
4. **Откат сайта:** `git reset --hard <коммит из п. 2>`.

## 2. Сухой прогон уборки (по «да» владельца; ничего не удаляет)

1. Панель SQL Editor → вставить **файлом** `scripts/cleanup-test-projects.sql` как есть (`v_mode := 'dry'`).
2. Ответ — `ERROR P0001 «СУХОЙ ПРОГОН (ничего не удалено, всё откатено)»` с отчётом: `0 |` проекты к удалению, `1 |` «REST…» у тестовых до / после, `4 |` удалено по таблицам, `5 |` оставлено (есть ссылки), итог «нетестовые компании: до = после по N таблицам».
3. Если ответ — «найдены записи «REST…» вне тестовых компаний — ничего не удалено» → **стоп**, список таблиц — Архитектору (решать, что это за записи).
4. Цифры — владельцу простыми словами («удалится N проектов прогонов, M строк справочника подрядчиков…; РБИ — без изменений»).

## 3. Уборка (по «да» владельца на цифры шага 2)

1. **Ночью и не во время `test:server`:** скрипт на время транзакции выключает сторожей неизменяемости — это держит блокировку таблиц ВОР / факта / КС-2 / журнала всех компаний до конца транзакции (ожидаемо секунды – минута).
2. Тот же файл, строка режима `v_mode text := 'apply';` → вставить файлом → результат — таблица отчёта (тот же состав, что у сухого прогона).
3. Повторный запуск `apply` — в отчёте нет строк `4 |` (удалено 0).
4. Сверка — запрос только на чтение (ниже): «REST…» в тестовых компаниях — только «REST-автопроверки» и записи, на которые ещё ссылаются (строки `5 |`).

```sql
-- P2-0075: «REST…» по компаниям (только чтение)
select c.name, c.is_test, x.t, count(*) from core.companies c join lateral (
  select 'проекты' t from core.projects p where p.company_id = c.id and p.name like 'REST%'
  union all select 'виды работ' from core.work_types w where w.company_id = c.id and w.name like 'REST%'
  union all select 'бригады' from planfact.brigades b where b.company_id = c.id and b.name like 'REST%'
  union all select 'контрагенты' from core.counterparties k where k.company_id = c.id and k.name like 'REST%'
  union all select 'работы' from planfact.works w where w.company_id = c.id and w.name like 'REST%'
  union all select 'подрядчики Качества' from quality.contractor_directory d where d.core_company_id = c.id and d.display_name like 'REST%') x on true
group by 1, 2, 3 order by 1, 3;
```

**Отката у уборки нет** (физическое удаление тестовых данных — решение владельца «Все три пункта»); защита — сухой прогон, отказ при «REST…» вне `is_test`, сверка «нетестовые до = после» и откат всего при любой ошибке внутри скрипта.

## 4. Два прогона `test:server` подряд (по «да» владельца)

1. `npm run test:server` — ожидаемо `ИТОГ: PASS`; в конце строки `P2-0075: проект прогона в архиве`, `P2-0075: видимых «REST…» в Альфе и Бете не прибавилось`, `P2-0075: постоянные записи теста — по одной`.
2. Сразу второй прогон — то же. Первый прогон после уборки создаст один раз постоянные записи (вид работ «REST-ВОР Устройство пола», словарь) — проверка их не считает ростом.
3. Если упало — строка FAIL с перечнем «что прибавилось» → Исполнителю (доработка), сайт не откатывать: тест на сайт не влияет.
