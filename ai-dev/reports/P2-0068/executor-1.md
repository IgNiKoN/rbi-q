## Что сделано

- **`RegistryTable` рисует порциями по 100** (`REGISTRY_CHUNK`). Следующая порция дорисовывается сама: кнопка «Показать ещё (N)» подъезжает к экрану (`IntersectionObserver`, запас 600 px). Кнопка остаётся запасным путём, подпись и класс — как во «Вводе факта» (`pf-btn pf-btn--ghost`).
- **Группы.** Порция считается по строкам открытых групп. Дальние группы появляются по мере дорисовки, порядок групп не меняется. «Всего: N» и счётчики статусов — по всем строкам группы.
- **По всем строкам, как раньше:** «Показано», фильтр-кнопки со счётчиками, «Выбрать всё», «Выбрано: N», строки для Excel (`registryRows`).
- **Сброс на первую порцию** — при смене фильтра, «Только просроченные», сортировки и группировки, в том числе при возврате к прежнему виду. Обновление данных (например, после «Принять») порцию не сбрасывает — список не прыгает.
- **Открытая строка** (`openKey`) дальше порции дорисовывается: строка № 3000 по адресу видна.
- Вид реестров на ПК и телефоне не менялся, колонки и фильтры не убирались.
- **«Факт → Ввод»:** `loadHints` запускается после показа мест (`afterPaint` — после отрисовки). Строки загрузок ВОР запрашиваются параллельно (`Promise.all`). Для проекта подсказки хранятся и повторно не запрашиваются. Поздний ответ другого проекта не подставляется. Не загрузились — список без подсказок и без ошибки.
- **Замер** — `tests/perf/screens-weak.mjs` (перенесён из `baseline/`). Добавлены параметры:
  - `--width` — ПК 1440;
  - `--shots end` — снимок после прокрутки;
  - `--check positions` — сценарий карточки с выгрузкой Excel.
  Снимок экрана теперь делается сразу после открытия, до прокрутки.
