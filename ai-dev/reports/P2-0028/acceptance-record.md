## Повторное ревью 032d (независимое, read-only)

Блокирующих нет; откат побайтно = прежние тела; права и динамический SQL — в порядке; M1, M3, M4 — верно. Остатки (приняты владельцем с условием):
- **HIGH H1′:** компания A может заранее создать учётку на чужую почту (подтверждена сразу, временный пароль знает A); если B потом добавит эту почту, A войдёт в B. Нужно: не присоединять к B учётку другой компании, ещё не входившую / с флагом «сменить пароль» (или подтверждение B).
- **MEDIUM:** привязка профилей на том же объекте может удалить профиль другой учётки, совпавший по ключу/имени (`x.auth_user_id is null or = m.user_id`); при однофамильце, когда профиль не переименован, рейтинг всё равно переименовывается.
- **LOW:** `assigned_to_name` в таблице без исполнителя — по автору (сегодня таких таблиц нет); ФИО глобально, а в компании, где человек отключён, записи не переписываются; два рейтинга одного человека под старыми именами на одном объекте → конфликт уникальности.

**Условие (владелец):** остатки — в P2-0035 «люди по id» (ADR-070); **до подключения второй независимой компании — закрыть обязательно** (ТД №189).
