## 1. Как должен работать (сквозной путь по ТЗ и каталогу)

| Шаг | Кто | Что происходит | Что получается | Сейчас |
|---|---|---|---|---|
| 1. Тендер | ПТО | ВОР заказчика любой формы → наши позиции «место × вид работ × объём»; цены компании → смета → КП в форме заказчика | КП, редакции | ✅ |
| 2. Договор | ПТО, договорной | договор с заказчиком; договоры с подрядчиками, их фронт и бригады (ядро) | план = утверждённая ВОР | 🟡 договоров нет |
| 3. График | ПТО, РП | из набора видов работ проекта × места строится ГПР по параметрам (дни на этаж, шаг, последовательность), ГДРС; директивный и рабочий; изменение — новая версия с причиной | у каждой позиции даты и плановый % на сегодня | ❌ |
| 4. Факт | прораб, мастер | утром — «что сегодня / просрочено» по своим секциям; факт за 3–4 касания: место → работа → объём → бригада (+ фото по шаблону); без связи; перебор — на подтверждение РП | факт прораба, % и отставание сразу | 🟡 без графика, фото, офлайна |
| 5. Приёмка | заказчик / СК | чек-лист заказчика по позиции подписан (или приёмка этапа в Стройконтроле) | факт «принято» с юридической датой | ❌ |
| 6. Деньги с заказчиком | ПТО, экономист | принятый факт → через связки в строки заказчика → КС-2 в его форме | КС-2, сверка «сделано ↔ выставлено» | ✅ |
| 7. Деньги бригадам | экономист, РП | 10 и 25 числа: принятое × расценка бригады → реестр → согласование → 1С → «выплачено» | ФОТ факт, реестры | ❌ |
| 8. Контроль | РП, руководство | отставания до просрочки, эскалации 3/7/14 дней; портфель, темп, прогноз, Гант, ФОТ, маржа | решения до срыва | 🟡 портфель и темп есть |

Три факта по одной позиции: **прораб → принято → в КС-2**. Каждый следующий шаг берёт данные предыдущего, а не вводит заново.

## 2. Оценка интерфейса (что видно сейчас)

**Хорошо:** единый стиль с Качеством; карточки работ с прогрессом и остатком; «Требует моего участия» по объектам; таблица КС-2 со статусами и редакциями; прораб не видит денег.

**Плохо (по убыванию важности):**
1. **Навигация по функциям, а не по задачам.** 8 значков (Сводка, Входящие, ВОР, Факт, Смета, КС-2, Справочники, Настройки); подпись есть только у открытого. Прорабу из восьми нужны два, ПТО — четыре. На телефоне 8 значков в нижней панели (норма — до 5).
2. **Три уровня вкладок** (значки → «Ввод / Шахматка / Ждёт РП / Журнал» → «Этажи × секции / Этажи × виды работ»). На телефоне четвёртая подвкладка «Журнал» не помещается — не видна.
3. **Выбор объекта на каждом экране** отдельным списком — должен быть один раз, в шапке Платформы (проект — общий контекст ядра).
4. **Пустые экраны не ведут к действию:** в Сводке «Нет данных» и прочерки без подсказки «загрузите ВОР / внесите факт»; «Смета» показывается тому, у кого нет права, с текстом «нет права» — пункт надо скрывать.
5. **Тяжёлая типографика:** заголовки и подвкладки ПРОПИСНЫМИ, крупная золотая «таблетка» активной вкладки отвлекает от данных.
6. **Шахматка слабая:** одна колонка «Без секции», статусы различаются оттенками тёмного — плохо видно на солнце; нет «выполнено / принято».
7. **Справочники не на месте:** бригады, цены и надбавки внутри План/Факта; по архитектуре бригады — ядро («Компания»), цены и надбавки — у смет.

**Вывод:** не косметика, а перестройка навигации под роли и под разбиение (п. 3); стиль (токены, карточки) сохраняем.

## 3. Разбиение на модули

Сейчас в одном модуле 4 разных продукта для разных людей и разных покупателей. По `MODULES.md` §1а модуль = лицензия, работает один, связи — через ядро.

| Модуль (лицензия) | Для кого | Что внутри | Работает один? | Связь, если есть партнёр |
|---|---|---|---|---|
| **Сметы и КС-2** (работа с заказчиком) | ПТО, экономист, тендерный отдел | ВОР заказчика и связки, словарь, цены и надбавки, смета, КП, КС-2, «сделано ↔ выставлено» | да: объёмы КС-2 вводит ПТО | Производство → объёмы КС-2 из принятого факта |
| **Производство (факт)** | прораб, мастер, РП | позиции, факт, подтверждения РП, журнал, шахматка выполнения, «что сегодня», чек-лист заказчика, фото, офлайн, сводка план/факт | да: позиции из ВОР или вручную | Сметы → позиции из ВОР; Сроки → плановый %; Стройконтроль → «принято» |
| **Сроки** (ГПР/ГДРС) | ПТО, РП, планировщик | генерация графика, директивный/рабочий, версии, вехи, Гант | да | Производство → факт на графике |
| **ФОТ и выплаты** | экономист, РП, бухгалтерия | расценки бригад, реестры 10/25, авансы, удержания, 1С, аналитика ФОТ, лимиты | нужен факт → **партнёр обязателен** (продаётся вместе с Производством) | Бюджет, Подрядчики |
| Портфель руководителя | руководство | — | — | уходит в «Управленческую аналитику» (5.20) |

**Условие, без которого делить нельзя:** позиция работ должна стать записью ядра (блок 5 архитектуры). Сейчас всё держится на `planfact.vor_positions` — Производство и Сроки без ВОР не живут.

**Варианты:**
- **А (рекомендую).** Утвердить разбиение в каталоге сейчас; делить код и лицензии по мере блоков: позиция работ в ядре → меню План/Факта по ролям (Производство / Сметы и КС-2) → отдельные лицензии. Новое (график, ФОТ) сразу строить отдельными модулями. Решение 7.2 меняется: график — модуль «Сроки» сразу.
- **Б.** Один модуль, но меню по ролям (прораб видит «Сегодня / Факт / Шахматка», ПТО — «ВОР / Сметы / КС-2»). Дёшево, но продать «только сметы» нельзя, модуль продолжит расти.
- **В.** Разделить всё сразу. Дорого и рискованно: позиций в ядре ещё нет, придётся переделывать дважды.
