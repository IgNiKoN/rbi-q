## 0. Срочно: старые таблицы РБИ открыты без входа (ТД №95 — подтверждено на сервере)

Старая схема `public` (приложение РБИ, выключено) отдаёт данные **без входа** по публичному ключу приложения (политики `…_select_anon USING (true)` и `GRANT SELECT … TO anon` — `sql/002_create_platform_v2_tables.sql:306-334`, `sql/003:68-85`, `sql/012:32-44`). Проверка 26.10.2026 (REST, публичный ключ, только чтение):

| Таблица (`public`) | Строк отдаётся без входа |
|---|---|
| `location_nodes` | 392 |
| `construction_floors_v2` / `construction_units_v2` | 133 / 64 |
| `construction_defects_v2` / `construction_acceptance_v2` | 33 / 21 |
| `contractors` / `contracts` | 14 / 2 |
| `rbi_company_settings` | 1 |
| `issues`, `sk_records_v2`, `location_node_aliases`, `contractor_aliases_v2` | 0 (пусто) |

Схема `quality` (Платформа 2.0) — закрыта: политики только `to authenticated` + `quality.can(...)` (M/018_quality_up.sql:5), `grant … to anon` нет. **Рекомендация:** отдельный маленький блок — закрыть чтение без входа у старых таблиц `public` (новое приложение их не читает), затем — удаление старых таблиц (решение владельца ADR-069 п. 3).

## 2. Дубли и разрывы

### 2.1 Места — **три дерева** (главный разрыв)
- `core.locations` (План/Факт, uuid).
- `quality.location_nodes` (+ `location_node_aliases`) — дерево Качества, `id text`, 392 узла; с ядром связан только уровень «объект» (039b), ниже — нет.
- Стройконтроль: v1 `construction_objects/buildings/floors/units` (`id text`, связь только через объект) и v2 `construction_floors_v2/units_v2` (ссылаются на `location_nodes`; 133 / 64).
- Следствие: «Корпус 1, 5 этаж» в факте и в проверке — разные записи; шахматка факта и замечания по этажам не сопоставляются. ТД №29, №111.

### 2.2 Подрядчики — один мастер, но 4 таблицы Качества и текст в записях
- Мастер — `core.counterparties`. Качество держит `contractors`, `contractor_directory` (по объекту), `contractor_aliases`, `sk_contractor_map` + тексты `contractor_name/canonical_key` в записях; мост `contractor_core_links` (один ключ ↔ один контрагент) и `core_counterparty_id` в записях (039a).
- Разрывы: представитель подрядчика не привязан к своей фирме (№109 — нет «кабинета подрядчика»); тёзки по названию с разным ИНН (№108); бригады План/Факта (`planfact.brigades`) не связаны с контрагентами; КС-2 не знает контрагентов на сервере (№103); ПТО не ведёт контрагентов (№101); нераспознанные подрядчики в задачах — ~1194, из них 1159 «Системная» (№216).

### 2.3 Виды работ и категории — у каждого модуля свои
- План/Факт: `core.work_types` (+ модульный словарь `planfact.vor_dictionary`).
- Качество: «вид работ» = шаблон чек-листа (`data/system_templates.js`, `quality.shared_checklists`, выбор официальных — `rbi_company_settings.official_templates`); в записях — текст `template_key/title`.
- Стройконтроль: категории и статусы замечаний — константы в коде (`src/services/construction-defects/types.ts`), в записях текст.
- СК (импорт): `sk_category_map`, `sk_mapping` — jsonb по объекту.
- Связей с `core.work_types` нет.

### 2.4 Единицы — общие есть, но текстом дублируются
- `core.units` — мастер; в План/Факте параллельно `unit_text` (словарь ВОР, цены), синонимов единиц нет (№68). В Качестве единиц нет (объёмы СК — jsonb).

### 2.5 Остаются модульными (сводить не нужно)
- Цены и надбавки (`planfact.price_*`, `overhead_*`) — коммерция План/Факта.
- Эталоны, TWI-карты, узлы, шаблоны отчётов Качества (`shared_*`, 46 / 214 / 2 / …) — содержимое модуля; общего у них — автор (ТД №238) и вид работ (п. 2.3).
- Статусы — CHECK и константы модулей; общий справочник не нужен.

## 3. Предлагаемый порядок (каждый — отдельный блок, решение владельца)

| № | Блок | Что даёт | Размер / риск |
|---|---|---|---|
| 1 | **Закрыть старые таблицы РБИ** (п. 0) | данные РБИ не читаются без входа | маленький; одна миграция, CRITICAL — права |
| 2 | **Подрядчики по номеру** | представитель видит свою фирму (кабинет подрядчика), тёзки по ИНН, бригада ↔ подрядчик, ПТО ведёт контрагентов | средний; права/RLS |
| 3 | **Одно дерево мест** | один «этаж» в факте, проверках, замечаниях; шахматка + замечания | крупный; перенос данных 392 + 197 узлов, два приложения |
| 4 | **Виды работ ↔ чек-листы** | отчёты «качество по видам работ» рядом с фактом | средний; сначала словарь соответствий, без переделки чек-листов |
| 5 | Единицы: синонимы | «компл.» = «комплект» | маленький; по спросу |

Перед второй независимой компанией важнее всего **1** и **2** (п. 2 — роли подрядчиков), **3** — для сквозной аналитики План/Факт × Качество.
