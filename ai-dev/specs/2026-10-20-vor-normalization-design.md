# Сквозной ВОР: нормализация → смета → КП → факт → КС-2

**Дата:** 20.10.2026 · **Статус:** DRAFT — на проверку владельцу продукта (Игорь) · **Тип:** архитектурное решение, меняет ТЗ и MVP
**Источник:** брейншторм 20.10.2026 (Cowork), образцы в iCloud `Project Cloude/` (`0_СЕБЕС_…xlsx`, `ГПР ФСК ЗУМ…xlsx`, `График.xlsx`).

## 1. Проблема (первая боль, которую решает приложение)

Каждый девелопер присылает ВОР в своей форме. ПТО и прорабу трудно работать с разными формами: перепечатка, путаница «что это за строка», ручной пересчёт в КС-2. Нужно привести все ВОР к **единому виду**, **сохранить исходник** и уметь **развернуть результат обратно в форму заказчика** — на тендере (КП) и при процентовке (КС-2).

## 2. Цели и критерии успеха

- Один нормализованный ВОР живёт от тендера до последней КС-2; повторно ничего не разбирается.
- **Минимум ручной работы ПТО:** ПТО проверяет только исключения. Второй ВОР знакомого девелопера — почти полностью автоматически.
- Прораб видит только понятные позиции «локация + вид работ + объём».
- Суммы всегда сходятся: Σ наших позиций = Σ строк заказчика (по каждой строке).
- КП и КС-2 выдаются в Excel с номерами/наименованиями/ЕИ/расценками заказчика.
- Видна маржа: цена заказчика − наша себестоимость по каждой строке.

## 3. Сквозной процесс

1. **Тендер.** Загрузка ВОР заказчика → автоматический разбор и нормализация (светофор) → смета из справочника цен → правки по тендеру → **КП в Excel-форме заказчика** (его файл с нашими ценами). Редакции КП хранятся, видны отличия.
2. **Договор.** Выигранный тендер становится объектом; нормализованный ВОР и связки сохраняются. Изменения по договору — новая редакция ВОР (показ отличий, перенос связок).
3. **Стройка.** Прораб закрывает наши позиции по секциям/этажам/квартирам.
4. **Процентовка.** Факт → через связки в строки заказчика → ПТО проверяет исключения → **КС-2 (унифицированная форма) в Excel** + сверка «прораб ↔ КС-2».

## 4. Модель данных (простыми словами)

| Слой | Что хранит | Правила |
|---|---|---|
| **Исходник** | файл заказчика и каждая его строка: номер, тип (группа/работа/материал), наименование, ЕИ, объём, цены, комментарий, место в иерархии и контекст (секция/этаж/список квартир) | не изменяется; новые редакции — новые версии |
| **Наша позиция** | локация **любого уровня** (дом/секция/этаж/квартира) + вид работ из справочника + ЕИ + объём | с ней работает прораб; уровень выбирает ПТО (по умолчанию — уровень заказчика) |
| **Связка** | строка заказчика ↔ наша позиция + доля | одна таблица для 1:1, 1:N, N:1 и «строка → группа квартир» |
| **Профиль девелопера** | как читать его форму: шапка, колонки, признаки заголовков секций/этажей/квартир, где материалы | создаётся при первом файле, дальше узнаётся автоматически |
| **Словарь сопоставлений** | «наименование у девелопера → наш вид работ» | пополняется подтверждениями ПТО, используется у всех девелоперов |
| **Справочник видов работ** | код, наименование, ЕИ, типовые материалы и нормы | живой: ПТО добавляет новые виды при разборе |
| **Справочник цен компании** | расценка работы, цены материалов, дата цены | по умолчанию подставляется в смету; в тендере можно переопределить с подсказкой прошлых цен |
| **Шаблон накладных** | доставка %, расходники %, инструмент %, ФОТ-надбавки, ИТР, хоз-быт, прибыль %, офис, НДС | копируется в тендер и правится под него |
| **Документы** | редакции КП, редакции КС-2 | неизменяемы; повторное формирование = новая редакция (LP-09) |

Материалы — дочерние строки работы: в смете и КС-2 считаются как объём работы × норма расхода.

## 5. Загрузка ВОР: светофор

Система сама: распознаёт форму (или узнаёт по профилю), читает строки-заголовки как контекст («Секция 1» → «Этаж 3» / «кв. 3, 16, 24…»), сопоставляет наименования по словарю и похожести, раскидывает «группу квартир» по квартирам (по листу площадей, иначе поровну), проверяет сходимость сумм.

- 🟢 уверена → принимается без ПТО;
- 🟡 предлагает → ПТО подтверждает в один клик, пачкой;
- 🔴 не знает → ПТО выбирает/создаёт вид работ, решение запоминается.

Новая редакция ВОР: показываются только отличия; совпавшие строки, связки и факт переносятся автоматически.

## 6. Смета (тендер)

Повторяет методику `0_СЕБЕС…`: строка работы = объём × расценка; материалы = объём × норма × цена; итоги = материалы + % → ФОТ СМР + надбавки → ИТР → хоз-быт → прибыль → офис → НДС → итого и ₽/м². Цены по умолчанию из справочника компании, ручная правка в тендере с подсказкой «было в прошлых тендерах». Результат — КП в форме заказчика; редакции КП с отличиями.

## 7. Процентовка и КС-2

ПТО выбирает период и договор → система собирает подтверждённый факт, переводит по связкам в строки заказчика, считает материалы → экран «по договору | ранее предъявлено | предлагается | итог ПТО», сверху 🟡 частично закрытые 1:N и расхождения (**решает ПТО вручную**, система только предлагает) → КС-2 в Excel → отчёт «прораб ↔ КС-2» с причинами. Хранятся и предложенное системой, и итог ПТО.

## 8. Решения владельца (20.10.2026)

- Справочник видов работ: частично есть, остальное собираем из ВОР по ходу.
- Уровень позиций: гибко, решает ПТО при загрузке.
- Новая редакция ВОР: показ отличий + автоперенос.
- Частичное закрытие строки заказчика: решает ПТО вручную.
- КС-2: унифицированная форма, Excel.
- ИИ-подсказки сопоставления: **не в MVP**, отдельная следующая задача.
- **Смета входит в MVP**; справочник цен компании + ручная правка в тендере.
- КП — заполнение Excel-формы заказчика; несколько редакций КП.

## 9. Вне объёма этого решения

ИИ-подсказки; калькулятор графика (ГПР/ГДРС); реестры выплат 10/25 и ФОТ бригад; электронная подпись и обмен с заказчиком; импорт из сметных программ (ГРАНД и т. п.).

## 10. Изменения ТЗ (на согласование)

- **PTO-01 / прил. 16:** вместо жёсткого шаблона — импорт ВОР любой формы с профилем девелопера, контекстным разбором, словарём и светофором; исходник хранится.
- **Новое PTO-11:** справочник цен компании и тендерная смета; КП в форме заказчика; редакции КП.
- **LP-04:** КС-2 формируется из факта через связки в строки заказчика, с ручной правкой ПТО и сверкой.
- **§1.4 «Границы»:** исключение «расчёт смет — только импорт результатов» снимается для тендерной сметы.
- **НФТ:** «минимум ручной работы ПТО» — измеримо: доля 🟢 строк на повторном ВОР девелопера ≥ 90 % (цель, уточнить на пилоте).

## 12. Проверка (тест на реальных данных)

- Разбор трёх образцов без ручной перепечатки; суммы сходятся по каждой строке.
- Повторная загрузка того же/обновлённого ВОР: ≥ 90 % 🟢, отличия показаны верно.
- Смета по `0_СЕБЕС…` совпадает с Excel-расчётом (итог и ₽/м²) с точностью до копеек.
- КП: исходная форма заказчика заполнена нашими ценами, структура файла не повреждена.
- КС-2: объёмы по строкам заказчика = ручной расчёт ПТО на тестовом наборе фактов.

## 13. Риски и открытые вопросы

- Формы с объединёнными ячейками/формулами могут портиться при заполнении КП → проверить на образцах в первой задаче.
- Нет листа площадей → раскладка поровну неточна → ПТО видит предупреждение.
- Цены материалов устаревают → дата цены и подсветка старых цен.
- Размер MVP вырос из-за сметы → сроки пересчитать после P2-0001.
- Где граница «смета» и «бюджет объекта» (план ФОТ, LP-05) — уточнить при декомпозиции P2-0006c.
