# platform-2-core

Оболочка Platform 2.0 с модулем «План/Факт СМР».
Источник: локальный снимок `rbi-q-main` (коммит c6f6b02 + незакоммиченные правки на 20.10.2026). Старое приложение (production Quality) этим репозиторием не изменяется.

**Как устроено:** оболочка запускается у вас на компьютере (`npm run dev`); «План/Факт» и «Компания» после входа почтой и паролем работают с общим сервером Platform 2.0 (только схема `planfact`, см. `docs/SERVERS.md`); старое облако Quality выключено. **Показ по ролям — `docs/DEMO.md`** («Демо-компания», объект «ЖК «Спутник» (демо)»).

## Как запустить (у себя на компьютере)

Нужен Node.js 24+ (проверить: `node -v`).

1. Скачать проект: `git clone https://github.com/IgNiKoN/platform-2-core.git` и перейти в папку `cd platform-2-core`.
2. Установить зависимости (нужен интернет, один раз): `npm ci`.
3. Запустить: `npm run dev`.
4. Открыть в браузере http://localhost:8781 → нажать **«Работать локально»**.
5. В левом меню выбрать **«План/Факт»** → форма входа (почта и пароль). Без входа — подсказка «Войдите»; доступен только разбор файла ВОР.
6. После входа «План/Факт» открывается на **«Сводке»**; разделы: Сводка · ВОР · Факт · Смета · КС-2 · Справочники (видны по правам роли).

**Вход в «План/Факт» и «Компанию»:** меню «План/Факт» (или адрес `#/company`) → форма «Почта / Пароль», сессия общая (демо-учётки `demo-…@demo.invalid` — `docs/DEMO.md`; тестовые `alfa-pto@test.invalid`, `alfa-foreman@test.invalid`, `alfa-admin@test.invalid`, `beta-pto@test.invalid`; пароли — только в `.env.local`, в git их нет). «Работать локально (демо)» — без входа, только разбор файла ВОР. Сервер и порядок миграций — `docs/SERVERS.md`. Если после обновления виден старый экран — открыть в окне инкогнито или очистить данные сайта (service worker).

Остановить сервер — `Ctrl+C` в окне терминала. Другой порт: `PORT=8790 npm run dev`.

## Команды для разработчика

| Команда | Что делает |
|---|---|
| `npm run test:server` | проверка входа и прав через настоящий сервер (нужен `.env.local`; без него SKIP) |
| `node scripts/demo-seed.mjs "<файл ВОР>"` | наполнить «Демо-компанию» на общем сервере (только по разрешению владельца; `docs/DEMO.md`) |
| `npm run dev` | локальный сервер без кэша (`scripts/dev-server.mjs`, только 127.0.0.1) |
| `npm test` | unit-тесты (оболочка + модуль planfact) |
| `npm run check:ts` | проверка типов TypeScript |
| `npm run build:planfact` | сборка модуля План/Факт → `js/dist/planfact/planfact.js` |
| `npm run build:company` | сборка раздела «Компания» → `js/dist/company/company.js` |
| `npm run build:modules` | сборка старых TS-модулей оболочки (locations, construction-*) |

После правок в `src/modules/planfact/**` выполнить `npm run build:planfact` — оболочка грузит собранный файл. Если браузер показывает старую версию — service worker: DevTools → Application → Service Workers → Unregister, затем обновить страницу.

## Модуль «План/Факт»

- Исходники: `src/modules/planfact/` (React + TypeScript). Старая демо-таблица «Работы» (`PlanfactTable`/`PlanfactWorks`, `demo-data.json`) с P2-0009 не показывается — код сохранён до отдельного решения (ТД).
- Описание модуля (manifest): `js/modules/planfact/planfact.manifest.js`. **Выключить модуль** — `enabled: false` там же (пункт меню пропадёт, модуль не загрузится).
- Контракт: `init(ctx)` / `mount(el)` / `unmount()`.
- В меню модуль попадает через общий блок `getPlatformMenuItems()` в `js/core/app-shell.js` (manifest с `menu.section: 'platform'`).

## План/Факт → Справочники (проекты, структура, единицы, P2-0005)

- Боковое меню: **План/Факт → Сводка / ВОР / Факт / Смета / КС-2 / Справочники** (на ПК ≥1280 — панель слева, на телефоне — нижняя панель). «Справочники» видны, если у вас есть доступ к компании.
- **Объекты:** список проектов компании, создать, изменить название и код, в архив. Кнопка **«Структура»** открывает дерево: корпус → секция → этаж → квартира (уровни можно пропускать), «+ Узел», переименовать, удалить (ветка — с подтверждением). **«Сгенерировать корпус»**: секции × этажи × квартиры на этаже, предпросмотр числа узлов, лимит 5 000.
- **Единицы:** общие (м², м³, м.п., шт., компл., т, кг, л, чел.-ч.) только для чтения + свои единицы компании (добавить / удалить).
- Без права `planfact.projects.manage` / `planfact.units.manage` — только просмотр. Чужая компания ничего не видит (проверяет сервер).
- Исходники: `src/platform/company/` (`ProjectsTab.ts`, `LocationsTree.ts`, `UnitsTab.ts`, `CompanyScope.ts`, `projects.service.ts`), страница `src/modules/planfact/PlanfactApp.ts`, меню — `js/modules/planfact/planfact.manifest.js` (`nav`).

## Раздел «Компания» (роли и сотрудники, P2-0004b; с P2-0005 — «Настройки → Компания»)

- Пункт меню **«Компания»** виден только тому, у кого есть право `security.roles.assign` на всю компанию (роль «Администратор компании» или её копия). Видимость решает сервер (`pf_my_admin_companies`); каждый вызов сервер проверяет заново.
- **Роли:** список ролей компании; шаблоны (9 ролей из ТЗ) помечены «шаблон» и только копируются. «Копировать» → новая роль; у своей роли — переименование, галочки действий по группам (Работы и план · Факт · Чек-листы · Деньги и выплаты · КС-2 · Настройки и журнал · Безопасность), «Сохранить действия», «Удалить роль» (если не назначена).
- **Сотрудники:** участники компании, их роли, проект или «Все проекты», срок; «Назначить роль» (сотрудник, роль, проект, срок до), «Отозвать». Добавлять новых людей с экрана нельзя (решение владельца) — пользователей заводит скрипт (`docs/SERVERS.md`).
- **Журнал:** кто, что и когда менял в ролях и назначениях.
- Права действуют со следующего запроса: изменили роль → в «План/Факт» достаточно обновить страницу, повторный вход не нужен.
- Защита на сервере: шаблоны не меняются; нельзя назначить роль себе; нельзя оставить компанию без администратора ролей; назначенную роль не удалить; неизвестное действие и чужая компания — отказ.
- Исходники: `src/platform/company/` (вход — общая форма `src/platform/auth/LoginForm.ts`), manifest `js/modules/company/company.manifest.js`.
