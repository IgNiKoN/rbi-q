# Сводный отчет 2.0 — наполнение титульного листа

Дата: 2026-07-21  
Статус: superseded by ranking-table trial (18.57.96)

## Update 2026-07-21 (trial A)

Титул = тонкий пульс + **сравнительная таблица** объектов.
Сортировка: УрК ↓ (лучше сверху). Колонки: объект, УрК+Δ, надёжность+Δ, ИКО+Δ, СК проср., пров.
Плитки и зона внимания не используются.

## Цель

Один A3 landscape: руководитель за 10–15 сек видит здоровье компании, СК и сравнение объектов. Детали — в one-pager объекта.

Визуальный каркас (спокойные полосы + нейтральные плитки) сохраняем; меняем наполнение.

## Структура

1. Пульс компании (5 метрик)
2. Короткая полоса ПК СК
3. Сетка объектов 5×3 (до 15)
4. Без «зоны внимания», без статусов Норма/Контроль/Внимание, без строки причин

## Пульс (5 ячеек)

| Ячейка | Значение | Подпись |
|--------|----------|---------|
| Уровень качества | УрК физика % | Δ к предыдущему периоду |
| Надёжность подрядчиков | средняя ИУрК % или «сбор» | Δ; при наличии базы — ИУрК&lt;70% N из M |
| ИКО · риск | ИКО | Δ (ниже = лучше) |
| ПК СК · просрочка | открытая просрочка, шт | % от выданных за период |
| Охват | число проверок | N объектов · M подрядчиков |

Не в пульсе: док %, B3, «фокус внимание/контроль».

## Полоса ПК СК

- Выдано · открыто · откр. просрочка · % просрочки
- Топ 2–3 подрядчика по открытой просрочке; при наличии — коротко объекты
- Период = фильтр отчёта, по дате выдачи

## Плитка объекта

Только цифры и динамика:

1. Название
2. Крупно: УрК + Δ · Надёжность + Δ (или «сбор»)
3. Вторично: ИКО + Δ · СК (проср. N или откр/выд) · N пров.

Без: док %, статусов, точек, строки причин, цветных блоков метрик.

## Сетка

- До 15 объектов, 5×3
- Порог: ≥10 проверок
- Сортировка: по ИКО ↓

## Вне скоупа

- Переработка one-pager объекта
- Изменение формул УрК / ИУрК / ИКО
