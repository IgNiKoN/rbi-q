# Серверы Platform 2.0

**Сейчас:** «План/Факт» подключён к общему self-hosted Supabase `https://api.rbi-q.ru` (ADR-061, ADR-061a, ADR-064). Адрес и публичный anon-ключ Platform 2.0 — в `js/services/config.service.js`, ключи `P2_SUPABASE_URL` / `P2_SUPABASE_ANON_KEY`.

**Качество и Стройконтроль (P2-0016, ADR-068).** Переключатель сборки «разработка / выпуск» P2-0013 убран: старое приложение РБИ (вход по PIN, боевые таблицы и бакеты `public`) живёт отдельно и из Платформы 2.0 не используется — облако старого Quality в `config.service.js` всегда пусто. Вход в Платформу 2.0 — только почта (+ демо). Вошедшему почтой с включённым у компании модулем «Качество» / «Стройконтроль» синхронизация идёт в раздел `quality` (55 таблиц той же структуры, что `public`, + `core_company_id`, `core_project_id`), запрос несёт заголовок `x-company-id`; файлы — в закрытые бакеты `quality-<бакет>` по пути `<компания>/…` (кэш приложения подставляет вход вошедшего). Локальная база на устройстве — `PLATFORM2_DB_<компания>` (без компании — `PLATFORM2_DB`). Раздел `quality` открыт для API настройкой роли `authenticator` (`pgrst.db_schemas` = `public, storage, graphql_public, quality`); `planfact`, `core` — закрыты.

### Откат Качества 2.0 (P2-0018)

Порядок: `026_down` → `025_down` → `024_down` → `023_down` → `022_down` → `021_down` → `020_down` → `018e_down` → `018d_down` → `018c_down` → `018b_down` → `018_down` (каждый откат сам проверяет, что предыдущий выполнен, и при нарушении порядка останавливается с понятной ошибкой до изменений — ТД №117).

**Откат файлов Качества.** `018d_quality_storage_down.sql` файлы SQL-ом не удаляет: если в бакетах `quality-*` есть файлы, откат останавливается («В бакетах quality-* есть файлы (N)…»).
