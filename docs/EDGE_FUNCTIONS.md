# Функции сервера (Edge Functions) — выкладка и откат

Выяснено в P2-0034 (25.10.2026) вместе с владельцем. Сервер `api.rbi-q.ru` — self-hosted Supabase на VPS Beget «rbi-q supabase».

## Где лежат

- Панель: `cp.beget.com` → Облако → «rbi-q supabase» → **Файловый менеджер** (или **Терминал**). Вход — учётка Beget владельца.
- Папка функций на сервере: `/opt/beget/supabase/volumes/functions/` (в службе функций — `/home/deno/functions/`).
  - `main/` — маршрутизатор Supabase: на каждый запрос `/functions/v1/<имя>` запускает папку `<имя>`. **Не менять.**
  - `deepseek-proxy/` — ИИ старого РБИ (копия для отката — `supabase/functions/_legacy/deepseek-proxy/`).
  - `pf-ai/` — ИИ-помощник Platform 2.0 (исходник — `supabase/functions/pf-ai/`).
  - `.env`, а также `/opt/beget/supabase/.env` и `docker-compose*.yml` — **секреты (ключи), не открывать, не копировать, не править**.
- Ключ DeepSeek и адрес сервера функция берёт из окружения службы (`DEEPSEEK_API_KEY`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`); в репозитории ключей нет.

## Новая функция (папка) — без перезапуска

Маршрутизатор подхватывает новую папку при следующем запросе.

1. Файловый менеджер → `/opt/beget/supabase/volumes/functions/` → «Новая папка» `<имя>`.
2. В неё «Загрузить Файлы» — все файлы из `supabase/functions/<имя>/` (для `pf-ai`: `index.ts`, `handler.ts`).
3. Проверка: `POST https://api.rbi-q.ru/functions/v1/<имя>` без токена → для `pf-ai` ответ **401** «Войдите в Платформу 2.0».

**Откат:** удалить папку `<имя>` (старые функции не затрагиваются).

## Изменение существующей функции

Замена файла подхватывается без перезапуска (проверено 25.10.2026 на `pf-ai` и `deepseek-proxy`). Если функция всё же отвечает по-старому — нужен перезапуск службы функций (на секунды; все функции, в т. ч. старая `deepseek-proxy`, на это время недоступны). Только по разрешению владельца.

1. **Сначала копия на сервере:** в `/opt/beget/supabase/backup-functions/` (вне папки функций: любая папка внутри `functions/` становится адресом функции) — файловый менеджер: слева `backup-functions`, справа файл → «Копировать», затем «Переименовать» в `<функция>.index.ts.bak-ГГГГММДД`; плюс копия в репозитории (`supabase/functions/_legacy/…`).
2. Заменить `index.ts` (файловый менеджер → «Правка» или загрузка файла).
3. Проверить ответ функции. Если отвечает по-старому — перезапуск: Терминал → `cd /opt/beget/supabase && docker compose restart functions`.
4. Сразу после — проверить старую `deepseek-proxy` (режим «корпоративный пароль» с неверным паролем → 403 «Неверный корпоративный пароль» — значит функция жива; без расхода токенов).

**Откат:** вернуть `index.ts` из `backup-functions/<функция>.index.ts.bak-…` (или из `_legacy/` в репозитории), при необходимости тот же перезапуск, та же проверка.

## Проверки без расхода токенов DeepSeek

- `pf-ai`: без токена → 401; с токеном учётки без права → 403; модуль «ИИ-помощник» выключен у компании → 403 «выключен для вашей компании» (до вызова DeepSeek). Версия — заголовок `x-pf-ai-version` (сейчас `3`).
- `deepseek-proxy`: `{"mode":"corporate","password":"<неверный>"}` → 403; `{"mode":"bogus"}` → 400.
