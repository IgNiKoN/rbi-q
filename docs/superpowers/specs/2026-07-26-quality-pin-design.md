# Quality pin на сквозном справочнике (подход 1)

**Дата:** 2026-07-26  
**Статус:** approved (пользователь «вроде ок», 2026-07-26) → план `_ai/current_plan.md` Q-pin-1  
**Контекст:** после CONFIRMED блока 7a (PDF квартир из Настроек, admin-only push локаций). Справочник объектов (`service.locations`) — сквозной.

## Цель

В модуле **quality** (осмотр) оставить привычный ручной ввод локации и добавить лёгкий способ отметить место на PDF-плане этажа из того же справочника, что использует construction-v2.

## Не цель (вне объёма)

- Pin на плане **квартиры** (apartment) в quality
- Чек-листы приёмки
- Полный отказ от legacy ObjectDirectory / полный мост ObjectDirectory↔locations
- Вынос общего pin-компонента quality+СК в один пакет «заодно»
- Meetings / §38 / Gotenberg

## Согласованное поведение

### Форма осмотра

1. Поля выбора **объект / корпус / этаж** — из сквозного `service.locations`, **с сохранением ручного ввода** (можно не выбирать из списка).
2. Поле уточнения / **осей** — ручной текст.
3. Маленькая кнопка **«на плане»** рядом с блоком локации.
4. Валидация пункта:
   - есть **pin** → оси/ручное уточнение **опциональны**;
   - нет pin → поведение как сейчас: нужен осмысленный ручной ввод локации (существующие правила quality не ослаблять без pin).

### Два входа на план

| Вход | Поведение |
|------|-----------|
| A | В форме уже выбраны объект → корпус → этаж (и у этажа есть PDF) → кнопка открывает fullscreen-план сразу |
| B | Кнопка нажата без полного пути → мини-выбор object → building → floor → затем тот же fullscreen-план |

### После выбора пути / точки на плане

1. Списки формы **подставляются** (object / building / floor).
2. В текстовую локацию пишется путь вида `Объект / Корпус / Этаж` (можно потом править руками).
3. Поле осей **не затирается**; пользователь может дописать оси опционально.
4. На форме виден индикатор «точка на плане» + действия **переставить** / **снять**.

### Редактирование pin

- **Переставить** — снова открыть план, новая точка заменяет старую.
- **Снять** — координаты очищаются; снова действует правило «нужен ручной ввод» (как без pin).

### Что сохраняем (истина данных)

Вариант **2** из обсуждения: **pin + ручной текст**.

- `locationId` = id узла **floor** из `location_nodes`
- координаты pin (нормализованные x/y, как в construction-v2)
- текстовая локация / оси — что пользователь ввёл или что подставилось из пути; оси могут быть пустыми при наличии pin

## UX (кратко)

```
[ Объект ▾ / руки ] [ Корпус ▾ / руки ] [ Этаж ▾ / руки ]
[ Локация / путь (текст) ]     [ оси (опц. если pin) ]  [📍 на плане]
[ ● Точка на плане | переставить | снять ]   // только если pin есть
```

Fullscreen: PDF этажа → тап = точка → подтвердить / отмена.  
Нет PDF у этажа → понятное сообщение, план не открывать пустым.

## Технический контур (ориентир для плана Архитектора)

- **Источник планов:** `service.locations` / `getPlanForFloor` (те же PDF, что Настройки).
- **Viewer:** переиспользовать паттерн pin из construction-v2 (`PlanViewer` / аналог), не тащить legacy UniversalPdfViewer в quality без нужды.
- **Хранение:** поля pin на сущности пункта/осмотра quality (точная схема — в implementation plan; YAGNI: не плодить отдельный plan-store).
- **Sync:** отдельным критичным шагом только если меняются push/pull схемы осмотров; иначе UI+local first в первом блоке, cloud — по факту наличия колонок/полей.

## Критерии готовности (DoD продукта)

1. Ручной ввод локации/осей работает как раньше без кнопки.
2. Списки object/building/floor читают сквозной справочник; ручной ввод не блокируется.
3. «На плане» открывает PDF выбранного этажа или ведёт через мини-выбор пути.
4. Точка делает оси опциональными; путь попадает в текст локации; оси можно дописать.
5. Переставить / снять работают.
6. Смоук: 0 console errors; тестовые данные `__SMOKE_TEST__` при cloud-проверке — cleanup.
