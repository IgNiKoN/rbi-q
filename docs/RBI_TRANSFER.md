# Перенос данных РБИ в Платформу 2.0 (P2-0027, отчёты — P2-0036)

Старое приложение РБИ (вход по PIN, раздел `public`, публичные бакеты) → компания «RBI» Платформы 2.0 (раздел `quality`, закрытые бакеты `quality-*`, вход по почте). Старое приложение и его данные **только читаются**: перенос — копия.

## Что переносится

- **Записи:** все таблицы, которые есть и в `public`, и в `quality` (55 = `TABLES` из `scripts/gen-quality-schema.mjs`), строки старого проекта `rbi-test` (и строки без кода проекта). Проект `rbi-work` пустой, не сопоставлен — не переносится.
- **Готовые отчёты (P2-0036, решение владельца 25.10.2026):** `shared_reports` (384, все строки, включая удалённые — не показываются), `shared_report_snapshots` (376, ≈ 1,2 ГБ HTML; снимок — вместе со своим отчётом) и файлы бакета `reports` (382, 1,8 ГБ). Отчёты переносятся раньше снимков (внешний ключ). Ссылки в новой версии — на `quality-reports/<компания>/…`; ссылки, отправленные заказчикам раньше, ведут в старое хранилище (владелец: «старые ссылки можно не открывать»). Страницу отчёта (снимок) в приложении показать нечем — ни в старом, ни в новом нет экрана; в старом она открывалась только по публичной ссылке/QR.
- **Файлы:** все файлы бакетов `construction-defects`, `construction-plans`, `custom-assets`, `inspection-photos`, `library-*`, `reports` (с 036) → `quality-<бакет>/<id компании>/<старый путь>`.
- **id записей сохраняются** (ключи `quality` — по компании). Код проекта `rbi-test` → id объекта ядра «Объекты RBI» (в `project_code` и внутри данных записи — `"project_code"`, `"projectCode"`). Ссылки `…/object/public/<бакет>/…` → `…/object/public/quality-<бакет>/<компания>/…`; `storage_path` — с компанией. PIN (`pin_hash`) не переносится.
- **Люди:** `quality.rbi_transfer_people` (старый профиль → почта → учётка). Сопоставленному человеку проставляется автор записей `core_created_by` и ссылки на учётку; старый профиль остаётся со старой учёткой (у человека свой профиль создаёт новое приложение при входе — 031b). Несопоставленные — автор пусто, имя в записи сохраняется.

## Объекты в базе (миграции 031, 031a, 031b, 031c, 036, 036a)

| Объект | Назначение |
|---|---|
| `quality.rbi_transfer_projects` | старый код проекта → объект ядра компании |
| `quality.rbi_transfer_people` | старый профиль → почта → учётка |
| `quality.rbi_transfer_files` | файлы к копированию / скопированные / ошибки |
| `quality.rbi_transfer_runs` | журнал запусков (что сколько строк) |
| `quality.rbi_transfer_run(компания, объект)` | перенос; объект — ключ объекта РБИ (проверки, пункты, фото, задачи; с 036 — отчёты объекта и их снимки), `null` — всё. Повтор — только новые строки. Полный — одним запросом SQL Editor не проходит (см. «Как запускать») |
| `quality.rbi_transfer_run_part(компания, таблицы, файлы)` | 036a: то же, что полный перенос, но для перечисленных таблиц; `'{}', true` — только список файлов всех бакетов |
| `quality.rbi_transfer_verify(компания, объект)` | сверка: строк старое (все / подходящие) = новое по каждой таблице; ссылки на старые бакеты; файлы; с 036 — по каждому бакету (в бакете / в списке / скопировано и есть копия, МБ старое = новое, ошибок 0) |
| `quality.rbi_transfer_public_fingerprint()` | отпечаток `public` и бакетов РБИ (строк и md5) — до = после |
| `quality.rbi_transfer_clear(компания)` | удалить все строки компании в `quality` (до дня переключения в «RBI» работает только перенос) |

Все функции и таблицы закрыты для `anon`/`authenticated`; вызываются в SQL Editor (роль `postgres`). `service_role` видит только список файлов.

## Как запускать в SQL Editor

Буфер только в UTF-8: `LC_ALL=en_US.UTF-8 pbcopy < файл.sql`, сверить md5. Панель через ~1 минуту показывает ошибку разбора ответа — запрос продолжает работать, результат смотреть в `quality.rbi_transfer_runs`. **Запрос дольше ~2 минут обрывается и откатывается целиком** (P2-0036, 25.10.2026: полный перенос с отчётами одним запросом — откат), поэтому перенос — пачками (`rbi_transfer_run_part`), снимки — порциями (`16_snapshots_batch.sql`). Не запускать повторно, пока идёт предыдущий (повтор безопасен, но удлиняет).

## День переключения (P2-0028) — порядок

Старое приложение продолжает работать до переключения и меняет записи (например, задачи — каждые несколько минут). Повторный запуск **добавляет только новые строки**, изменённые не обновляет, поэтому:

1. `05_fingerprint.sql` — отпечаток «до»; `08_size.sql`.
2. Сотрудники уже есть (P2-0028, 25.10.2026: 17 учёток, `09_staff.mjs`); новые — тем же скриптом (повтор безопасен).
3. `06_clear.sql` — строки компании (список файлов не трогается).
4. Перенос пачками (P2-0036, каждая ≤ ~1,5 мин; ждать запись пачки в `quality.rbi_transfer_runs`, затем следующую):
   `select * from quality.rbi_transfer_run_part((select id from core.companies where name = 'RBI'), array(select x from quality.rbi_transfer_tables() x where <условие>), false);` — условия по очереди: `x < 'rbi_inspection_items' and x <> 'shared_report_snapshots'`; `x = 'rbi_inspection_items'`; `x > 'rbi_inspection_items' and x < 'sk_records' and x <> 'shared_report_snapshots'`; `x >= 'sk_records'`.
4а. Снимки отчётов — `16_snapshots_batch.sql`, `v_part` = 0, 1, … до «порций всего N» (25.10.2026: 9 порций по ~1 мин).
4б. Список файлов: `select * from quality.rbi_transfer_run_part((select id from core.companies where name = 'RBI'), '{}', true);`
5. `node scripts/rbi-transfer/files.mjs copy <id RBI>` — докопирует только новые файлы.
5а. `10_attach_profiles.sql` — профили (рейтинг, награды) к учёткам; без этого у людей «пропадают» рейтинг и награды.
5б. `11_roles.sql` — показ, затем применение (`true`): роли и объекты; ждать «уже так» у всех 17. Затем `12_visibility_check.sql` по порциям — «расхождений: 0».
6. `04_verify.sql` (null) — все `ok` (в т.ч. файлы по каждому бакету, ссылки на старые бакеты — 0); `07_verify_detail.sql` — все `ok`; `05_fingerprint.sql` «после» — строк столько же (md5 может отличаться только у таблиц, которые меняло работающее старое приложение — проверить по времени изменений).
7. Устройства, которые уже входили в «RBI» до переноса, загружают только изменения — перенесённые записи со старыми датами к ним не придут: на таком устройстве нужна полная загрузка (выход из компании/повторный вход или сброс данных устройства). Новые устройства загружают всё при первом входе.

8. Пароли: сотрудникам выдаёт владелец — «Компания → Сотрудники → Сбросить пароль» (временный, показывается один раз; при первом входе человек придумывает свой).

**Сотрудники (P2-0028, 25.10.2026):** 17 учёток по рабочим почтам (справочник организации Яндекс 360), роли временные до P2-0033 (с 25.10.2026 — роли «как в РБИ» и объекты, `11_roles.sql`); владелец — рабочая почта («Администратор компании»), gmail — только администратор платформы. Перенос заново 25.10.2026: 1610 проверок, у всех автор — учётка; сверка 55/55 и 25/25; `public` до = после.

**Откат:** `files.mjs clear <id RBI>`, затем `06_clear.sql`; старое приложение не затронуто. Миграции — `031c…031_down.sql` в обратном порядке (`031c` → `031b` → `031a` → `031`).

## Объекты и подрядчики по id (P2-0035, миграции 039–039c)

- **Перенос заполняет id сам:** у записей Качества `core_object_id` (объект ядра ЖК) и `core_counterparty_id` (контрагент) пишут триггеры при вставке; объект Качества, который сервер успел создать по узлу дерева (дерево переносится раньше справочника), уступает настоящему с тем же ключом. Отдельного шага нет.
- **Контейнер:** `02_setup_company.sql` создаёт объект «Объекты RBI» без синхронизации с Качеством и помечает его `quality_container` (скрыт из списков «Компании» и План/Факта; Качество работает в нём).
- **После переноса (только чтение):** `select * from quality.object_link_report(<id RBI>)` и `quality.counterparty_link_report(<id RBI>)` — строк, с id, «не разобрано»; 25–26.10.2026: объекты — узнано 99,94 % (23 «не разобрано»), 15/15 объектов Качества связаны с ядром; подрядчики задач — 1194 без фирмы (1159 — пометка «Системная», не фирма). «Не разобрано» по объектам — заявки в очереди названий Качества («Объекты и планы» → «Связать с: …»).
- **Сверка видимости** `12_visibility_check.sql`: новая объяснённая категория «свои „не разобрано“» — своя запись, объект которой сервер не узнал, видна автору (старое приложение её от автора прятало).
