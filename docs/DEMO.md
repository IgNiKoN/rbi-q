# Показ Платформы 2.0 «План/Факт» — сценарий для «Демо-компании» (P2-0009)

Сквозной путь: **ВОР заказчика → смета и КП → факт прораба (с исправлением) → КС-2 в Excel → сводка руководителю**, плюс проверка, что чужая компания ничего не видит. Данные — реальная ВОР «ЖК Спутник» (файл заказчика, только на общем сервере в демо-компании), факт и даты — придуманные.

## Перед показом

1. Открыть платформу: **https://ignikon.github.io/platform-2-core/** (GitHub Pages, обновляется после push в `main`; решение владельца 22.10.2026 — тестировщики работают здесь) или локально `npm run dev` → http://localhost:8781. Если видна старая версия — обновить страницу два раза.
2. Учётки «Демо-компании» (общий сервер) — **по одной на каждую из 9 ролей** (22.10.2026 добавлены `demo-qc`, `demo-economist`, `demo-customer`, `demo-contractor`). **Логины и пароли — в файле `.env.local` в папке проекта** (пары строк `P2_DEMO_…_EMAIL` / `P2_DEMO_…_PASSWORD`, тестовые «Альфа»/«Бета» — `P2_TEST_…`), список для раздачи тестировщикам — `.env.demo-logins.txt`; пароли в git и в чате не попадают.

3. Вход: при открытии — экран **«Вход»** → вкладка «Почта и пароль» → учётка роли. Смена роли — «Выйти» (полоса «почта · компания · роль» или «Настройки → Платформа»), затем вход другой учёткой. Меню — только положенные модули (P2-0013); «Посмотреть без входа (демо)» — разбор ВОР без сервера.
4. Телефон: тот же сценарий в узком окне (в Chrome — режим устройства, ширина 375). С настоящего телефона — по адресу GitHub Pages (п. 1).

## Что уже есть в демо (наполнено скриптом)

Объект **«ЖК «Спутник» (демо)»**, корпуса 1.1 и 1.2 (по 12 этажей); ВОР двух листов файла (73 + 75 работ, 148 позиций, каждая — на корпусе своего листа); смета по двум листам с надбавками (итог **213 850 266,76 ₽**, 33 602,22 ₽/м² при S = 6 364,17 м²); КП ред. 1 (прямые затраты по файлу 91 834 859,83 ₽) — она же договорная; факт прораба за ~4 недели (6 записей + одно исправление 35 → 30 дверей); выданный акт КС-2 № 1; плановые даты. Сводка: готовность 1,7 %, сделано 1 565 152,29 ₽, выставлено 1 408 494,69 ₽, разрыв 156 657,60 ₽, «Отставание».

## Сценарий

**1. Руководство (`demo-boss`) — «Сводка».** План/Факт открывается сразу на «Сводке» (первый пункт меню). Видно: % готовности по деньгам договорной КП, темп за 7 и 14 дней, нужный темп, прогноз окончания, светофор «Отставание», «Сделано, не выставлено в КС-2». «Открыть» → виды работ и позиции; вкладка «Сделано ↔ КС-2» — построчный разрыв; «Скачать Excel» — сводка файлом. **Запомните цифры** «сделано» и «разрыв».

**2. ПТО (`demo-pto`) — «ВОР».** Список загрузок: два листа файла заказчика, «подтверждён». «Открыть» → позиции, место каждой — «Корпус 1.1» / «Корпус 1.2» (корпус подставлен по названию листа «… корп. 1.1»). Показать, что «Σ позиций = объём строки заказчика».
*Можно показать загрузку вживую:* «Загрузить Excel» → тот же файл → лист → «Сохранить черновик» → поле «Корпус листа» уже заполнено, виды работ подтягиваются из словаря компании (🟢). После показа — «← Загрузки» → «Удалить черновик» (ВОР не подтверждать — иначе позиции задвоятся).

**3. ПТО — «Смета».** «Тендерная смета»: по листам работа и материалы (совпадают с файлом заказчика до копейки), блок «Расчёт: надбавки и итог», ₽/м². Внизу — «КП в форме заказчика», редакция 1. *Сформировать новую редакцию:* «Сформировать КП — выбрать файл заказчика» → тот же файл → «Сформировать и скачать» → файл заказчика с нашими ценами (формулы и оформление заказчика не тронуты).

**4. Прораб (`demo-foreman`) — «Факт» (лучше в узком окне — как на телефоне).** «Корпус 1.1» → список работ: под названием — № строки и раздел ВОР заказчика (например, «№ 17.2 · Стены (пом. Лифтовой холл…)»), поэтому одинаковые работы различимы. На карточке «Обеспыливание…» → «Внести факт» → объём (например, 300), дата, бригада → «Записать» — % и остаток пересчитаны. «История» у «Монтаж межкомнатных дверей» → видно исправление 35 → 30 с причиной и автором; «Исправить» последнюю запись (например, 30 → 32, причина) → старая запись помечена «заменено». Показать, что у прораба **нет сумм в рублях** и пунктов «Смета»/«КС-2»; по прямой ссылке `#/planfact/estimate` открывается «Сводка».

**5. ПТО — «КС-2».** Договорная КП уже выбрана, акт № 1 «выдан». «Новый акт» → номер 2, период по сегодня → «Создать» → в акт попал факт, ещё не вошедший в акт № 1 (обеспыливание и внесённое на шаге 4) → «Сохранить редакцию» → «Скачать Excel» (унифицированная форма КС-2) → «Выдать» → «Да, выдать».

**6. Руководство — «Сводка» снова.** «Сделано» выросло на внесённое прорабом, «выставлено» — на акт № 2, разрыв уменьшился.

**7. Чужая компания (`alfa-pto`).** В «Сводке» и «ВОР» объекта «ЖК «Спутник» (демо)» нет — только свой «Альфа: Объект 1».

## Сброс демо (вернуть к исходному состоянию)

Только владелец, в SQL Editor сервера (`docs/SERVERS.md`). Удаляет демо-компанию со всеми её данными и демо-учётки; «Альфа»/«Бета» и Quality не затрагиваются.

Выполнить целиком файл `scripts/demo-reset.sql` (одна транзакция: защитные триггеры журнала и неизменяемых ВОР / КП / КС-2 / факта отключаются только на время удаления и включаются обратно).

Создать заново: `node scripts/demo-users.mjs` → файл `.env.demo-users.sql` (пароли берутся из `.env.local`) выполнить в SQL Editor и удалить → `node scripts/demo-seed.mjs "<путь к 0_СЕБЕС…Спутник….xlsx>"` (3–5 минут; печатает итог сводки). Даты факта отсчитываются от дня запуска.

## Ограничения показа

- Адрес GitHub Pages общий с боевым Quality (`ignikon.github.io`): кэш и база браузера у Platform 2.0 свои (P2-0002), но сохранённые настройки браузера (localStorage) на одном адресе общие — проверять «План/Факт», а не старый Quality в этой копии (он не подключён к боевым данным). Ссылку может открыть любой; данные — только после входа.
- Учётки созданы SQL-вставкой (ТД №13): перед боевым запуском удалить.
- Строки ВОР без цены (29 из 637) в КП остаются пустыми — так в файле заказчика.
