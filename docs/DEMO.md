# Демо, обучение и доступ клиенту (P2-0053)

Три вещи для показа Платформы 2.0 внешним клиентам (застройщикам, подрядчикам):

1. **Кнопка «Демо»** — заполненный «ЖК Демо» глазами любой из 8 ролей, **только смотреть**. Есть у каждого, кто вошёл почтой.
2. **«Обучение»** — пошаговые туры поверх «ЖК Демо»: План/Факт, Качество, Стройконтроль.
3. **«Песочница» клиента** — своя тестовая компания на боевом приложении: клиент сам грузит ВОР и структуру мест, заводит сотрудников и проходит План/Факт по-настоящему (с синхронизацией и работой без сети).

Прежняя памятка «Демо-компании» («ЖК Спутник», P2-0009) — в истории git; саму старую компанию удаляем после приёмки P2-0053 отдельным шагом по «да» владельца.

## 1. Кнопка «Демо»

**Где:** экран приветствия → «Демо и обучение: заполненный объект глазами любой роли»; «Настройки → Мой профиль» (под выбором компании); прямой адрес `https://app.rbi-q.ru/#/demo`.

**Что внутри «ЖК Демо»** (компания «Девелопмент Демо», наша роль — заказчик): три корпуса на разных стадиях — **Корпус 1 — старт** (ВОР и смета, факта нет), **Корпус 2 — в разгаре** (факт за 4 недели, открытые замечания на PDF-планах этажей, КС-2 №3 — черновик), **Корпус 3 — сдача** (работы закрыты, замечания закрыты, приёмка квартиры); паркинг. 244 места, 3 подрядчика, 20 видов работ (их чек-листы — системные шаблоны Качества), ВОР 325 строк, смета и договорная КП, 241 запись факта с одним исправлением, КС-2 №1 и №2 выданы, 10 проверок Качества с фото, 30 замечаний Стройконтроля (24 — точками на PDF-планах), 3 приёмки.

**Роли на выбор** — что видит каждая:

| Роль | Что видит | Открывается |
|---|---|---|
| Руководитель | вся компания: сводка, деньги, качество | План/Факт → Сводка |
| Руководитель проекта | весь «ЖК Демо»: ВОР, смета, факт на проверке, КС-2 | План/Факт |
| Инженер ПТО | ВОР, смета и КП, места, PDF-планы | План/Факт |
| Прораб | только свой участок — Корпус 2, секция 1 | План/Факт |
| Инженер качества | проверки, замечания на планах, приёмки | Стройконтроль 2.0 |
| Экономист | цены, смета, КС-2 и деньги | План/Факт |
| Заказчик | ход стройки и качество — без сумм | План/Факт |
| Представитель подрядчика | только своя фирма — «Отделка Демо» | Стройконтроль 2.0 |

**Как устроено:** «Демо» делает вошедшего участником демо-компании с выбранной демо-ролью (миграция `057`, функции `pf_demo_roles / pf_demo_enter / pf_demo_leave`). Права и область — та же проверка, что у всех (P2-0070); **любую запись** в данные демо-компании сервер отклоняет: «Демо — только просмотр. Попробуйте это в своей компании» (сторож на каждой таблице с компанией или проектом; файлы в папку демо — правило Storage); у демо-ролей нет административных действий. Красная рамка и плашка «Демо · роль · Выйти» внизу экрана (на ПК — справа сверху); нажатие на роль — сменить роль; «Выйти» — назад в свою компанию (её база на телефоне и неотправленные записи на месте). Администратор платформы в запросах к демо-компании (пока она выбрана и он её посетитель) — обычный посетитель: видит глазами выбранной роли; на другом устройстве или в другой компании — администратор как раньше; «Выйти из демо» снимает и это. В демо «План/Факт → Сводка», «Входящие» и выбор объекта показывают только объекты демо-компании (свои объекты посетителя — в своей компании; миграции `057`, `058`), кнопки создания Стройконтроля 2.0 («+ Замечание», «Зона», «Управление иерархией») скрыты. Посетителей не видно в «Сотрудниках», «Кто что может» и в числе людей у администратора платформы; посетители не видят друг друга. Без интернета «Демо» не открывается — понятное сообщение.

**Показ за 10 минут:** «Демо» → «Руководитель проекта» (Сводка: К1 0 %, К2 ≈ 56 %, К3 100 %) → плашка → «Прораб» (только своя секция; внести факт нельзя) → «Инженер качества» (Стройконтроль 2.0 → «📄 эт. 5» в Корпусе 2 → точки замечаний) → «Представитель подрядчика» (только замечания «Отделка Демо») → «Выйти».

## 2. Обучение

На экране «Демо» под ролями — **«Обучение по шагам»**: три тура.

| Тур | Роль | Шагов | Путь |
|---|---|---|---|
| План/Факт | руководитель проекта | 11 | сводка → требует внимания → ВОР → позиции → смета и КП → факт прораба → шахматка и проверка → входящие → КС-2 → реестр актов → «повторить у себя» |
| Качество | инженер качества | 6 | проверка по чек-листу → уровень качества → подрядчики → замечание на плане → устранение → «повторить у себя» |
| Стройконтроль | инженер качества | 6 | планы этажей → точки замечаний → реестр → приёмка → передача → «повторить у себя» |

Тур сам входит в демо нужной ролью, подсвечивает элемент и объясняет; «Назад / Далее / Закончить / Закрыть». Шаг, чей элемент не виден (другая ширина экрана, роль не видит), пропускается. Прогресс — на устройстве («продолжить» с того же шага). Последний шаг — «Выйти из демо и повторить у себя». Тексты туров — `src/platform/tour/tours.json`.

## 3. Доступ клиенту — «Песочница»

**Условие:** до передачи учёток закрыть открытые снаружи порты сервера (раздел 5).

**Существующими кнопками (5 минут):**

1. «Настройки → Администрирование платформы» → новая компания «Песочница — Клиент N», отметка **«Тестовая»** → создать.
2. В строке компании — модули: **План/Факт, Качество, Стройконтроль** включить; ИИ — выключен.
3. «Администратор компании» → своя почта → назначить (вы — её администратор, чтобы завести клиента).
4. Выбрать «Песочница — Клиент N» (переключатель «Компания» в «Настройки → Мой профиль», отметка «Показать тестовые») → «Компания → Сотрудники» → «Добавить сотрудника»: почта клиента, ФИО, роль **«Администратор компании»** → приложение покажет **временный пароль один раз** — передать клиенту.
5. Клиент входит, меняет пароль и дальше сам заводит сотрудников («Сотрудники → Добавить», роли и участки).

**Скриптом (так создаётся «Песочница — Клиент 1», 9 учёток — по одной на роль):**

```bash
node scripts/demo/sandbox.mjs --name "Песочница — Клиент 2" --key k2 --out "$HOME/Library/Mobile Documents/com~apple~CloudDocs/Project Cloude/Доступы клиентов/Песочница — Клиент 2.md"
```

Тот же путь, что кнопками (функции экранов, права проверяет сервер): компания → модули → вы администратор → учётки `<роль>.k2@sandbox.rbi-q.ru` (писем приложение не шлёт) с временными паролями. У прораба, инженера качества и представителя подрядчика участие пустое — объекта у клиента ещё нет; клиент назначит после загрузки ВОР. Логины и пароли — **только в файле доступов** (iCloud «Доступы клиентов», вне git, права 600), в консоль не печатаются. Нужны в `.env.local`: `P2_SUPABASE_URL`, `P2_SUPABASE_ANON_KEY`, `P2_PLATFORM_ADMIN_EMAIL`, `P2_PLATFORM_ADMIN_PASSWORD`. Проверка пути на стенде — `npm run demo:check-sandbox` (компания, модули, 9 входов, места из образца Excel, ВОР из образца, факт прораба, КС-2).

**Первые шаги клиента в своей компании:** «Компания → Проекты» — объект → «Объекты и места → Загрузить из Excel» (образец списка квартир) → PDF-планы этажей → «План/Факт → ВОР → Загрузить» (образец ВОР) → «Сотрудники» — прорабу участок и «ответственный за факт», подрядчику — фирма → прораб вносит факт → ПТО: смета, КП, КС-2.

## 4. Попробуйте сами: образцы и «без сети»

- `docs/demo-files/Образец — список квартир.xlsx` — Корпус 1, 2 секции × 5 этажей × 4 квартиры, площади и комнаты (форма «Загрузить из Excel»).
- `docs/demo-files/Образец — ВОР своей формы.xlsx` — ВОР с заголовками «Корпус 1 / Секция 1 / Этаж 1» строками; разбор сам расставит места.
- Пересоздать образцы — `node scripts/demo/files.mjs` (после записи файлы читаются разборщиками приложения: 40 квартир, 60 работ с этажом).
- **Без сети:** телефон в авиарежим → прораб вносит факт, инженер — замечание → значок «Нет связи · не отправлено: N» → включить сеть → записи уходят сами (P2-0064, P2-0060). Только в своей компании — в демо записи не сохраняются.

## 5. Закрыть порты до выдачи учёток (действие владельца)

Снаружи открыты служебные порты сервера Supabase: **5432, 6543** (база), **8000, 8443** (служебный шлюз), **4000** (аналитика). Приложение через них не ходит — только `https://api.rbi-q.ru` (порт 443); проверка — `npm run demo:check-sandbox`, первая строка.

1. Панель Beget → VPS «rbi-q supabase» → «Настройки сети» (может называться «Сеть» / «Firewall»).
2. Входящие: оставить **22** (SSH), **80** и **443** (сайт и API); запретить **5432, 6543, 8000, 8443, 4000** → сохранить.
3. Проверить с Mac: `nc -zv -w 3 api.rbi-q.ru 5432` (и 6543, 8000, 8443, 4000) — «refused / timed out»; `https://app.rbi-q.ru` открывается, вход работает.

Полное решение по портам и ссылкам — P2-0062.

## 6. Обновить «ЖК Демо» (вручную, по «да» владельца — перед показом или раз в неделю)

1. SQL Editor сервера (`docs/SERVERS.md`): выполнить целиком `scripts/demo/reset.sql` — удаляет только «Девелопмент Демо» (is_test и is_demo) и учётки `zd-dd-…@demo.invalid`; защита внутри: строки всех остальных компаний по каждой таблице «до = после», иначе отмена. Посетители (настоящие учётки) остаются, их участие в демо исчезает.
2. `node scripts/demo/accounts.mjs` → выполнить `.env.zhk-demo-accounts.sql` в SQL Editor → файл удалить (пароль демо-учёток — `P2_ZHK_DEMO_PASSWORD` в `.env.local`).
3. `node scripts/demo/seed.mjs` (около минуты; `--today ГГГГ-ММ-ДД` — от какой даты считать, не позже сегодня). Те же числа при каждом запуске.

**Стенд (без сервера):** `npm run demo:stand` — засев на копии схемы (PGlite) за ~3 с; `npm run demo:check` — числа, сводка и КС-2, посетитель ролями, сброс «до = после»; `node scripts/demo/browser.mjs <папка>` — кнопка «Демо» в браузере (375 и 1440); `node scripts/demo/tours.mjs <папка>` — три тура. Нужен `P2_PGLITE` (`tests/server/pglite-db.mjs`).
